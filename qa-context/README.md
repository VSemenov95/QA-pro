# Папка контекста QA pro

Источник контекста для QA pro и для Claude: правила, шаблоны, память агента, паспорт и база знаний продукта.
Лежит в репозитории QA-pro, поэтому изменения видны в истории git и проходят через запрос на слияние.

## Что где
- `rules/generation.md` — правила для агента (из настроек команды QA pro).
- `rules/review.md` — правила ревью; пока нет — берутся из QA pro.
- `templates/api.md`, `ui.md`, `e2e.md` — шаблоны кейсов: префикс ID, правила оформления, образец JSON.
- `templates/export.md` — формат экспорта.
- `products/тмбс/` — продукт ТМБС: `passport.md` (знания о продукте), `context.md` (доп. контекст QA),
  `lessons.md` (память агента), `kb/` (разделы базы знаний, файл = раздел), `qa-pro-docs.json` (какие документы уже разобраны).

## Подключение в QA pro
1. Обновите клон: `git pull` в `C:\Users\vlad3\IdeaProjects\QA-pro`.
2. Разрешите мосту папку репозитория: в `C:\Users\vlad3\.qa-pro-bridge\context.json` в `roots` добавьте
   `C:\Users\vlad3\IdeaProjects\QA-pro`.
3. QA pro → шестерёнка → «Контекст» → «Изменить»: «Папка на компьютере»,
   путь `C:\Users\vlad3\IdeaProjects\QA-pro`, подпапка `qa-context`, папка продукта `тмбс` → «Подключить».

## Как меняется
QA pro пишет изменения прямо в файлы рабочей копии. «Зафиксировать и отправить» во вкладке «Контекст» делает коммит
в ветку `qa-pro/<дата-время>` и `push` — дальше запрос на слияние в `main`. Прямо в `main` QA pro не отправляет.
Править файлы можно и вручную в IDE: QA pro перечитает изменённые файлы при следующем открытии или по «Обновить».
