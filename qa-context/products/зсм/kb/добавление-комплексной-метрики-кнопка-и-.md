# Добавление комплексной метрики: кнопка и форма добавления

> Добавление комплексной метрики в коллекцию: кнопка на портале, форма на шторке с конструктором или ручным вводом PROMQL-выражения, проверки при добавлении и сохранение метрики.

### Описание
- Пользовательская история: «Я как Авторизованный пользователь хочу Задать PROMQL-выражение из метрик ИС с помощью конструктора или вручную для формирования комплексной метрики, для того, чтобы поставить на мониторинг комплексную метрику для сбора данных с экспортера по заданному правилу». Описание сформировано на основании PPMON-209. Реализация комплексных метрик. Все прототипы расположены по ссылке Figma. (13-[US] Добавление комплексной метрики)
- История версий: версия 2.0, 15.12.2023, автор Шашков Алексей, задача PPPM-2135 [RI2][BA] Проработка скоупа и пользовательских требований фичи комплексных метрик (Закрыто): первая версия на основании описания фичи. (13-[US] Добавление комплексной метрики)
- Конструктор для формирования арифметических выражений на основании метрик. (13-[US] Добавление комплексной метрики)

### Экраны и навигация
- Портал: возможность пользователя видеть кнопку добавления комплексных метрик (1.0). (13-[US] Добавление комплексной метрики)
- Портал: добавление комплексной метрики, форма на шторке (2.0). (13-[US] Добавление комплексной метрики)
- Закрытие по клику вне шторки: функциональное окно (2.2). (13-[US] Добавление комплексной метрики)

### Поля и элементы
- Форма добавления (2.0): (13-[US] Добавление комплексной метрики)
  - редактируемое название комплексной метрики;
  - нередактируемый подзаголовок «Комплексная»;
  - блок шапки основных параметров коллекции: единица измерения, тип данных, активность (как у прочих метрик, см. #[RI1] Возможность Пользователя просматривать/редактировать карточку конкретной метрики);
  - блок конструирования выражения: незаполненный блок конструктора с кнопками +, -, *, /, (), min, max, avg, const; кнопка «Сформировать Promql-выражение» (в тексте также «Сформировать PROMQL»); обязательный текстовый блок итогового запроса «Текст PROMQL-выражения», по умолчанию не заполнен;
  - обязательный параметр типа «дробь» «Укажите значение, которое будет формироваться в случае ошибки», по умолчанию 0.0. Подставляется как результат арифметического выражения, если в любую из переменных передан результат деления на ноль ИЛИ в ходе арифметических операций совершено деление на ноль;
  - необязательный параметр типа «Время» «Интервал подтверждения»: при регулярном формировании метрики в соответствии с частотой запроса ищутся значения для расчёта в интервале (0-Интервал подтверждения; вызов выражения для формирования метрики). Если не заполнен, то 5m;
  - блок управления метками (аналогичный описанному в Метки, #[RI1] Возможность Пользователя просматривать/редактировать карточку конкретной метрики);
  - блок управления порогами (аналогичный описанному в той же #[RI1]);
  - кнопки «Добавить» и «Отменить»/«X».
- Функциональное окно при клике вне формы (2.2): кнопка «Х»/«Назад к заполнению»; «Не сохранить»; «Сохранить». (13-[US] Добавление комплексной метрики)
- Блок итогового (результирующего) выражения. (13-[US] Добавление комплексной метрики)

### Бизнес-правила и ограничения
- Добавление метрики считается редактированием формы экземпляров коллекций; доступ по #PM.Ролевая модель. Добавление возможно только если коллекция доступна для редактирования по #PM.Статусная модель заявки на мониторинг/объекта мониторинга. (13-[US] Добавление комплексной метрики)
- Любое изменение экземпляра коллекции (в т.ч. добавление метрики, изменение порогов) переводит его в состояние «Отредактировано», и пользователь должен повторно отправить заявку на мониторинг. (13-[US] Добавление комплексной метрики)
- 1.0 Кнопка добавления: пользователь добавил коллекцию на основании шаблона «Комплексная метрика» с признаком автопостановки (#[RI1] Возможность Пользователя добавить коллекцию метрик для объекта мониторинга в карточке мониторинга); коллекция доступна для редактирования; открыт список метрик (пустой) и видна кнопка. Кнопка доступна, если коллекция доступна для редактирования и пока не включён режим редактирования списка метрик (только после добавления метрик). (13-[US] Добавление комплексной метрики)
- 2.0 Форма: выполнено 1.0, коллекция в редактируемом состоянии; пользователь нажал кнопку добавления и видит форму на шторке. (13-[US] Добавление комплексной метрики)
- 2.1 Проверки при нажатии «Добавить»: (13-[US] Добавление комплексной метрики)
  1. Корректно заполнены шапка, пороги, метки.
  2. Заполнено PROMQL-выражение (неважно, заблокировано или нет); иначе подсветка красным.
  3. Заполнено «Укажите значение, которое будет формироваться в случае ошибки»; иначе подсветка красным.
  4. Переменные: если не добавлены — не ошибка; если добавлены — заполнены корректно, иначе некорректные элементы красным.
  5. Конструктор (в документе помечено как п. 4): если не заполнен — не ошибка; если заполнен — сформировано выражение и выполнены условия сохранения из «Конструктор для формирования арифметических выражений на основании существующих метрик», п. «Проверки выражения при сохранении для выражения конструктора». Если не выполнено: красным незаполненные поля и сообщение об ошибке с перечнем замечаний согласно таблице из этого пункта.
- При успешных проверках: (1) новая метрика с типом коллекции «Комплексная» добавляется в список коллекций метрик; (2) статус коллекции становится «Отредактировано»; (3) в таблице metrics сохраняются параметры. (13-[US] Добавление комплексной метрики)
- Таблица metrics: metric_source_type, STRING, значение complex-physical; metric_key, STRING, по маске complex_physcial_metric; promql_expression, STRING, по маске %metric_key%{metricInstanceId="%id%"}, где metric_key и id — параметры коллекции в таблице metrics. (13-[US] Добавление комплексной метрики)
- В разрезе метрики сохраняются: expression — PROMQL-выражение пользователя на момент сохранения; default_value — значение по умолчанию, если в expression получено NaN (результат деления на ноль) ИЛИ при расчёте по правилу из expression после подстановки значений произошло деление на ноль; promql_query_step — введённое значение интервала поиска (интервал (0-Интервал подтверждения; вызов выражения для формирования метрики)). (13-[US] Добавление комплексной метрики)
- Вместе с метрикой сохраняется JSON, использованный на фронте для формирования выражения и выбора переменных; он используется при открытии коллекции на редактирование: пользователь видит то выражение и те переменные, что сохранил. (13-[US] Добавление комплексной метрики)
- Сохраняются все метрики, выбранные как переменные, независимо от использования в выражении (предлагается переименовать таблицу). Связи работают так же, как для синтетических. (13-[US] Добавление комплексной метрики)
- 2.2 Клик вне формы вызывает функциональное окно: «Х»/«Назад к заполнению» — возврат к заполнению; «Не сохранить» — закрытие шторки; «Сохранить» — закрытие окна и выполнение проверок из 2.1. (13-[US] Добавление комплексной метрики)
- 7.0 Формирование PROMQL из конструктора: предусловие — выражение составлено в конструкторе, нажата «Сформировать PROMQL-выражение»; выполняется проверка корректности конструктора; если корректно — в блоке итогового выражения формируется PROMQL-выражение, иначе ошибка по логике из (ссылка обрезана). Повторное нажатие «Сформировать PROMQL» перепишет выражение пользователя. (13-[US] Добавление комплексной метрики)
- 7.1 Ручной ввод: предусловие — выполнено 2.0; пользователь задал выражение в блоке результирующего выражения вручную. При нажатии «Сформировать PROMQL» введённое выражение будет переписано. (13-[US] Добавление комплексной метрики)

### Сообщения и ошибки
- Сообщение об ошибке при проверке конструктора содержит перечень замечаний согласно таблице проверок выражения конструктора; текст ошибки в документе не читается. (13-[US] Добавление комплексной метрики)

### Роли и права
- Действует авторизованный пользователь; доступ по #PM.Ролевая модель. (13-[US] Добавление комплексной метрики)

### Сценарии
- 1.0 Возможность пользователя увидеть кнопку добавления комплексных метрик. (13-[US] Добавление комплексной метрики)
- 2.0 Возможность пользователя видеть форму добавления комплексных метрик. (13-[US] Добавление комплексной метрики)
- 2.1 Возможность пользователя подтвердить создание комплексной метрики. (13-[US] Добавление комплексной метрики)
- 2.2 Возможность пользователя сохранить изменения в случае нажатия вне шторки добавления. (13-[US] Добавление комплексной метрики)
- 7.0: составить выражение в конструкторе → «Сформировать PROMQL-выражение» → проверка → PROMQL-выражение или ошибка. (13-[US] Добавление комплексной метрики)
- 7.1: ввести PROMQL вручную; последующее нажатие «Сформировать PROMQL» перепишет его. (13-[US] Добавление комплексной метрики)

### Открытые вопросы
- Фрагмент частично обрезан: текст ошибки и ссылка на логику её формирования не читаются. (13-[US] Добавление комплексной метрики)
- Предлагается переименовать таблицу сохранённых переменных-метрик. (13-[US] Добавление комплексной метрики)
