# Интеграция с Сфера.Каталог сервисов через Kafka

> Интеграция ЗСМ с Сфера.Каталог сервисов через Kafka: при постановке БС на базовый мониторинг и при снятии ЗСМ однократно отправляет событие в один топик Kafka без подтверждения от Каталога сервисов.

### Описание
- ЗСМ передаёт сведения о постановке/снятии БС с БМ в Каталог сервисов через Kafka (один топик). (12-PPMON-1879. Базовый мониторинг)
- Сообщение отправляется при выполнении функции постановки БС на Базовый мониторинг в карточке БС и при снятии. (12-PPMON-1879. Базовый мониторинг)

### Бизнес-правила и ограничения
- Атрибуты, передаваемые при постановке: идентификатор сервиса (ciId); дата постановки на БМ; ссылка на дашборд (ссылка на «Типовой дашборд БС» по данной БС); ссылка на карточку мониторинга БС в ЗСМ; логин автора (логин текущего пользователя, инициировавшего постановку на БМ, из локальной ролевой модели ЗСМ). (12-PPMON-1879. Базовый мониторинг)
- Передачи изменений нет: изменение ссылки на дашборд в ЗСМ не приводит к передаче изменённой ссылки в Каталог Сервисов. Фактически ожидается, что ссылка будет задана 1 раз. При изменениях обновление общей части ссылки потребует ручных изменений в КС ИЛИ снятия и последующей постановки на БМ со стороны ЗСМ. (12-PPMON-1879. Базовый мониторинг)
- Примечание 2 (21.10.2026): со стороны Каталога сервисов может поддерживаться update, но в функциональности ЗСМ отправки обновлений нет. Согласован вариант, когда Команда Внедрения может обновить ссылку через Kafka путём самостоятельного создания сообщения в ней (вне рамок ЗСМ). (12-PPMON-1879. Базовый мониторинг)
- Паттерн Request/Reply не используется: однократная передача сообщения в Kafka без подтверждения со стороны КС. Producer (ЗСМ) записывает с гарантией доставки At least once. (12-PPMON-1879. Базовый мониторинг)
- Взаимодействие с Каталогом Сервисов только через Kafka, формат сообщений согласован на момент старта работ. Дополнительных требований к интеграции со стороны КС нет (ни starter'а, ни требований к версии springboot у consumer'а и прочего). (12-PPMON-1879. Базовый мониторинг)
- Логин автора: у ЗСМ нет интеграции с ДиР, логин передаётся из локальной ролевой модели (формируется при первичном входе Пользователя в ЗСМ на основании учётных данных из Сфера.Аутентификация и более не меняется). Переход на ДиР в оценку не входит. (12-PPMON-1879. Базовый мониторинг)

### API и интеграции
- Контракт постановки («eventType»: «BS_BASE_MONITORING_ENABLED»): {"eventId":"3f6c2a1e-8b4d-4c7a-9e21-5d0f7a9b1c22","eventType":"BS_BASE_MONITORING_ENABLED","schemaVersion":1,"ciId":"CI00012345","eventDate":"2026-10-19T07:40:12.345Z","authorLogin":"AMysev_tk","dashboardUrl":"https://grafana.example/d/typical-bs?var-ciId=CI00012345","monitoringCardUrl":"https://zsm.example/bs-cards/CI00012345"} (12-PPMON-1879. Базовый мониторинг)
- В разделе 6 пример: dashboardUrl «ссылка на дашборд>», monitoringCardUrl «<ссылка на БС>». (12-PPMON-1879. Базовый мониторинг)
- Контракт снятия («eventType»: «BS_BASE_MONITORING_DISABLED»): {"eventId":"a91d0e44-27f3-4b6e-8c15-0b7e3d5f6a90","eventType":"BS_BASE_MONITORING_DISABLED","schemaVersion":1,"ciId":"CI00012345","eventDate":"2026-11-02T09:15:00.000Z","authorLogin":"AMysev_tk"} (12-PPMON-1879. Базовый мониторинг)
- eventId: String (UUID). Обязательное. Уникальный идентификатор события для дедупликации. Формат: UUIDv4 (например, 3f6c2a1e-8b4d-4c7a-9e21-5d0f7a9b1c22). (12-PPMON-1879. Базовый мониторинг)
- eventType: String (Enum). Обязательное. Тип события. Допустимые значения: BS_BASE_MONITORING_ENABLED, BS_BASE_MONITORING_DISABLED. (12-PPMON-1879. Базовый мониторинг)
- schemaVersion: Integer. Обязательное. Версия схемы для контроля совместимости. Текущее значение: 1. (12-PPMON-1879. Базовый мониторинг)
- ciId: String. Обязательное. Идентификатор конфигурационной единицы в CMDB (например, CI00012345). (12-PPMON-1879. Базовый мониторинг)
- eventDate: String (DateTime). Обязательное. Дата и время фиксации события в источнике. (12-PPMON-1879. Базовый мониторинг)
- authorLogin: String. Обязательное. Логин сотрудника, который инициировал включение или выключение постановки на базовый мониторинг. (12-PPMON-1879. Базовый мониторинг)
- dashboardUrl: String (URL). Обязательное только для eventType = BS_BASE_MONITORING_ENABLED (для DISABLED не передаётся). Прямая ссылка на типовой дашборд БС в Grafana; ссылка реализуется в PPMON-1880 «Ссылка на типовой дашборд в карточке бизнес-сервиса». (12-PPMON-1879. Базовый мониторинг)
- monitoringCardUrl: String (URL). Обязательное только для eventType = BS_BASE_MONITORING_ENABLED (для DISABLED не передаётся). Ссылка на карточку БС в ЗСМ. Сейчас ссылка на БС выглядит так: https://sfera.ppcps-stable.test.sfera-t1.ru/portal/monitoring/cards-bs/2 (можно вместо порядкового номера отображать ciId БС). (12-PPMON-1879. Базовый мониторинг)

### Открытые вопросы
- Формат даты в критериях и в контракте записан по-разному (см. расхождения). (12-PPMON-1879. Базовый мониторинг)

### Расхождения между документами
- Формат даты: в критериях YYYY.MM.DDThh:mm:ss.sssZ, в контракте YYYY-MM-DDTHH:mm:ss.SSSZ (оба в 12-PPMON-1879. Базовый мониторинг).
