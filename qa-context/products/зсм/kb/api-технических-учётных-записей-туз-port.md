# API технических учётных записей (ТУЗ) Portal backend

> Раздел описывает административные методы GET Portal backend для получения списка технических учётных записей (ТУЗ), одной ТУЗ по идентификатору и её версии в указанной заявке.

### Описание
- Базовый адрес Portal backend v1: https://portal-portalbackend.ppmon.test.sfera-t1.ru/portalbackend (portalbackend)
- GET /admin/service-account — «Получение списка технических учетных записей» (portalbackend)
- GET /admin/service-account/{id} — получение технической учетной записи по идентификатору в формате UUID (portalbackend)
- GET /admin/service-account/{id}/draft/{requestId} — «Обновление технической учетной записи по идентификатору в указанной заявке» (метод GET) (portalbackend)

### Поля и элементы
- Общие поля ТУЗ (список и по id): id (string, Идентификатор), name (Название), description (Описание), login (Логин), username (Имя пользователя), tokenUrl (URL токена), clientId (Идентификатор клиента, зарегистрированного у IdP), scope (Список прав/разрешений для токена), resource (URI API, на который выдается токен) (portalbackend)
- configurationUnits (массив object, Конфигурационные единицы): cmdbId (string, Идентификатор); name (string, Значение); ciTypeReadable (string, Тип КЕ для вывода пользователю); smId (string, Идентификатор конфигурационной единицы (КЕ), пример "CI1203767"); editable (boolean, Признак возможности изменения связи); typeId (Идентификатор типа) (portalbackend)
- relatedTypes — Типы КЕ для системного ТУЗа; в ответах списка и по id элементы: name (string, Название типа КЕ), editable (boolean, Признак возможности изменения связи) (portalbackend)
- globalType (string: USER | SYSTEM) — Тип ТУЗа (portalbackend)
- authType (string: LP | SSH | MTLS | TOKEN | AUTHORIZATION_HEADER | OAUTH2) — Подтип ТУЗа (portalbackend)
- countMetricCollection (integer, int64) — Количество связанных коллекций метрик; countIntegrationPoint (integer, int64) — Количество связанных точек интеграций (portalbackend)
- allowMetricManage (boolean) — Разрешение на создание метрик (true-разрешено, false-запрещено) (portalbackend)
- requestStatus (object): id (integer,null, int32), name (string,null), editable (boolean,null) — в ответах списка и по id (portalbackend)
- createdTime — Дата создания; lastModifiedTime — Дата изменения (portalbackend)

### API и интеграции
- GET /admin/service-account: параметр filterDto (в запросе, object, обязательный). Ответ 200 — OK: itemsCount (integer, int64) — Общее число элементов; items (массив) — Элементы на странице; элемент items содержит общие поля ТУЗ, configurationUnits, relatedTypes, globalType, authType, countMetricCollection, countIntegrationPoint, allowMetricManage, requestStatus, createdTime (integer, int64), lastModifiedTime (integer, int64) (portalbackend)
- GET /admin/service-account/{id}: параметр id (в пути, string, обязательный). Ответ 200 — OK, поля как выше; id необязательное; все поля ответа необязательные (portalbackend)
- GET /admin/service-account/{id}/draft/{requestId}: параметры id (в пути, string, обязательный), requestId (в пути, string, обязательный). Ответ 200 — OK, все поля необязательные, описаний нет (portalbackend)
- Поля ответа draft: id, name, description, login, username, tokenUrl, clientId, scope, resource (string); countMetricCollection (integer, int64); countIntegrationPoint (integer, int64); allowMetricManage (boolean); allowedMetricManage (boolean); globalType (USER | SYSTEM); authType (LP | SSH | MTLS | TOKEN | AUTHORIZATION_HEADER | OAUTH2) (portalbackend)
- configurationUnits в draft (массив object): cmdbId (string), name (string), displayLabel (string), env (string), ciType (string), ciTypeReadable (string), ciCategory (string), risId (string), smId (string), serviceCode (string), а также typeId (portalbackend)
- В draft нет requestStatus; есть allowedMetricManage помимо allowMetricManage (portalbackend)

### Расхождения между документами
- configurationUnits.typeId: в GET /admin/service-account и /{id} — string; в draft — integer, int64
- relatedTypes: в списке и по id — массив object (name, editable); в draft — массив из string
- createdTime/lastModifiedTime: в списке и по id — integer, int64; в draft — string

### Открытые вопросы
- Описание draft-метода говорит «Обновление…», но метод GET; назначение (чтение или обновление) не уточнено (portalbackend)
- Структура filterDto не раскрыта (portalbackend)
- У draft-метода нет описаний полей; неясно различие allowMetricManage и allowedMetricManage (portalbackend)
