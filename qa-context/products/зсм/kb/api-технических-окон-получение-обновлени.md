# API технических окон (получение, обновление, удаление, вкл./выкл.)

> REST API административной части Portal backend для работы с техническими окнами (ТО): получение карточки по CMDB ID, обновление, удаление, включение/выключение, а также вспомогательные методы (фильтр КЕ, обновление из CMDB, словарь действий).

### Описание
- API технических окон в Portal backend (префикс /admin/maintenance-window): получение, обновление, удаление, вкл./выкл. ТО; все методы принимают id (в пути, string, обязательный) — CMDB ID окна. (portalbackend)

### Поля и элементы
- Поля ответа GET (все необязательные): cmdbId (string) — CMDB ID; name — Название; description — Описание; createdTime, modifiedTime (string, date-time) — Дата создания / изменения; repeatType (WEEKLY | DATES) — Тип повторения; enabled (boolean) — Состояние, включен/выключен TRUE|FALSE; status (ACTIVE | WAITING | DISABLED) — Статус; relatedMonitoringObjectCount (integer, int32) — Подключено к объектам мониторинга; createdByUserName — Учетная запись создавшего ТО; modifiedByUserName — Учетная запись изменившего ТО; action (NOTHING | SUPPRESS_EVENT | SUPPRESS_REACTION) — Действие; sendEvent (boolean) — Флаг отправки эвента о начале/окончании ТО; reactionRuleId — Id правила реагирования; reactionRuleName — Имя правила реагирования; ecosNotificationGroupId — id группы рассылки; ecosNotificationGroupName — Имя группы рассылки. (portalbackend)
- relatedParentObjects (массив object) — Список ИС и КЕ; элементы: cmdbId, name (string); include (boolean); type (string); monitoringObjects (массив object: cmdbId, name, type — string). (portalbackend)
- schedule (object): weekly (object) — Расписание еженедельное, заполняется при repeatType = WEEKLY; dates (object) — Расписание по датам, заполняется при repeatType = DATES; dateIntervals (массив object) — Расписание по периодам, заполняется при repeatType = DATES; элементы: start (string, date-time, пример: "2025-05-23 00:00:00") — Начало периода; end (string, date-time, пример: "2025-05-26 23:30:00") — Конец периода. (portalbackend)

### API и интеграции
- GET /admin/maintenance-window/{id} — получение ТО по cmdb id для карточки технического окна. Ответ 200 — OK (поля выше). (portalbackend)
- PUT /admin/maintenance-window/{id} — обновление ТО. Тело (application/json), все поля необязательные: name, description, repeatType (WEEKLY | DATES), relatedCmdbIds (массив string) — Список CMDB ID ИС и КЕ, выбранных для технического окна; enabled (boolean) — Включено TRUE|FALSE; schedule (weekly, dates, dateIntervals со start/end — как в GET; заполнение по repeatType); action (NOTHING | SUPPRESS_EVENT | SUPPRESS_REACTION); sendEvent (boolean); reactionRuleId; ecosNotificationGroupId. Ответ: 200 — OK. (portalbackend)
- DELETE /admin/maintenance-window/{id} — удаление ТО. Ответ: 200 — OK. (portalbackend)
- PUT /admin/maintenance-window/{id}/change-enabled — вкл./выкл. ТО. Тело (application/json): enabled (boolean, необязательное) — Включено TRUE|FALSE. Ответ 200 — OK: cmdbId (string) — CMDB ID; enabled (boolean) — Включено TRUE|FALSE; status (ACTIVE | WAITING | DISABLED) — Статус. (portalbackend)
- Смежные методы: GET /admin/maintenance-window/search/filter/cis — получение КЕ для мультиселекта в фильтре Объекты мониторинга; параметр filterDto (в запросе, object, обязательный); ответ 200 — OK: itemsCount (integer, int64) — Общее число элементов; items (массив object) — Элементы на странице: cmdbId, name, ciType (string). (portalbackend)
- GET /admin/maintenance-window/refill-from-cmdb — обновить данные в core-maintenance из cmdb; параметр securityPhrase (в запросе, string, обязательный), нужно прописать iknowwhatido, иначе не заведется; ответ 200 — OK. (portalbackend)
- GET /admin/maintenance-window/action — получить словарь для работы с действиями ТО; ответ 200 — OK, массив: code (string) — Код; desc (string) — Описание; available (boolean) — Доступно для выбора пользователем. (portalbackend)
