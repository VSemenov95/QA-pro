# API календарей (получение, обновление, удаление)

> REST API раздела администрирования для получения карточки календаря по id, его обновления и удаления, а также для получения связанных объектов календаря (правил реагирования, коллекций, шаблонов коллекций, объектов для применения).

### Описание
- GET /admin/calendars/{id} — «Получение календаря по айди для карточки календаря». (portalbackend)
- PUT /admin/calendars/{id} — обновление календаря. (portalbackend)
- DELETE /admin/calendars/{id} — удаление календаря. (portalbackend)

### Поля и элементы
**GET, ответ 200 (все поля необязательные):**
- cmdbId (string) — CMDB ID календаря
- name (string) — Название календаря
- description (string) — Описание календаря
- createdTime (string, date-time) — Дата создания
- accessType (string: USER | SYSTEM) — Тип доступа календаря USER|SYSTEM
- repeatType (string: WEEKLY | DATES | PRODUCTION_CALENDAR | FOR_IAS) — Тип повторения календаря WEEKLY|DATES
- infoSystemNames (массив object) — Список Информационных систем, выбранных в календаре: cmdbId, name, risId (string)
- businessServices (массив object) — Список Бизнес-сервисов, выбранных в календаре: cmdbId, name (string)
- scheduleAssignments (массив string: FOR_ALERTS | FOR_DATA_COLLECTION | FOR_IAS) — Назначения календаря
- useAllBs (boolean) — Флаг использования для всех БС
- useAllIs (boolean) — Флаг использования для всех ИС
- timeType (string: INTERVAL | ONCE) — Тип времени календаря INTERVAL|ONCE
- enabled (boolean) — Календарь включен TRUE|FALSE
- schedule (object) — см. ниже
- collectionTemplatesCount (integer, int32) — Количество шаблонов коллекций, в которых используется календарь
- collectionsCount (integer, int32) — Количество коллекций, в которых используется календарь
- reactionRulesCount (integer, int32) — Количество правил реагирования, в которых используется календарь
(portalbackend)

**Объект schedule (одинаков в GET-ответе и PUT-запросе):**
- weekly (object) — Расписание еженедельное. Заполняется при repeatType = WEEKLY
- dates (object) — Расписание по датам. Заполняется при repeatType = DATES
- productionCalendar (object): enabled (boolean) — Использовать производственный календарь; mode (string: EXCLUDE_WORKING | EXCLUDE_NON_WORKING | OVERRIDE_ALL) — Тип применения производственного календаря; shortenedDays (массив object) — Сокращенные дни; workingDays (массив object) — Рабочие дни; nonWorkingDays (массив object) — Не рабочие дни. Элементы каждого из трёх массивов: start (string) — Начало интервала, заполняется при timeType = INTERVAL; end (string) — Конец интервала, заполняется при timeType = INTERVAL; once (string) — Единичное время, заполняется при timeType = ONCE
- dateIntervals (массив object) — Расписание по периодам. Заполняется при repeatType = DATES: start (string, date-time, пример: "2025-05-23 00:00:00") — Начало периода; end (string, date-time, пример: "2025-05-26 23:30:00") — Конец периода
- excludedDates (массив string) — Даты исключений из повторений
- excludedIntervals (массив object) — Интервалы исключений из повторений: start (string, date) — Начало интервала; end (string, date) — Конец интервала
(portalbackend)

**PUT, тело запроса (application/json, все поля необязательные):**
- name (string) — Название календаря
- description (string) — Описание календаря
- accessType (string: USER | SYSTEM) — Тип доступа календаря USER|SYSTEM
- repeatType (string: WEEKLY | DATES | PRODUCTION_CALENDAR | FOR_IAS) — Тип повторения календаря WEEKLY|DATES
- useAllIs (boolean) — Флаг использования для всех ИС
- infoSystemCmdbIds (массив string) — Список CMDB ID Информационных систем, выбранных в календаре
- useAllBs (boolean) — Флаг использования для всех БС
- businessServiceCmdbIds (массив string) — Список CMDB ID Бизнес-сервисов, выбранных в календаре
- scheduleAssignments (массив string: FOR_ALERTS | FOR_DATA_COLLECTION | FOR_IAS) — Назначения календаря FOR_ALERTS|FOR_DATA_COLLECTION
- timeType (string: INTERVAL | ONCE) — Тип времени календаря INTERVAL|ONCE
- enabled (boolean) — Календарь включен TRUE|FALSE
- schedule (object) — как описано выше
(portalbackend)

### API и интеграции
- GET, PUT, DELETE /admin/calendars/{id}: параметр id (в пути, string, обязательный); ответ 200 — OK. (portalbackend)
- GET /admin/calendars/{id}/related-reaction-rule — Получение списка связанных правил реагирования. Параметры: id (в пути, string, обязательный); filterDto (в запросе, object, обязательный). Ответ 200 — OK: itemsCount (integer, int64) — Общее число элементов; items (массив object) — Элементы на странице: id (string, uuid); name (string); reactionTypes (массив string). (portalbackend)
- GET /admin/calendars/{id}/related-collection — Получение списка связанных коллекций. Параметры: id (в пути, string, обязательный); filterDto (в запросе, object, обязательный). Ответ 200 — OK: itemsCount; items: id (integer, int64); name (string); monitoringObjectId (integer, int64); monitoringObjectName (string); monitoringCardId (integer, int64). (portalbackend)
- GET /admin/calendars/{id}/related-collection-template — Получение списка связанных шаблонов коллекций. Параметры: id (в пути, string, обязательный); filterDto (в запросе, object, обязательный). Ответ 200 — OK: itemsCount; items: id (integer, int64); version (integer, int64); status (string); name (string). (portalbackend)
- GET /admin/calendars/related-objects — Получение списка объектов для применения. Параметры: filterDto (в запросе, object, обязательный). Ответ 200 — OK: itemsCount (integer, int64) — Общее число элементов; items (массив object): cmdbId (string); name (string); ciType (string). (portalbackend)

### Открытые вопросы
- В описании repeatType указано «WEEKLY|DATES», хотя перечень значений включает ещё PRODUCTION_CALENDAR и FOR_IAS. (portalbackend)
- В описании scheduleAssignments (PUT) указано «FOR_ALERTS|FOR_DATA_COLLECTION», хотя перечень значений включает ещё FOR_IAS. (portalbackend)
- Не описаны структуры объектов schedule.weekly и schedule.dates, а также ответы на ошибки, тексты сообщений и права ролей. (portalbackend)
