# API технических учётных записей (ТУЗ): связанные коллекции, черновик, фильтры, КЕ, подтипы

> Административное API Portal backend для технических учётных записей (ТУЗ): получение связанных коллекций, черновика и его заявки, данных для фильтров, конфигурационных единиц (КЕ), их типов, подтипов ТУЗ и поиск ТУЗ по КЕ.

### Описание
- Раздел описывает GET-методы /admin/service-account/* и /admin/service-account-by-cmdb-id: связанные коллекции, черновик ТУЗ и его заявка, данные для фильтрации, КЕ, типы КЕ, подтипы ТУЗ, поиск ТУЗ по КЕ. (portalbackend)

### Поля и элементы
- Черновик ТУЗ (все поля необязательные): id — Идентификатор; name — Название; description — Описание; login — Логин; username — Имя пользователя; tokenUrl — URL токена; clientId — Идентификатор клиента, зарегистрированного у IdP; scope — Список прав/разрешений для токена; resource — URI API, на который выдается токен; countMetricCollection (int64) — Количество связанных коллекций метрик; countIntegrationPoint (int64) — Количество связанных точек интеграций; allowMetricManage (boolean) — Разрешение на создание метрик (true-разрешено, false-запрещено); requestStatus (id int32, name, editable); createdTime (int64) — Дата создания; lastModifiedTime (int64) — Дата изменения. (portalbackend)
- globalType (USER | SYSTEM) — Тип ТУЗа. authType (LP | SSH | MTLS | TOKEN | AUTHORIZATION_HEADER | OAUTH2) — Подтип ТУЗа. (portalbackend)
- configurationUnits (массив): cmdbId — Идентификатор; name — Значение; typeId — Идентификатор типа; ciTypeReadable — Тип КЕ для вывода пользователю; smId — Идентификатор конфигурационной единицы (КЕ), пример "CI1203767"; editable (boolean) — Признак возможности изменения связи. (portalbackend)
- relatedTypes (массив, Типы КЕ для системного ТУЗа): name — Название типа КЕ; editable (boolean) — Признак возможности изменения связи. (portalbackend)

### API и интеграции
- GET /admin/service-account/{id}/paged-linked-collections — пагинированный список связанных коллекций по id (UUID). Параметры: id (путь, string, обязательный); filterDto (запрос, object, обязательный). 200 — OK: itemsCount (int64) — Общее число элементов; items — Элементы на странице: collectionId (int64, обяз.) — Идентификатор коллекции; collectionName (string, обяз.) — Название коллекции; monitoringObjectId (int64, обяз.) — Идентификатор объекта мониторинга; cardId (int64, обяз.) — Идентификатор карточки мониторинга; infoSystemName (string, обяз.) — Название ИС; status (обяз.): id (int32) — Идентификатор, name — Наименование; monitoringObject (string) — Название карточки мониторинга; request (object): id (int64,null), uid (string,null), objectType (number,null: 0–13), processType (id int32, name), status (id int32, name, editable boolean). (portalbackend)
- GET /admin/service-account/{id}/linked-collections — DEPRECATED. Полный список связанных коллекций по id (UUID). Параметр id (путь, string, обязательный). 200 — OK, массив элементов той же структуры, что items в paged-linked-collections. (portalbackend)
- GET /admin/service-account/{id}/draft — черновик ТУЗ по id (UUID). Параметр id (путь, string, обязательный). 200 — OK, поля см. выше. (portalbackend)
- GET /admin/service-account/{id}/draft-request — заявка для черновика ТУЗ по id (UUID). Параметр id (путь, string, обязательный). 200 — OK, все поля необязательные: id (int64,null); uid; parentUid; processType (id int32, name); infoSystemCmdbId: cmdbId — Идентификатор, name — Наименование ИС, risId — Идентификатор РИС, owner (login — Логин пользователя, name — ФИО пользователя, id int64 — Идентификатор, email — Электронная почта пользователя, phone — Контактный номер телефона пользователя); changeRequestTitle; metricCollectionDeleted (boolean,null); infoSystemMetric (boolean,null); createdDate, slaDate, completedDate, modifiedDate (int64,null); objectId; objectDeleted (boolean,null); data (null); objectType (number,null: 0–13); status (id int32, name, editable); createdBy и assignedTo (login, name, id, email, phone); statusDescription; attributes (object,null). (portalbackend)
- GET /admin/service-account/enrich-with-count-metric-collections — Данные для фильтрации ТУЗов. 200 — OK, структура ответа не указана. (portalbackend)
- GET /admin/service-account/data-filter — Данные для фильтрации ТУЗов. Параметр requestDto (запрос, object, обязательный). 200 — OK: itemsCount (int64); items (массив: value, name); content (массив: value, name). (portalbackend)
- GET /admin/service-account/configuration-unit — Получение списка конфигурационных единиц для привязывания к технической учетной записи. Параметр filter (запрос, object, обязательный). 200 — OK: itemsCount (int64) — Общее число элементов; items — Элементы на странице: cmdbId, name, typeId, ciTypeReadable, smId (пример "CI1203767"). (portalbackend)
- GET /admin/service-account/configuration-unit-types — Получение списка типов конфигурационных единиц для привязывания к ТУЗ. 200 — OK (массив; структура элементов не указана). (portalbackend)
- GET /admin/service-account/auth-type — Получение списка подтипов ТУЗа. 200 — OK. (portalbackend)
- GET /admin/service-account-by-cmdb-id — Получение технических учетных записей по КЕ. Параметр filterDto (запрос, object, обязательный). 200 — OK: itemsCount (int64) — Общее число элементов; items — Элементы на странице, структура как в ответе GET /admin/service-account/{id}/draft. (portalbackend)

### Открытые вопросы
- Не указаны структура ответа enrich-with-count-metric-collections, схема элементов configuration-unit-types и формат ответа auth-type. (portalbackend)
- У enrich-with-count-metric-collections и data-filter одинаковое описание «Данные для фильтрации ТУЗов». (portalbackend)
