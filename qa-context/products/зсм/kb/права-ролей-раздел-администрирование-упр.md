# Права ролей: раздел «Администрирование» — управление доступом и технические учётные записи

> Раздел «Администрирование» ЗСМ: права ролей на управление доступом (каталог и карточки учётных записей, экспорт пользователей) и на технические учётные записи (пользовательские и системные ТУЗ), а также API получения ролей и списка пользователей.

### Описание
- Глобальный раздел «Администрирование» со всеми подразделами: Просмотр read — «Доступ к отдельным подразделам» (200-Описание ролевой модели ЗСМ)

### Экраны и навигация
- 5.1 «Управление доступом»: вкладка «Управление доступом», каталог учетных записей, карточка учетной записи, экспорт записей о пользователях (200-Описание ролевой модели ЗСМ)
- 5.2 «Технические учетные записи»: вкладка «Администрирование» с подразделом «Технические учетные записи», каталог пользовательских ТУЗ, карточка пользовательской ТУЗ (вкладки «Связанные коллекции», «История заявок»), карточка системной учетной записи / системной ТУЗ (вкладки «Связанные коллекции», «История заявок») (200-Описание ролевой модели ЗСМ)

### Поля и элементы
- 77 Вкладка «Управление доступом»: Просмотр read - (200-Описание ролевой модели ЗСМ)
- 78 Каталог учетных записей: Просмотр read - (200-Описание ролевой модели ЗСМ)
- 79 Карточка учетной записи: Просмотр read -; Добавление create - (функциональность доступна только с выключенным тоглом с ДИРом); Редактирование update -; Удаление (PPPM-7241) delete - (200-Описание ролевой модели ЗСМ)
- 80 Экспорт записей о пользователях (PPPM-7241): Выгрузка записей create - (200-Описание ролевой модели ЗСМ)
- 81 Вкладка «Администрирование» с подразделом «Технические учетные записи»: Просмотр read + (200-Описание ролевой модели ЗСМ)
- 82 Каталог пользовательских ТУЗ: Просмотр read +; видит только те ТУЗы, у которых выбраны КЕ, относящиеся к ИС, к которой у пользователя есть доступ (у другой роли — видит все пользовательские ТУЗы) (200-Описание ролевой модели ЗСМ)
- 83 Карточка пользовательской ТУЗ: Просмотр read + (может открывать те ТУЗы, у которых выбраны КЕ, относящиеся к ИС, к которой есть доступ у пользователя; у другой роли — любые); Добавление create +; Удаление delete + (может удалять те ТУЗы, у которых выбраны КЕ, относящиеся к ИС, к которой есть доступ); Включение/Отключение update + (доступные созданные ТУЗы); Редактирование update + (доступные ТУЗы) — NEW! (200-Описание ролевой модели ЗСМ)
- 84 Карточка пользовательской ТУЗ (вкладка «Связанные коллекции», PPPM-7241): доступ к кнопке «Перейти в экземпляр коллекции» read + (200-Описание ролевой модели ЗСМ)
- 85 Карточка пользовательской ТУЗ (вкладка «История заявок», PPPM-7241): доступ к кнопке «Перейти к заявке» read - (200-Описание ролевой модели ЗСМ)
- 86 Карточка системной учетной записи: Просмотр read + (видит системные ТУЗ, привязанные к ИС (+ к КЕ, дочерним к этим ИС), доступным для пользователя; видит системные ТУЗ, привязанные к типам КЕ, соответствующим типам ИС (+ КЕ, дочерним к этим ИС), доступным для пользователя; у другой роли — видит все системные ТУЗы); Добавление add -; Удаление delete -; Включение/Отключение update switch_on/switch_off - (NEW!); Редактирование update - (200-Описание ролевой модели ЗСМ)
- 87 Карточка системной ТУЗ (вкладка «Связанные коллекции», PPPM-7241): доступ к кнопке «Перейти в экземпляр коллекции» read + (200-Описание ролевой модели ЗСМ)
- 88 Карточка системной ТУЗ (вкладка «История заявок», PPPM-7241): доступ к кнопке «Перейти к заявке» read - (200-Описание ролевой модели ЗСМ)

### API и интеграции
- GET /admin/users/roles — «Получение ролей системы». Ответ 200 — OK (структура ответа не описана) (portalbackend)
- GET /admin/users/details — «Получение списка пользователей с дополнительными данными». Параметры: filter (в запросе, object, обязательный). Ответ 200 — OK: itemsCount (integer, int64) — Общее число элементов; items (массив) — Элементы на странице (portalbackend)
- Элемент items: id (integer, int64) — Идентификатор пользователя в Портале мониторинга; name (string) — ФИО пользователя; login (string) — Логин пользователя; roles (массив object) — Роли пользователя в Портале мониторинга: id (integer, int32) — Идентификатор, name (string) — Наименование, isExclusive (boolean) — Признак эксклюзивности (portalbackend)
- infoSystems (массив object) — Информационные системы за которые ответственен пользователь с ролью Ответственный ИС: cmdbId (string) — Идентификатор; name (string) — Наименование ИС; risId (string) — Идентификатор РИС; owner (object): login (string) — Логин пользователя; name (string) — ФИО пользователя; id (integer, int64) — Идентификатор; email (string) — Электронная почта пользователя; phone (string) — Контактный номер телефона пользователя (portalbackend)
- businessServices (массив object) — Список бизнес-сервисов пользователя с ролью Технолог БС: cmdbId (string); name (string) (portalbackend)
- userInfoSystems (массив object) — Информационные системы за которые ответственен пользователь с ролью Пользователь: cmdbId, name, risId, owner (те же поля, что в infoSystems) (portalbackend)
- userBusinessServices (массив object) — Список бизнес-сервисов пользователя с ролью Пользователь: cmdbId (string); name (string) (portalbackend)
- modifiedDate (integer, int64) — Дата и время последней модификации; aiopsIntegration (boolean) — Интеграция с ИАС (portalbackend)
- GET /admin/users/details/csv. Ответ 200 — OK (структура ответа не описана) (portalbackend)
