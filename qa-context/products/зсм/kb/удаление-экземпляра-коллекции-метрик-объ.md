# Удаление экземпляра коллекции метрик объекта мониторинга

> Авторизованный пользователь удаляет экземпляр коллекции метрик объекта мониторинга через модальное окно «Удаление»; результат зависит от статуса экземпляра, привязки метрик к ТМ БС, использования в композитном мониторе и настройки автопостановки, а для экземпляров на мониторинге удаление проходит че

## 🟩[RI1] Возможность пользователя удалять экземпляры коллекций метрик-31.pdf

### Описание
- Пользовательская история: Я как Авторизованный Пользователь хочу иметь возможность удалять экземпляры коллекций, для того чтобы убрать из списка экземпляров коллекции устаревший/излишний экземпляр коллекции.
- Работы в разрезе спецификации:
  - №1 Возможность Пользователя удалить экземпляр коллекции метрик объекта мониторинга (критерии 1.0-1.4).
  - №2 Возможность Пользователя создать заявку на удаление экземпляра коллекции в статусе "К удалению" со всеми выключенными метриками (критерии 2.0-2.1).
- В документе есть блок «Предыдущая версия» критериев (1.0-1.5, 2.0-2.1) и новые блоки критериев по сценариям: экземпляр, не стоящий на мониторинге (1.0, 2.0-2.2); экземпляр, стоящий на мониторинге, автопостановка ВКЛ (3.0-3.1, 4.0, 5.0); автопостановка ВЫКЛ (6.0-6.1, 7.0, 8.0-8.1, 9.0-9.2).
- Нумерация критериев в «предыдущей версии» и в новых блоках пересекается (например, 2.0 и 2.1 есть и там, и там).

### Экраны и навигация
- Предусловие: экземпляр коллекции открыт согласно #[RI1] Возможность Пользователя просматривать карточку экземпляра коллекции.
- Удаление запускается кнопкой 'Удалить коллекцию': в карточке экземпляра коллекции, ИЛИ на плашке текущего экземпляра коллекции, ИЛИ на плашке другого экземпляра коллекции.
- Пользователь видит модальное окно 'Удаление' в соответствии с #1.0 Визуальный дизайн.
- Элементы модального окна: кнопка 'Удалить', кнопки 'Х'/'Отменить'.
- После нажатия 'Удалить' система закрывает модальное окно 'Удаление', и пользователь остаётся на странице объекта мониторинга (во всех критериях, кроме 1.3, где описана только ошибка).
- Прототип: Figma, «Удаление экземляра коллекции метрик: модальное окно подтверждения».
- В документе есть страницы «МАКЕТ» (макеты изображений) для критериев 1.0, 2.0, 2.1-2.2, 3.0, 3.1, 4.0, 5.0, 6.0, 7.0, 8.0, 8.1, 9.0, 9.1; текст макетов не извлечён.
- Заголовки блоков макетов: «Возможность Пользователя удалить экземпляр коллекции метрик, НЕ стоящий на мониторинге», «Возможность пользователя удалить экземпляр коллекции метрик, стоящий на мониторинге (автопостановка ВКЛ)», «(автопостановка ВЫКЛ)».

### Поля и элементы
- Модальное окно 'Удаление': кнопка 'Удалить', кнопки 'Х', 'Отменить'.
- Кнопка "Создать заявку" (отображается после пометки экземпляра на удаление).
- Кнопка "Отозвать заявку" (отображается после создания заявки).
- В карточке заявки в разделе "Реестр заявок" для Ответственного ИС: кнопки "Принять в работу" и "Отклонить"; после принятия в работу: "В ожидание", "Выполнить", "Отклонить"; после перевода в ожидание: "Вернуть в работу".

### Бизнес-правила и ограничения
- Проверка привязки к ТМ БС: метрика коллекции считается подключённой к ТМ БС при добавлении ТМ (# [R1][US] Добавление точки мониторинга) или редактировании ТМ (# [R1][US] Редактирование карточки точки мониторинга).
- Если хотя бы одна метрика коллекции подключена к ТМ БС: система закрывает модальное окно, пользователь остаётся на странице объекта мониторинга, система НЕ удаляет экземпляр коллекции, НЕ меняет статус коллекции, пользователь видит предупреждение (критерии 1.1, 2.2, 3.1).
- Если статус экземпляра 'Добавлено' ИЛИ 'Отредактировано' ИЛИ 'Отклонено' и ни одна метрика не подключена к ТМ БС (критерий 1.2): система закрывает окно, пользователь остаётся на странице объекта мониторинга, система удаляет экземпляр коллекции; удаляет связанные виджеты в соответствии с #[RI1] Возможность Пользователя добавить виджет на дашборд; удаляет связанные скрипты, ТУЗы, точки интеграции и тд.; пользователь видит сообщение 'Коллекция метрик удалена'.
  - Новое по виджетам: 1) если в виджете есть метрики помимо удаляемой, из виджета удаляется только данная метрика; 2) если в виджете нет иных метрик, виджет удаляется.
- Если коллекция используется для расчёта композитного монитора (критерий 1.3): формируется ошибка, удаления не происходит.
- Критерий 1.4: статус экземпляра 'На мониторинге', коллекция не используется для расчёта композитного монитора (согласно «Экземпляр коллекции - управление списком коллекций для расчета композитного монитора») и ни одна метрика не подключена к ТМ БС: окно закрывается, пользователь остаётся на странице объекта мониторинга, система НЕ удаляет экземпляр из списка, меняет статус экземпляра на 'К удалению', пользователь видит сообщение 'Коллекция метрик помечена на удаление' и кнопку "Создать заявку" для создания заявки на удаление (см. стори #[RI1] Возможность Пользователя создать заявку на постановку ИС на мониторинг).
- Критерий 1.5: при нажатии 'Х' ИЛИ 'Отменить' система закрывает модальное окно, пользователь остаётся на странице объекта мониторинга, экземпляр коллекции НЕ удалён из объекта мониторинга.
- Критерий 2.0 (предыдущая версия, все метрики выключены): при критерии 1.0 и нажатии 'Удалить', когда все метрики коллекции выключены: окно закрывается, коллекция переходит в статус "К удалению", система отображает уведомление "Коллекция удалена".
- Критерий 2.1 (предыдущая версия): при критерии 2.0 и нажатии "Создать заявку" заявка переходит в статус "На удалении", система отображает уведомление "Заявка создана".
- Экземпляр не стоит на мониторинге:
  - 2.0 (новая): критерий 1.0 выполнен; статус экземпляра = 'Добавлено' ИЛИ 'Отклонено'; ни одна метрика не подключена к ТМ БС → окно закрыто, пользователь остался на странице объекта мониторинга, система удалила экземпляр коллекции.
  - 2.1 (новая): критерий 1.0 выполнен; статус = 'Отредактировано'; коллекция ранее НЕ была поставлена на мониторинг (предыдущий статус = "Добавлено"); ни одна метрика не подключена к ТМ БС → окно закрыто, пользователь на странице объекта мониторинга, система удалила экземпляр коллекции.
  - 2.2: хотя бы одна метрика подключена к ТМ БС → см. выше (экземпляр и статус не меняются, предупреждение).
- Экземпляр на мониторинге, автопостановка ВКЛ:
  - 3.0: критерий 1.0 выполнен И на момент добавления экземпляра в шаблоне, на основании которого он создан, 'Автоматическая постановка метрики' ВКЛЮЧЕНА (в соответствии с #[RI1] Возможность пользователя добавить шаблон коллекций в Каталоге шаблонов /коллекций #[RI1] Возможность пользователя редактировать вкладку "Общие сведения" шаблона коллекции); пользователь нажал 'Удалить'; статус = 'На мониторинге' ИЛИ (статус = "Отредактировано" и коллекция ранее была на мониторинге (предыдущий статус = "На мониторинге")); ни одна метрика не подключена к ТМ БС → окно закрыто, пользователь на странице объекта мониторинга, система НЕ удалила экземпляр из списка, изменила статус = 'К удалению' согласно #PM. Статусная модель заявки на мониторинг/объекта мониторинга, пользователь видит сообщение 'Коллекция метрик помечена на удаление' и кнопку "Создать заявку" (см. стори #[RI1] Возможность Пользователя создать заявку на постановку ИС на мониторинг).
  - 3.1: хотя бы одна метрика подключена к ТМ БС → поведение как в 1.1 (не удалять, статус не менять, предупреждение).
  - 4.0: критерий 3.0 выполнен; пользователь нажал 'Создать заявку' (согласно #[RI1] Возможность Пользователя создать заявку на постановку ИС на мониторинг) → система отображает сообщение "Заявка создана", меняет статус экземпляра на 'На удалении' согласно #PM. Статусная модель заявки на мониторинг/объекта мониторинга, отображает кнопку "Отозвать заявку".
  - 5.0: критерий 4.0 выполнен; пользователь обновил страницу → система удалила экземпляр коллекции; удалила связанные виджеты (#[RI1] Возможность Пользователя добавить виджет на дашборд): 1) если виджет содержит метрики из разных коллекций, система очищает из виджета только метрики удалённой коллекции, остальные продолжают отображаться (сейчас так и реализовано); Новое: 2) если виджет содержит метрики из одной коллекции (и она удалена), виджет удаляется целиком; удалила связанные скрипты, ТУЗы, точки интеграции и тд.
- Экземпляр на мониторинге, автопостановка ВЫКЛ:
  - 6.0: критерий 3.0 выполнен И на момент добавления экземпляра в шаблоне 'Автоматическая постановка метрики' выключена (в соответствии с теми же историями о шаблоне); пользователь нажал 'Создать заявку' → система отображает сообщение "Заявка создана", меняет статус экземпляра на 'Запрос удаления' согласно #PM. Статусная модель заявки на мониторинг/объекта мониторинга, отображает кнопку "Отозвать заявку", отображает заявку в реестре заявок в статусе "Создано".
  - 6.1: пользователь нажал "Создать заявку" и при создании возникла ошибка → система НЕ меняет статус экземпляра, НЕ создаёт заявку на постановку метрики на мониторинг, пользователь видит сообщение 'Заявка не создана. Ошибка на сервере'.

  - 9.0: Ответственный ИС, критерий 8.0, нажал "Выполнить" → статус заявки "Выполнено"; система удалила экземпляр коллекции; удалила связанные виджеты (1) если виджет содержит метрики из разных коллекций, очищаются только метрики удалённой коллекции, остальные продолжают отображаться (сейчас так и реализовано); Новое: 2) если метрики из одной коллекции (и она удалена), виджет удаляется целиком); удалила связанные скрипты, ТУЗы, точки интеграции и тд.
