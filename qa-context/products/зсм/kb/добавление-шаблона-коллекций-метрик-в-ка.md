# Добавление шаблона коллекций метрик в Каталоге шаблонов коллекций: кнопка, форма и создание шаблона

> Авторизованный пользователь с правом на изменение списка шаблонов добавляет новый шаблон коллекций метрик через форму «Добавление шаблона коллекций метрик» с выбором типа, скрипта из хранилища, проверками обязательных полей, подтверждением при выходе и подсказками.

## 29-🟩[RI1]Возможность пользователя добавить шаблон коллекций в Каталоге шаблонов коллекций.pdf

### Описание
- Пользовательская история: «Я как Авторизованный Пользователь хочу возможность добавить новый шаблон в списке шаблонов коллекций метрик, для того, чтобы создавать на основании шаблонов коллекций метрик экземпляры коллекций метрик для использования в карточках мониторинга ИС».
- Контекст: Авторизованный Пользователь с соответствующей ролью должен иметь возможность добавлять новые шаблоны коллекций метрик.
- Добавление шаблона выделено в отдельную статью (PPPM-1417, 28.07.2023).
- История изменений: PPPM-1659 (30.08.2023): 1) добавлена возможность добавить скрипт без сохранения скрипта; 2) добавлена возможность выбора новых коллекций типа Script_Local и Script_Remote вместо Script; 3) указано, что при добавлении коллекции типа скрипт и при выбранном скрипте аргументы скрипта преобразуются в параметры массива Script_Args. PPPM-1697 (13.09.2023): 1) добавлена возможность выбора скрипта для коллекции типа Python (Custom); 2) добавлен учёт категории при выборе скрипта. PPPM-2552 (20.11.2023): добавлена новая функциональность подсказок. PPPM-3840 (13.11.2023): атрибут script_args для скриптовых коллекций добавляется всегда, даже если скрипт не указан.
- Работы в разрезе спецификации: 1.0 Открыть форму добавления шаблона (критерии 1.0-1.2; задачи PPPM-1007 «пользователь может выбрать новый тип запроса в каталоге метрик типа URL» (Закрыто), PPPM-1049 «...типа PORT» (Выполнено), PPPM-1697 «Добавить новый тип коллекции - "PYTHON (Custom)"» (Выполнено)); 2.0 Выбрать скрипт из хранилища скриптов при типе Script_local/Script_remote/Python (custom) (критерии 2.0-2.2; PPPM-1324, PPPM-1697, PPPM-1659); 3.0 Добавить шаблон коллекций метрик (критерии 3.0-3.4; PPPM-1324); 4.0 Подтвердить сохранение изменений при нажатии на область вне формы (критерии 4.0-4.3); 5.0 Видеть текстовую подсказку (критерии 5.0-5.1; PPPM-2552).
- Вне спецификации: «Возможность Пользователя управлять списком шаблонов в Каталоге шаблонов коллекций» (отдельная статья).

### Экраны и навигация
- Страница «Каталога шаблонов коллекций» с кнопкой «Добавить шаблон».
- По нажатию «Добавить шаблон» открывается форма «Добавление шаблона коллекций метрик» (визуальный дизайн #1.1) с элементами для заполнения (#Атрибуты полей форм), кнопкой «Добавить» и кнопкой «Х»/«Отменить».
- Модальное окно с запросом сохранения изменений (#3.0 Визуальный дизайн) при нажатии вне формы; элементы: кнопка «Х»/«Назад к заполнению», кнопка «Не сохранять», кнопка «Сохранить».
- Прототипы (Figma): основная форма добавления шаблона; отображение дополнительного поля для коллекции типа Script_local, Script_Remote или Custom_Python; валидация обязательных атрибутов и сообщение «Шаблон коллекций добавлен»; окно с запросом сохранения изменений при нажатии за пределами области добавления (3.0); появление подсказки (4.0); исчезновение подсказки (4.1).
- Пометки на прототипах: «устарело добавить кнопку удаления выбранного скрипта»; «Устарело, Тип метрики можно изменить»; «Столбец доступно В убрать».

### Поля и элементы
Ограничения в зависимости от типа описаны в отдельной статье (sfera.inno.local/knowledge/pages?id=708259).
- 1. Название шаблона — поле для ввода, формат: строка, обязательно: да, редактируемо: да. Ввод названия шаблона. По умолчанию: не заполнено.
- 2. Описание — поле для ввода, формат: текст, обязательно: нет, редактируемо: да. Ввод текстового описания шаблона. По умолчанию: не заполнено.
- 3. Тип метрики — выбор из выпадающего списка, обязательно: да, редактируемо: да. Возможен выбор одного значения из выпадающего списка; доступные типы согласно «Перечень системных атрибутов в зависимости от типа коллекции». По умолчанию: не выбрано.
- 4. Выберите скрипт — выбор из выпадающего списка, обязательно: нет, редактируемо: да, если тип метрики Script_Local, Script_Remote или Custom Python. Пользователь выбирает скрипт из выпадающего списка, скрипты хранятся со стороны портала. Доступность: если текущий тип скрипта Script_local/Script_remote — доступны только скрипты категории Bash; если Custom (python) — только скрипты категории Python. По умолчанию: не выбрано.
- 5. Автоматическая постановка на мониторинг — чекбокс Вкл/Выкл, обязательно: нет, редактируемо: да. Связано с «Возможность Пользователя добавить коллекцию метрик для объекта мониторинга в карточке мониторинга»: состояние ВКЛ/ВЫКЛ фиксируется в экземпляре коллекции при создании нового экземпляра; определяет жизненный цикл заявки при постановке на мониторинг (см. «Возможность Пользователя создать заявку на постановку ИС на мониторинг»). По умолчанию: Выкл.
- Иконка (i) — при наведении курсора появляется текстовая подсказка (#4.0 Визуальный дизайн).

### Бизнес-правила и ограничения
- 1.0: если список шаблонов открыт по ранее имплементированной логике («Возможность Пользователя просматривать список шаблонов и удалять шаблоны в Каталоге шаблонов коллекций») и по Ролевой модели пользователь НЕ имеет права на изменение списка шаблонов — кнопка «Добавить шаблон» не отображается.
- 1.1: если пользователь имеет право на изменение списка шаблонов — кнопка «Добавить шаблон» доступна для нажатия.
- 1.2: при нажатии «Добавить шаблон» пользователь видит форму «Добавление шаблона коллекций метрик» с элементами для заполнения, кнопкой «Добавить», кнопкой «Х»/«Отменить».
- 2.0: если выбран тип метрики Script_local, Script_Remote или Custom (Python) — отображается выпадающий список «Выберите скрипт».
- 2.1: при открытии списка отображается перечень доступных для выбора скриптов по логике из атрибутов полей форм.
- 2.2: после выбора скрипт становится значением параметра «Выберете скрипт», пользователь видит кнопку для удаления выбранного скрипта.
- 2.3: после удаления выбранного скрипта он перестаёт считаться выбранным, и пользователь может добавить шаблон без выбранного скрипта.
- 3.0: при нажатии «Х» или «Отменить» система НЕ создаёт новый шаблон, закрывает форму, пользователь видит страницу «Каталога шаблонов коллекций».
- 3.1: при нажатии «Добавить», если хотя бы один обязательный атрибут НЕ заполнен — сообщение «Поле обязательно для заполнения» (#2.0 Визуальный дизайн).
- 3.2: при нажатии «Добавить», если все обязательные атрибуты заполнены и (тип коллекции НЕ Script_Local/Script_Remote/Custom_Python ИЛИ (тип Script_Local/Script_Remote/Custom_Python и скрипт не выбран)) — система создаёт новый шаблон; для шаблона формируется список системных атрибутов согласно «Перечень системных атрибутов в зависимости от типа коллекции» и список метрик согласно «Перечень регулярных метрик в зависимости от типа коллекции»; пользователь видит сообщение «Шаблон коллекций добавлен» (#1.1 Визуальный дизайн).
- 3.4: при нажатии «Добавить», если все обязательные атрибуты заполнены, тип Script_Local/Script_Remote/Custom_Python и пользователь выбрал скрипт — система создаёт шаблон, формирует список системных атрибутов и список метрик (как в 3.2), пользователь видит сообщение «Шаблон коллекций добавлен»; кроме того аргументы и подстановки скрипта, заданные при добавлении скрипта (см. «[RI1] Возможность Пользователя добавить скрипт в хранилище скриптов»), преобразуются в системные атрибуты (логика — комментарий №1), и дополнительно формируется набор метрик, соответствующих метрикам скрипта (логика — комментарий №2).
- 4.0: при нажатии на область экрана вне рамок формы показывается модальное окно (#3.0 Визуальный дизайн) с кнопками «Х»/«Назад к заполнению», «Не сохранять», «Сохранить».
- 4.1: «Х» или «Назад к заполнению» — окно закрывается, пользователь остаётся на форме.
- 4.2: «Не сохранять» — шаблон НЕ создаётся, модальное окно закрывается, пользователь видит страницу «Каталога шаблонов коллекций» в соответствии с критериями 3.1-3.3.
- 4.3: «Сохранить» — система закрывает модальное окно и выполняет комплекс проверок, описанных для создания нового шаблона коллекций.
- 5.0: при наведении курсора на иконку (i) появляется текстовая подсказка (#4.0 Визуальный дизайн); 5.1: при уводе курсора подсказка исчезает (#4.1 Визуальный дизайн).
- Допущение: при изменении параметров метрики в Каталоге метрик изменения не применяются к уже добавленным объектам метрики в Карточке мониторинга, и наоборот — при изменении параметров объекта метрики в Карточке мониторинга изменения не применяются к связанной метрике в Каталоге метрик.
- Комментарий №1 (построчное преобразование аргументов скрипта в параметры атрибута шаблона script_args): в качестве ключа строки отображается ПОЛЬЗОВАТЕЛЬСКОЕ название аргумента, сформированное при добавлении скрипта (а не системное, как сейчас); в качестве типа значения учитывается тип, выбранный при добавлении аргумента скрипта; добавляются ограничения: пользователь не может изменить значение пользовательского названия аргумента, не может добавить или удалить строку. В атрибут подтягиваются правила подстановки параметров ТУЗ, заданные при добавлении скрипта. Параметр состоит из строк элементов: «Название» (текст; название подстановки, заданное при добавлении скрипта; редактирование недоступно); «Подтип» (текст; подтип ТУЗ, из которого будет осуществляться подстановка, задаётся при формировании скрипта; недоступно); «Параметр» (текст; ТУЗ, который пользователь должен выбрать для подстановки, по умолчанию указывается значение, заданное на уровне шаблона; доступно).
- Комментарий №2: каждая строчка метрик, заданных при добавлении скрипта, преобразуется в метрику скрипта по логике: «Метрика -> Метрика», «Тип -> Тип» (комментарий: доступно только значение типа = Дробь). Новые строчки метрик отображаются последовательно, согласно нумерации из карточки скрипта, после регулярных метрик. Часть текста комментариев в документе обрезана.

### Сообщения и ошибки
- «Поле обязательно для заполнения» — при нажатии «Добавить» с незаполненным обязательным атрибутом.
- «Шаблон коллекций добавлен» — после успешного создания шаблона.

### Роли и права
- Кнопка «Добавить шаблон» отображается и доступна только пользователю, который по Ролевой модели имеет право на изменение списка шаблонов; иначе не отображается.
- Связанный документ: PM.Ролевая модель Sfera.Портал мониторинга.

### Сценарии
- Открытие формы: пользователь с правом на изменение списка нажимает «Добавить шаблон» и видит форму.
- Выбор скрипта: выбрать тип Script_local/Script_Remote/Custom (Python), открыть список «Выберите скрипт», выбрать скрипт (категория Bash или Python по типу), при необходимости удалить выбор и добавить шаблон без скрипта.
- Создание: заполнить обязательные поля, нажать «Добавить», увидеть «Шаблон коллекций добавлен».
- Отмена: «Х» или «Отменить» — форма закрывается без создания.
- Выход кликом вне формы: модальное окно — вернуться к заполнению, не сохранять или сохранить (с выполнением проверок создания).
- Подсказка: навести курсор на (i) — подсказка появляется, увести — исчезает.

### API и интеграции
- Связанные документы: «[MVP] Возможность Пользователя видеть Главную страницу Портала», «PM.Ролевая модель Sfera.Портал мониторинга», «[RI1] Возможность Пользователя добавить скрипт в хранилище скриптов».
- Скрипты хранятся со стороны портала (хранилище скриптов); аргументы скрипта преобразуются в параметры атрибута script_args (массив Script_Args), подстановки — в системные атрибуты.
