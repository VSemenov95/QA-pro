# PUT API массового обновления коллекций (миграция с версии шаблона на версию)

> PUT API массового обновления коллекций шаблона метрик (bulkUpdateCollections), которое отбирает коллекции версии sourceVersion по фильтру и обновляет их данными версии targetVersion или override-структурой с учётом или без учёта пользовательских изменений.

### Описание
- Фича: PPMON-1810 «Основные API для управления стандартами мониторинга. PUT API: миграция коллекций при повторном применении стандарта с одной версии на другую». Стори: PPPM-5806 US-Q3-6 «PUT API: миграция коллекций с одной версии шаблона на другую». (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- Эндпоинт: PUT `/api/v1/metric-templates/{metricTemplateId}/collections:bulk-update`, operationId `bulkUpdateCollections`. Summary: «Массовое обновление коллекций данными версии шаблона (в т.ч. миграция с версии на версию)». Swagger: openapi 3.0.3, title «Metric Templates API», version "1.0". (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- Отбирает коллекции по фильтру (КЕ и/или список коллекций, логика И/ИЛИ) среди коллекций версии sourceVersion и обновляет данными targetVersion (либо override, если передан). Затрагиваются атрибуты, метрики и метки. При отключённом учёте пользовательских изменений значения полностью перезаписываются, при включённом правки пользователя имеют приоритет выше override. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)

### Поля и элементы
- Path: `metricTemplateId` (integer, обязательный, пример 1000101) — id шаблона.
- Body (application/json, обязательный); required: sourceVersion, targetVersion, filter, preserveUserChanges.
- `sourceVersion` (integer, обяз.) — версия, по которой созданы отбираемые коллекции (пример 3).
- `targetVersion` (integer, обяз.) — версия, значения которой применяются; может совпадать с sourceVersion (пример 4).
- `override` (object, опц., nullable) — JSON-override значений атрибутов/метрик targetVersion; приоритетнее шаблона, ниже пользовательских изменений (при preserveUserChanges = true). `attributes` (object, additionalProperties: true, пример {"Interval": 60}); `metrics` (object, additionalProperties: true). Структура в разработке, пока только пример с интервалом.
- `filter` (object, обяз.) — нужен хотя бы один из ciList / metricCollectionIdList («опционально*»): `ciList` (array<string>, nullable, пример ["CI301001","CI301002"]); `metricCollectionIdList` (array<string>, nullable; только коллекции шаблона версии sourceVersion, пример ["49499"]); `logicOperator` (string, enum AND/OR; обязателен при указании обоих, пример "OR").
- `preserveUserChanges` (boolean, обяз.): true — пользовательские изменения сохраняются (приоритетнее override); false — полная перезапись данными targetVersion/override.
- Примеры: byCiOnly «Отбор только по КЕ» (sourceVersion 3, targetVersion 4, override.attributes.Interval 60, ciList ["CI301001","CI301002"], preserveUserChanges true); byCiAndCollections «Отбор по КЕ и списку коллекций с логикой OR» (3→4, ciList ["CI301001"], metricCollectionIdList ["49499"], logicOperator "OR", preserveUserChanges false).
- Ответ 200: `metricCollectionIdList` (array<object>) — успешно обновлённые коллекции: `ciId` (string, родительская КЕ, "CI301001"), `metricCollectionId` (string, "49499"), `changeRequestId` (string, ID заявки, "REQ-5011"). Пример: [{CI301001, 49499, REQ-5011},{CI301002, 49500, REQ-5012}]. Возвращаются коллекции, найденные по фильтру и обновлённые согласно 1826 «Реализация точечного обновления коллекции из шаблона». (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)

### Бизнес-правила и ограничения
- Вход: id шаблона; target-версия (опционально JSON-override); source-версия; могут совпадать; фильтры И/ИЛИ (обязателен фильтр по КЕ или коллекциям, коллекции должны быть созданы по id шаблона и версии source); обязателен AND/OR; признак сохранения пользовательских изменений. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- Отбор: 1.1) только КЕ — все коллекции КЕ версии source; 1.2) только набор коллекций — те, что созданы для source; 1.3) оба — по 1.1 и 1.2 с учётом AND/OR. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- 2.1) Создаётся черновик изменения найденной коллекции (заявка создастся, даже если изменений нет). (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- 2.2) Учёт пользовательских изменений отключён: атрибуты — удаляются системные и пользовательские, которых нет в target; актуальные (технические названия есть и в коллекции, и в target) обновляются из target (при override — из структуры). Метрики — удаляются унаследованные из source, которых нет в target; оставшиеся унаследованные обновляются из target (при override — из структуры); новые метрики target добавляются; созданные пользователем сохраняются без изменений (!). Метки — удаляются отсутствующие в target (кроме пользовательских); добавляются имеющиеся в target. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- 2.3) Учёт включён: атрибуты (в документе «аналогично 2.1.1») и метрики (в документе «аналогично 1.2») — как выше, но правки пользователя сохраняются с приоритетом выше override. Пользовательские изменения меток дополнительно к 2.2.3 не учитываются, алгоритм может быть уточнён при реализации. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- ВКЛЮЧЕНО: можно указывать только версию шаблона, разрешённую для создания коллекций. После обновления с кастомной структурой дальнейшие изменения коллекции сравниваются с шаблоном версии, для которой коллекция создана/обновлена, а не с json-override. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- НЕ ВКЛЮЧЕНО: параметр override «остановлен мониторинг/запущен мониторинг» и остановка/возобновление мониторинга (вынесено в PPMON-XXX3); возврат списка заявок/коллекций. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)

### API и интеграции
- Безопасность: `security: systemUserAuth` (http, bearer); нужна роль системного пользователя. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- Асинхронный колбэк в топик Kafka со списком всех созданных коллекций — после обработки ЗСМ каждой коллекции (заявка выполнена или нужны ручные действия, в т.ч. неотправленные неполные заявки). Параметры по коллекции: id; название; родительский ИС; текущее КЕ; ID заявки на постановку на мониторинг; внутренний ID заявки; статус полноты заявки (только для черновиков); статус заявки; текущая версия (выполнена — целевая, иначе исходная). (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
- Схема `Error`: `code` (string), `message` (string). (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)

### Сообщения и ошибки
- 200 — «Запрос обработан, возвращён список успешно обновлённых коллекций» (в таблице 2.5: запрос успешно обработан, коллекции созданы, независимо от полноты итоговой заявки).
- 400 — «Ошибка валидации входных данных»: `FILTER_REQUIRED` «Должен быть указан фильтр ciList и/или metricCollectionIdList»; `VALIDATION_ERROR` «При указании ciList и metricCollectionIdList обязателен logicOperator»; `INVALID_OVERRIDE_STRUCTURE` «JSON-override не соответствует структуре шаблона версии targetVersion». В таблице 2.5: пустой ciList, некорректная структура override.
- 401 — «Пользователь не аутентифицирован» (нет/невалиден токен).
- 403 — «Нет прав системного пользователя, либо использование версии targetVersion для обновления коллекций запрещено»; пример `TEMPLATE_VERSION_UPDATE_FORBIDDEN` «Версия 4 шаблона 1000101 не разрешена для использования при обновлении коллекций».
- 404 — «Не найден шаблон, sourceVersion, targetVersion, КЕ или коллекции из фильтра»: `VERSION_NOT_FOUND` «sourceVersion 3 не найдена у шаблона 1000101»; `COLLECTIONS_NOT_FOUND` «По указанному фильтру не найдено коллекций версии sourceVersion»; в таблице 2.5 также `TEMPLATE_NOT_FOUND`, `CI_NOT_FOUND`.
- 500 — «Внутренняя ошибка сервиса». (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)

### Роли и права
- Вызов доступен системному пользователю (bearer); без роли — 403, без/с невалидным токеном — 401. (5-1810. PUT API_ миграция коллекций при повторном применении стандарта с одной версии на другую)
