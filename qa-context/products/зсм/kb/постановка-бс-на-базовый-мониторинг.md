# Постановка БС на базовый мониторинг

> Функция постановки бизнес-сервиса (БС) на базовый мониторинг в ЗСМ из карточки мониторинга: проверки, подтверждение, заявка в Истории изменений и передача данных в Сфера.Каталог сервисов через Kafka.

### Описание
- Фича PPMON-1879: интеграция со «Сфера.Каталог сервисов»: постановка БС на базовый мониторинг и снятие БС с базового мониторинга. (12-PPMON-1879. Базовый мониторинг)
- В Карточке мониторинга БС появляется функция постановки БС на Базовый мониторинг (БМ) (признак); вызывается из меню «…» карточки с подтверждением в модальном окне. (12-PPMON-1879. Базовый мониторинг)
- О постановке ЗСМ сообщает в Сфера.Каталог сервисов через Kafka (один топик). Операция фиксируется в Аудите и Истории изменений БС. (12-PPMON-1879. Базовый мониторинг)
- Зависит от PPMON-1880 «Ссылка на типовой дашборд в карточке бизнес-сервиса»: в каталог отправляется ссылка на типовой дашборд. (12-PPMON-1879. Базовый мониторинг)
- Критерий: при попытке поставить БС на БМ появляется предупреждение в GUI; если пользователь подтверждает, выполняется попытка постановки. (12-PPMON-1879. Базовый мониторинг)

### Экраны и навигация
- Макеты: «Дизайн PIXSO». (12-PPMON-1879. Базовый мониторинг)
- Скриншот 1: карточка БС не на БМ; плашка «Не на базовом мониторинге»; в списке доп. действий кнопка «Установить сервис на базовый мониторинг»; рядом с кнопкой «Создать точку мониторинга» иконка перехода к типовому дашборду (здесь и далее). (12-PPMON-1879. Базовый мониторинг)
- Скриншот 2: экран подтверждения установки. (12-PPMON-1879. Базовый мониторинг)
- Скриншот 3: успех; плашка «На базовом мониторинге» и всплывающее сообщение об успехе. (12-PPMON-1879. Базовый мониторинг)
- Экран подтверждения (сценарий 1.1): заголовок «Установить сервис на мониторинг»; текст «Вы уверены что хотите установить на базовый мониторинг бизнес-сервис?»; кнопки «Отменить» / «Установить». (12-PPMON-1879. Базовый мониторинг)

### Поля и элементы
- Плашка статуса в карточке БС. (12-PPMON-1879. Базовый мониторинг)
- Кнопка доп. действий «Установить сервис на базовый мониторинг» (в сценарии 1.0: «Установить сервис на базовый мониторин»). (12-PPMON-1879. Базовый мониторинг)
- Кнопки модального окна «Отменить» / «Установить». (12-PPMON-1879. Базовый мониторинг)
- Иконка перехода к типовому дашборду. (12-PPMON-1879. Базовый мониторинг)
- Красный тостер (ошибка) и зелёный тостер (успех) снизу. (12-PPMON-1879. Базовый мониторинг)

### Бизнес-правила и ограничения
- Постановка блокируется при невыполнении хотя бы одного условия. Проверки: (12-PPMON-1879. Базовый мониторинг)
  1. БС не архивная: в cmdb нет признака isArchived (атрибут КЕ типа БС «статус» ≠ «Архивная запись»); «снятие с мониторинга» на это не влияет.
  2. Все ТМ в статусе «Подключено» к ИАС (успешно завершено добавление/последнее редактирование; см. [R1][US] Добавление точки мониторинга, [R1][US] Редактирование карточки точки мониторинга); есть минимум 1 метрика «Подключено». Пороги отдельно не проверяются: без них метрику к ИАС подключить нельзя.
  3. Есть хотя бы одна ТМ с типом «Для расчета доступности»; тип выбирается при добавлении/редактировании ТМ и отдельно не меняется. Если она единственная в БС, она «Конечная» по атрибуту «Положение ТМ БМ из Архитектура» (атрибут уже передаётся из Сфера.Конфигурации в ЗСМ).
  4. У каждой ТМ «Для расчета доступности» минимум 1 метрика «Успех» и 1 метрика «Ошибка» (в самой точке, не в черновике). Для «Информационных» ТМ не требуется. Ошибку формировать по первой нарушающей точке.
  5. Есть хотя бы одна ТМ с признаком «Конечная» (признаки задаются при добавлении/редактировании ТМ и при получении из СферыКонфигурации; см. PPMON-1431, PPMON-1874).
  6. Если в БС одна ТМ и выполнено условие 3, она должна быть «Конечная».
  7. Должны быть заведены одна «Конечная» и одна «Начальная» ТМ. «Начальной» ТМ нельзя назначить через интерфейс, только через интеграцию с СК; параметр хранится только в базе.
- Сценария изменения статуса БМ при изменении ТМ после установки нет (так задумано); автоматические проверки по сочетанию требований не требуются. (12-PPMON-1879. Базовый мониторинг)
- Ответ от каталога сервисов не ожидается. (12-PPMON-1879. Базовый мониторинг)

### API и интеграции
- При успешных проверках формируется пакет в топик Kafka для каталога сервисов (см. «Интеграция с Сфера.Каталог сервисов через Kafka»). (12-PPMON-1879. Базовый мониторинг)

### Сообщения и ошибки
- Если не выполнена хотя бы одна проверка, в красном тостере снизу последовательно указываются все нарушенные правила. (12-PPMON-1879. Базовый мониторинг)
  1. «Бизнес-сервис является архивным, установка на базовый мониторинг невозможна.»
  2. «Все точки мониторинга должны быть подключены к ИАС, установка на базовый мониторинг невозможна»
  3. «В бизнес-сервисе отсутствует точка мониторинга с типом "Для расчета доступности", установка на базовый мониторинг невозможна»
  4. «Точка мониторинга %название точка% типа "Для расчета доступности" не содержит обязательную метрику с признком "Успех" или с признаком "Ошибка", установка на базовый мониторинг невозможна»
  5. «В бизнес-сервисе отсутствует точка мониторинга с признаком "Конечная", установка на базовый мониторинг невозможна»
  6. «Единственная точка мониторинга должна иметь признак "Конечная", установка на базовый мониторинг невозможна»
  7. «В бизнес-сервисе должна быть заведена хотя бы одна точка с признаком "Конечная" и хотя бы одна с признаком "Начальная", установка на базовый мониторинг невозможна»
- Успех: зелёный тостер «Сервис установлен на мониторинг». (12-PPMON-1879. Базовый мониторинг)

### Роли и права
- Доступно только ролям «Технолог БС» (в разрезе своих БС) и «Инженер ЗОНТ». (12-PPMON-1879. Базовый мониторинг)
- Объект ролевой модели для сценариев 1.0–1.2: «Карточка мониторинга/update». (12-PPMON-1879. Базовый мониторинг)
- Для доступа к дашборду по ссылке пользователь должен существовать в ЗСМ с соответствующими ролями; ролевая модель не меняется. (12-PPMON-1879. Базовый мониторинг)

### Сценарии
- 1.0: пользователь открывает список активных БС, затем карточку БС не на БМ; видит плашку; открывает доп. действия; видит кнопку «Установить сервис на базовый мониторин». (12-PPMON-1879. Базовый мониторинг)
- 1.1: после 1.0 при нажатии на кнопку возникает экран подтверждения. (12-PPMON-1879. Базовый мониторинг)
- 1.2: после 1.1 пользователь нажимает «Установить»; выполняются проверки; при провале любой — красный тостер; если все пройдены: создаётся заявка типа «Установка на базовый мониторинг» (видна в Истории изменений по БС, сразу выполнена), формируется пакет в Kafka, показывается зелёный тостер «Сервис установлен на мониторинг», статус меняется на «На базовом мониторинге». (12-PPMON-1879. Базовый мониторинг)

### Открытые вопросы
- Тексты плашки различаются: «Не на базовом мониторинге» (скриншоты, раздел 4) и «Не установлено на базовый мониторинг» (сценарий 1.0). (12-PPMON-1879. Базовый мониторинг)
- Критерии: при «количестве ТМ >= 2» нужны «Начальная» и «Конечная»; в проверке 7: «больше двух». (12-PPMON-1879. Базовый мониторинг)
- Текст ошибки проверки 7 упоминает обе точки, а условие в критериях и проверке сформулировано по-разному. (12-PPMON-1879. Базовый мониторинг)
