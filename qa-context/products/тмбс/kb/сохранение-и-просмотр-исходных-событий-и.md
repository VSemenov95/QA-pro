# Сохранение и просмотр исходных событий источника данных

> Настройка администратором сохранения исходных событий источника данных в ClickHouse (JSON целиком и/или технические атрибуты отдельными колонками) и просмотр сохранённых событий.

### Описание
- Продукт сохраняет события источника в ClickHouse: весь JSON целиком или отдельные технические атрибуты (каждый в отдельной колонке); способы можно включать по одному или оба сразу. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4; 7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; 14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Пользовательская история: «Я как Администратор системы. Хочу иметь возможность включить сохранение технических атрибутов источника данных в базу данных. Для того, чтобы обрабатывать эти данные в будущем». Задачи: PPBP-1630, PPBP-1636, PPBP-1690. (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; 7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Пользователь может просмотреть сохранённые исходные события источника. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Экраны и навигация
- Настройка: карточка источника данных, кнопка «Настроить» в шапке открывает боковую шторку настроек сохранения событий; по завершении нажать «Применить». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4; 7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; 14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Просмотр: «Администрирование» -> «Просмотр исходных событий» либо специальная кнопка из источника данных. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Отображение сохранённых технических атрибутов на UI в состав работ не входит. (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)

### Поля и элементы
- Шторка: чекбоксы «Сохранять JSON целиком» (boolean, M, Default False) и «Сохранять технические атрибуты по отдельности» (boolean, O, Default False); поля «Срок хранения данных» (enum) и «Версия» (enum); кнопки «Применить» и «Закрыть». «Срок хранения данных» активен только при включении хотя бы одного чекбокса. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4; 7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; 14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Переключатель «Сохранять события источника» (КП 1.0 — выключен); при включении сохранения шторка показывает поля «Срок хранения данных» и «Версия». (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Блок «Условия поиска»: (Обязательно) «Источник данных» — выпадающий список всех источников, у источников с включённым сохранением индикатор «События сохраняются»; «Версия» — версии источника и вариант «Все»; (Обязательно) «Период» — глубина поиска 1 месяц; (Обязательно) «Максимальное количество» — число выводимых событий; «Текст для поиска» — если найден, столбец «Json» в блоке «События» начинается с введённого текста. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Блок «События» (после кнопки «Поиск»): source_time — исходное время события; insert_time — время вставки в БД; «Версия» — версия, по которой найдено событие; «Json» — предпросмотр; «Шестеренка» — добавляет в таблицу дополнительные атрибуты. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Блок «Json»: по клику событие раскрывается в форматированном виде; справа окно ввода для поиска по JSON-сообщению. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Бизнес-правила и ограничения
- Оба чекбокса выключены — сохранение отключено; хотя бы один включён — включено: isRawDataCollecting = true ИЛИ isTechAttributesCollecting = true. Рядом со статусом источника надпись «События сохраняются». (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Если оба флага false, dataSourceVersion и ttl не требуются. (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- При isTechAttributesCollecting = true сервис получает список тех. атрибутов для dataSourceVersion и добавляет колонку типа string на каждый; имя колонки формируется из имени атрибута. Все атрибуты хранятся как String (функции возвращают String, STRING_AS_INTERNAL_FORMAT_DATE_TIME, JsonNode в виде строки). (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- При смене версии (или состава тех. атрибутов) при включённом isTechAttributesCollecting: получение нового списка, сравнение с текущей схемой, ALTER TABLE — добавление колонок новых атрибутов и удаление колонок отсутствующих; данные удалённых колонок теряются. (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; 14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Допущение 3: пользователя уведомляют, что при изменении состава тех. атрибутов будут изменены таблицы в БД. (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Одновременно на сборе данных может быть только одна версия источника; сбор можно включить только в режиме «Просмотра». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### API и интеграции
- «Применить» -> PUT /api/datasource-data-collecting/{dataSourceId}. Контракты (статус «Изменяется»): GET /api/datasource-data-collecting/{dataSourceId}, PUT того же пути, POST /api/datasource-data-collecting/list. В DataSourceDataCollectingInfoDto: isDataCollecting -> isRawDataCollecting; isTechAttributesOnly -> isTechAttributesCollecting. (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Конфигурация генерируется в admin-service (configuration.value) с параметром saveOnEnrichment: isRawDataCollecting = true И isTechAttributesCollecting = false И saveOnEnrichment = false — preprocessor передаёт сообщение в Kafka-топик для сохранения в ClickHouse; isTechAttributesCollecting = true И saveOnEnrichment = true — preprocessor отправляет данные в Kafka-топик, который читает enrichment. (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Модель данных: таблица src_{$ID}_raw_event_distributed (новая) — колонки по тех. атрибутам выбранной версии; таблица data_source_data_collecting_info (изменяется) — переименованы колонки is_data_collecting и is_tech_attributes_only. Хранилище: ClickHouse. (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse; 14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)

### Сообщения и ошибки
- После «Применить» (КП 1.2, 2.1): «Применение изменений. Изменения в параметрах сохранения источника уже применяются. Пожалуйста, подождите несколько минут, чтобы статус сохранения обновился.» (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Успех (КП 1.3, 2.2): «Успешно. Параметры сохранения событий источника были успешно изменены». Неудача (КП 1.4): «Ошибка. Что-то пошло не так». (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Неудачный ALTER TABLE: changeStatus = "FAILED", причина в errorText. (7-ТМ. [СА] Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- «События не найдены» — ошибка в блоке «Json», если события не найдены или не отображены. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Роли и права
- Настройка: Администратор (Роль #1); ролевая модель действует для UI и API; ID разрешений не указаны. (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)
- Просмотр событий: разрешение ppbp_datasource_messages_read. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Сценарии
- Включение: заполнить общую информацию, параметры подключения и тех. атрибуты; нажать иконку на странице «Общей информации»; переключить свитчер «Сохранять события источника»; выбрать срок хранения; выбрать версию (если сохранение уже было включено, доступны 2 версии: исходная и текущая в статусе «Подключено»; при выборе новой старая пропадает из выбора); «Применить». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- КП 1.0: Роль #1, карточка источника, переключатель выключен, клик «Настроить» -> шторка. КП 1.1: включение любого чекбокса -> появляются «Срок хранения данных» и «Версия». КП 2.0/2.1: после успешного сохранения шторка открывается повторно, изменение чекбоксов и «Применить» отправляют запрос. (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)

### Открытые вопросы
- Раздел «Пользовательский путь» пуст; значения enum для «Срок хранения данных» и «Версия» и ID разрешений не указаны; правила валидации, бизнес-правила и примечания Dev/QA в 14-ТМ пусты. (14-ТМ. Сохранение технических атрибутов исходных событий источника данных в БД ClickHouse)

### Расхождения между документами
- Обязательность «Срок хранения данных» и «Версия»: 7-ТМ — при включённом флаге ttl и dataSourceVersion обязательны; 14-ТМ — оба поля O (необязательные).
- Активность «Версия»: 7-ТМ — при включении хотя бы одного чекбокса; 14-ТМ — ещё и если версий у источника больше 1.
- Статус источника для настройки: 14-ТМ — «Подключен», «В работе» или «В анализе»; Руководство — только «Подключен».
