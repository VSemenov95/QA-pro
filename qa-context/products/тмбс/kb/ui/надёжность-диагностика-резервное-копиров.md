# Надёжность, диагностика, резервное копирование и аварийное восстановление

> Раздел руководства администратора о рекомендациях по надёжности продукта «ТМБС»: диагностика и плановые мероприятия, расписание резервного копирования, критерии аварийных событий и порядок действий при них.

### Описание
- 7.1. Политика безопасности продукта: «Описание будет позднее.» (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- 7.2. План защиты от инцидентов: «Описание будет позднее.» (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- 7.5. Восстановление из резервной копии: «Рекомендаций нет.» (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)

### Бизнес-правила и ограничения
- 7.4. Резервное копирование, рекомендуемое расписание: полный бэкап — в выходные дни 1 раз в неделю; инкрементальный бэкап — один раз в сутки; бэкап-архив логов — несколько раз в сутки. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- 7.5.1.1. Критерии аварийного события: 1) массовые обращение пользователей ИС в службу поддержки; 2) обращение Администратора ИС, Сотрудника службы мониторинга или Аналитика в службу поддержки; 3) выявление События в результате Планово-предупредительных мероприятий со стороны службы поддержки; 4) обращение со стороны сотрудников Мониторинга, администраторов СУБД и серверов приложений; 5) отрицательный результат проверки работоспособности сервисов при вводе продукта в эксплуатацию. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- Перечень возможных аварийных событий: 1) недоступность серверов приложений; 2) недоступность баз данных; 3) некорректная работа продукта. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)

### Сценарии
- 7.3. Диагностика продукта. Процедуры проверки работоспособности и локализации неработающих компонентов — таблица 7.3-1 «Перечень планово-предупредительных мероприятий» (колонки: №, Содержание мероприятия, Периодичность, Ответственный). Ответственный во всех строках — Администратор. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
  1. Мониторинг работоспособности различных компонентов продукта — определяется Администратором (рекомендованная частота: один раз в сутки, 5 дней в неделю).
  2. Локализация неработающих компонентов продукта — определяется Администратором.
  3. Проверка наличия сертификатов — перед запуском пилотной или целевой версии продукта в промышленную среду.
  4. Проверка в консоли администратора Kubernetes состояния подов (все поды запущены в требуемом количестве) — после запуска пилотной или целевой версии продукта в промышленную среду.
  5. Проверка лог-файлов запуска компонентов продукта (микросервисов) на наличие сообщений с типом «ERROR» — после запуска пилотной или целевой версии в промышленную среду.
  6. Проверка работоспособности микросервисов на маршрутах (/healthcheck) — после запуска пилотной или целевой версии в промышленную среду.
  7. Проверка работоспособности микросервисов — ежедневно.
  8. Проверка работоспособности компонента БД PostgreSQL — ежедневно.
  9. Проверка статуса запуска серверов — ежедневно.
  10. Проверка статуса мониторинга использования серверов — раз в месяц.
  11. Проверка статуса мониторинга выполнения задач планировщика — ежедневно.
  12. Мониторинг использования серверов: анализ статистики по лог-файлам — раз в месяц.
- 7.5.1.2. Порядок действий при выявлении аварийного события: 1) диагностика возникшей ситуации, первичный сбор информации; 2) при невозможности самостоятельного устранения проблемы — оповещение координатора, ответственного за выполнение аварийного восстановления; 3) определение специфики проблемы, привлечение специалистов; 4) выполнение действий по восстановлению согласно выбранному сценарию; 5) оповещение об аварийной ситуации. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- Оповещение: потребители информации — Администратора ИС, Аналитик; канал — e-mail и sms/звонок (дополнительно: канал информирования на усмотрении службы поддержки); содержание — данные о зарегистрированном инциденте (описание События, периметр События, возможные причины, плановые сроки устранения, возможные последствия). (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
