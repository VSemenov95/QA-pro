# Передача событий мониторинга в сторонние продукты

> Передача событий мониторинга ТМБС в сторонние продукты (в первую очередь в «Сфера: Зонтичная cистема мониторинга» через Kafka) в виде групповых событий с контрактом полей и атрибутов для ЗСМ и ОСУС.

### Описание
- Группа функций «Передача событий мониторинга в сторонние продукты». (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- Продукт может передавать события мониторинга в сторонние продукты. (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- Каждое событие мониторинга, отправляемое в ЗСМ, считается групповым, т.е. может содержать более 1 выявленного отклонения. (2-Передача событий мониторинга для устранения отклонений )
- В событие вкладывается массив, содержащий ИД сквозной транзакции, вложенный массив ФИ и массив ФТ, УРЛ на дашборд. Все остальные поля контракта без изменений. (2-Передача событий мониторинга для устранения отклонений )
- Добавляется поле «группа нотификации» для ЭКОС. Приведён вариант обновлённого контракта с учётом отправки событий в ОСУС. (2-Передача событий мониторинга для устранения отклонений )

### Бизнес-правила и ограничения
- 6.1 Интеграция со сторонними продуктами для возможности передачи и последующей обработки событий мониторинга. (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- 6.2 Хранение событий мониторинга и обеспечение анализа и просмотра в хранилище событий мониторинга за выбранный пользователем временной период. (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- Правила группировки (период, за который собирается событие мониторинга) должны быть индивидуальными для каждой ЦС. (2-Передача событий мониторинга для устранения отклонений )
- Предусмотреть настраиваемый лимит размера события мониторинга для передачи в Кафку, «возможно в 1 МБ не будем помещаться». (2-Передача событий мониторинга для устранения отклонений )
- ВАЖНО: автоматически сгенерированные события формируются только по группе транзакций, индивидуальные отклонения формируются только вручную. (2-Передача событий мониторинга для устранения отклонений )

### API и интеграции
- События передаются в «Сфера: Зонтичная cистема мониторинга». (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- Взаимодействие через брокер сообщения (Apache Kafka). (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4; 2-Передача событий мониторинга для устранения отклонений )
- Раздел 3.2 «Публичные интерфейсы (API)»: в продукте отсутствуют публичные интерфейсы (API). (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- Контракт события (первая часть):
  - `title`: string, вручную.
  - `application`: string, не заполняется; в Select берётся из переменной окружения; проверить переиспользование для InstanceId контракта ОСУС и наличие логики обработки на стороне ЗСМ.
  - `category`: string, вручную; проверить наличие логики обработки на стороне ЗСМ.
  - `alertText`: string, вручную; описание события для ЗСМ.
  - `externalId`: string, вручную.
  - `severity`: string, вручную.
  - `ciName`: string, руками; название ЦС согласно Каталогу сервисов, соответствует «ChainName» для ОСУС.
  - `ciType`: string, не заполняется; Сервис или Цепочка сервисов, сейчас NULL.
  - `metricName`: string, вручную; соответствует «MetricName» для ОСУС.
  - `metricValue`: string, вручную.
  - `timeCreated`: пример «2026-03-04T14:08:59.623Z», вручную; время срабатывания, соответствует DetectionTime для ОСУС.
  - `metricKey`: string, считается автоматически по настройкам переменных окружения.
  - `alertId`: string, не заполняется, сейчас NULL.
  - `originalData`: {}, руками, для записи оригинального JSON; записывает ЗСМ; рекомендовано к удалению.
  - `additionalAttributes`: {}, не заполняется.
  (2-Передача событий мониторинга для устранения отклонений )
- `customAttributes`:
  - `ppbpNotificationGroup`: string; согласно значению поля «Группа оповещений» на FE. Если не указана, присылать атрибут с пустой строкой; соответствует NotificationGroup для ОСУС.
  - `ChainName` (пример «Размещение депозитов ЮЛ», автоматически) — в документе закомментировано.
  - `ChainCode`: пример «СМБ-БЦ-2185», автоматически из конфигураций.
  - `CIID`: пример «CI123456», автоматически из Конфигураций.
  - `MetricId`: пример «1234», вручную из внутренних конфигураций ТМБС — Atribute_Id.
  - `MetricCode`: пример «АН.ФИ1», автоматически из поля MetricCode события мониторинга.
  - `MetricName` (пример «АН.ФИ1 бла бла») и `DetectionTime` (пример «2025-09-24T14:19:27.224+03:00») — закомментированы.
  - `InstanceId`: пример «PPBP-01», автоматически из переменной окружения.
  - `PublishTime`: пример «2025-09-24T14:19:32.224+03:00», автоматически; время отправки в интеграцию.
  - `TransactionEvents`: массив объектов, вручную: 4 поля селектом — массив FinancialInstructionIds, массив FinancialTransactionIds, поле TransactionId; DashboardUrl формируется как конкатенация ссылки + TransactionId.
    - `TransactionId`: пример «2d94ac8b-5189-4e9e-8eab-2075686225bd».
    - `FinancialInstructionIds`: массив (пример «74f9e809-620c-48b7-84f6-af14b1ddb541», «bea0716d-02e8-4ac4-a86e-5823341f0503»).
    - `FinancialTransactionIds`: массив (пример «6775f047-8ff1-4e22-827d-3f1b5a390602», «c587d382-e4ca-4714-81fe-bebf6171f402»; в первом элементе примера также «bea0716d-02e8-4ac4-a86e-5823341f0503»).
    - `DashboardUrl`: шаблон «https://p0ppbp-apc001lk.region.vtb.ru:3000/d/m1OxbBxIz/<имя дашборда для ЦС>?var-transaction_uuid=<TransactionId>».
  (2-Передача событий мониторинга для устранения отклонений )

### Открытые вопросы
- Можно ли переиспользовать `application` (из переменной окружения) для InstanceId контракта ОСУС. (2-Передача событий мониторинга для устранения отклонений )
- Есть ли логика обработки `application` и `category` на стороне ЗСМ. (2-Передача событий мониторинга для устранения отклонений )
- `originalData` рекомендовано к удалению. (2-Передача событий мониторинга для устранения отклонений )
- Лимит размера события для Kafka: возможно, 1 МБ недостаточно. (2-Передача событий мониторинга для устранения отклонений )
- В примере JSON неточности структуры (незакрытые/лишние скобки, отсутствует запятая в массиве FinancialTransactionIds первого элемента). (2-Передача событий мониторинга для устранения отклонений )
