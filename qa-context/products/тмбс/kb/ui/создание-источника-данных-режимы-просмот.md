# Создание источника данных (режимы просмотра и редактирования, статусы, валидация)

> Создание, просмотр и редактирование источника данных в продукте ТМБС: страница конфигурации с вкладками, режимами просмотра и редактирования, статусами и валидацией.

### Описание
- Пользовательская история: «Я как Администратор. Хочу Создать источник данных. Для того, чтобы Поставить БС на мониторинг на базе этого источника». Добавление редактирования созданного источника меняет существующий паттерн создания; паттерн меняется для единообразия создания и редактирования. Макеты Figma (проект «Мониторинг») — в п. 5.4. Версия от 15.02.2024, автор Полоухина Мария, PPBP-1627. (ТМ. Создание источника данных-18)
- Документ «Валидация источника данных» описывает правила проверки наименования технических атрибутов и наименования источника данных, требования к уникальности и обработку ошибок. (7-ТМ.Валидация источника данных)
- Разделы 6.1–6.4 «Описание технического решения» содержат только незаполненные шаблонные подсказки. (ТМ. Создание источника данных-18)

### Экраны и навигация
- Список источников с кнопкой «+ Создать источник данных»; форма названия с кнопками «Создать» и «Отмена»; страница конфигурации в режимах редактирования и просмотра. (ТМ. Создание источника данных-18)
- Шапка: «Наименование источника», «Статус», «Сохранить»; в просмотре дополнительно «Версия» и «Редактировать». Вкладки: «Общая информация», «Параметры подключения», «Предварительная обработка», «Технические атрибуты», «Сводка». Шторки: пример события (кнопка «Пример события» на «Общая информация»), отдельный тех. атрибут. (ТМ. Создание источника данных-18)
- «Общая информация», редактирование: Наименование источника (с карандашом, редактируемо); Статус (список активен, по умолчанию «Черновик»); Информационные системы (список активен); Описание (редактируемо); «Пример события» (активна) — поле кода редактируемо. Просмотр: наименование без карандаша, нередактируемо; Статус отображает «Черновик»; Версия (список неактивен, «Нет версий»); «Редактировать» активна; Информационные системы неактивны; Описание нередактируемо; поле кода только для чтения. (ТМ. Создание источника данных-18)
- «Параметры подключения»: Тип источника (в редактировании список активен, в просмотре неактивен), Описание. Kafka: bootstrapAddress, inputTopics. Ключ-АСТРОМ: Идентификатор переменного окружения кластера, Имя хоста кластера, ID сервиса, Наименование сервиса, Описание сервиса. Редактируемы в редактировании, нередактируемы в просмотре. (ТМ. Создание источника данных-18)
- «Предварительная обработка»: переключатель «Настроить обработку JSON» (активен в редактировании, неактивен в просмотре). При включении: Тип обработки массива данных (список), Путь к массиву данных, «Запустить обработку» (в просмотре неактивна), поле «Пример событий», «Развернуть всё», «Свернуть всё» (всегда активны). (ТМ. Создание источника данных-18)
- «Технические атрибуты»: Формат события; Наименование тех.атрибута; «+ Добавить атрибут»; «Пример события»; переключатель «Дедупликация»; «Дедупликация отдельных тех. атрибутов» (только при включённой общей). В редактировании всё активно, в просмотре неактивно, кроме «Пример события». В шторке: Наименование атрибута (с карандашом только в редактировании), Функция, Условия, «Проверить код» (активна всегда), «Событие 1» (при сложном JSON, активен), поле кода только чтение. (ТМ. Создание источника данных-18)
- «Сводка» (оба режима): в блоке «Тех. атрибуты» сводная таблица тех.атрибутов. (ТМ. Создание источника данных-18)

### Поля и элементы
- Наименование источника: заголовок (в редактировании с карандашом, в просмотре без); произвольное значение; не может быть пустым, не может состоять только из пробельных символов, подчеркиваний, спец.символов; первый символ не может быть пробелом. Есть поле «название» (наименование источника данных), поле наименования технического атрибута и элемент сохранения наименования источника (ТМ. Создание источника данных-18; 7-ТМ.Валидация источника данных)
- Шапка: «Статус» — раскрывающийся список, активен; доступны только статусы, в которые можно перейти согласно статусной модели. В редактировании: «Сохранить» — кнопка, активна. В просмотре: «Версия» — раскрывающийся список, активен, при создании источника «Нет версий»; «Редактировать» — кнопка, активна (ТМ. Создание источника данных-18)
- Вкладка «Общая информация»: «Информационные системы» — раскрывающийся список, обязательное, минимум 1 ИС; в редактировании можно добавить новую ИС, но не удалить; в просмотре неактивен. «Описание» — необязательное, произвольное значение; в просмотре неактивно. «Пример события» — кнопка, активна; шторка «Пример события» с полем «Код примера события»: в редактировании можно изменить, проверяется валидность кода в формате JSON; в просмотре только чтение (ТМ. Создание источника данных-18)
- Вкладка «Параметры подключения»: «Тип источника» — раскрывающийся список, обязательное, должен быть выбран один из типов; в просмотре неактивен. «Описание» — необязательное, произвольное; в просмотре неактивно (ТМ. Создание источника данных-18)
- Kafka: «bootstrapAddress» (поле ввода, обязательное) — адрес по шаблону «host:port»; «host» — IP-адрес или доменное имя сервера Kafka, допустимы только a-z, A-Z, 0-9, дефис (-) и точка (.); «port» — номер порта сервера Kafka, только цифры 0-9, значение от 1 до 65535 включительно; между «host» и «port» один символ — двоеточие (:); пробелы перед, после и внутри строки не допускаются; можно ввести несколько адресов из кластера через запятую без пробела, каждый адрес должен соответствовать правилам валидации. «inputTopics» (поле ввода, обязательное) — наименование топика не более 255 символов; допустимы a-z, A-Z, 0-9, подчёркивания (_), дефисы (-), точки (.); первый символ не может быть числом или символом подчеркивания. «maxPollRecords» — значение по умолчанию 500, убрано из интерфейса. В просмотре поля неактивны (ТМ. Создание источника данных-18)
- Ключ-Астром: «Идентификатор переменного окружения кластера» (обязательное) — a-z, A-Z, 0-9, _, -, .; первый символ не может быть _, - или точкой. «Имя хоста кластера» (обязательное) — a-z, A-Z, 0-9, - и .; первый символ не может быть _, - или точкой. «ID сервиса» (обязательное) — a-z, A-Z, 0-9, _, -; первый символ не может быть _ или -. «Наименование сервиса», «Описание сервиса» — необязательные, произвольное значение. В просмотре все поля неактивны. Убраны из интерфейса: «Отступ от стартового окна (в мс)» = 120000, «Шаг окна (в мс)» = 60000, поле «raw_data_topic», «Загружать без детализации данных» = true (ТМ. Создание источника данных-18)
- Вкладка «Предварительная обработка»: блок «Обработка JSON с массивом данных»; «Настроить обработку JSON» — тоггл; «Тип обработки массива данных» — раскрывающийся список, необязательное; «Путь к массиву данных» — поле ввода, обязательно при активированном тоггле, должен быть указан путь к элементу JSON, при невалидном значении будут отсутствовать обработанные события при нажатии «Запустить обработку»; «Запустить обработку» — кнопка; «Пример события» — заголовок, нередактируемый; «События» — аккордеон, только чтение; «Развернуть всё»/«Свернуть всё» — кнопки, активны. В просмотре тоггл, список, путь и «Запустить обработку» неактивны (результат сохранён в примере событий, повторное нажатие не требуется); аккордеон и кнопки развернуть/свернуть активны (ТМ. Создание источника данных-18)
- Вкладка «Технические атрибуты»: «Формат события» — раскрывающийся список; «Наименование тех.атрибута» — поле ввода: только a-z нижнего регистра, 0-9, _; первый символ не цифра и не _; наименования уникальны (не должно быть двух тех. атрибутов с одинаковым наименованием); «+ Добавить атрибут» — кнопка; «Пример события» — кнопка, активна; «Дедупликация» — тоггл; «Дедупликация отдельных тех. атрибутов» — тоггл, отображается только при включённой общей дедупликации. В просмотре все неактивны, кроме «Пример события». Тех.атрибут «event_time» должен быть обязательно; в правилах его обработки (шторка со списками и полями ввода) должна быть выбрана функция времени, например: formatDate, formatUnixtime, getCurrentTime (ТМ. Создание источника данных-18)
- Шторка тех.атрибута: наименование (заголовок; в редактировании с карандашом, правила те же, что у наименования; в просмотре без карандаша); «Функция» — раскрывающийся список; «Условия» — список/поле ввода, необязательное, набор компонентов зависит от функции, в просмотре неактивны, при невалидном значении будут отсутствовать обработанные события при нажатии «Проверить код»; «Проверить код» — кнопка, активна в обоих режимах; «Событие 1» — раскрывающийся список, необязательное, нередактируемый, отображается при настроенной обработке сложного JSON, можно выбрать другое событие и просмотреть его; «Пример события» — поле кода, только чтение (ТМ. Создание источника данных-18)
- Вкладка «Сводка»: раскрывающийся блок «Тех. атрибуты»; в редактировании данные о связях с КТ, БС (КМ) не отображаются; в просмотре напротив тех. атрибута указано, к каким контрольным точкам он подключен и к каким БС (КМ); пока связей нет, значения не отображаются (ТМ. Создание источника данных-18)

### Бизнес-правила и ограничения
- БТ 1: создание включает режим просмотра и режим редактирования; завершено при статусе «Подключен», дальше изменения идут в процессе редактирования. БТ 2: нельзя вводить невалидные значения. БТ 3: нельзя перевести в «Подключен» без обязательных полей. (ТМ. Создание источника данных-18)
- БТ 4: «Черновик» → «Подключен» напрямую (только в него), минуя «В анализе», «В работе»; статусов 6, эти два остаются в БД и разрешениях, в интерфейсе недоступны; доступны только статусы по статусной модели. (ТМ. Создание источника данных-18)
- БТ 5: значения true/false тех.атрибутов должны отображаться (сейчас для true — пустота, для false — «пусто»). (ТМ. Создание источника данных-18)
- При «Подключен» + «Сохранить» проверяется: 1) обязательные поля заполнены; 2) по правилам валидации; правила обработки добавленных тех.атрибутов заполнены. Валидация названия источника — на всех этапах; обязательных полей — при переводе в «Подключен» + «Сохранить». Приоритет — поля из п. 5.4.1. (ТМ. Создание источника данных-18)
- Вкладка «Сводка»: связи с КТ, КМ (БС) как в макетах редактирования; пока связей нет, значения в колонках не отображаются. Дропдаун версий только в режиме просмотра; при создании «Нет версий». В режиме редактирования «Сохранить» неактивна до внесения изменений. (ТМ. Создание источника данных-18)
- В «Информационные системы» можно добавить новую ИС, но не удалить. Код примера события проверяется на валидность JSON. «Дедупликация отдельных тех. атрибутов» отображается только при включённом общем переключателе. Невалидный «Путь к массиву данных» — нет обработанных событий при «Запустить обработку»; невалидные условия — при «Проверить код». В просмотре при создании «Запустить обработку» неактивна (результат уже сохранён в примере событий). (ТМ. Создание источника данных-18)
- Наименование тех.атрибута: только латиница нижнего регистра, цифры, «_»; первый символ — латинская буква (не цифра, не «_»); без пробелов; макс. 128 символов по умолчанию. Примеры: azzz, a8zz, a_8zz, не Azzz, 9azz, _dzz. Запрещённые слова: uuid, transaction_uuid, event_source_id, event_stage, event_transaction_type, event_time, source_timestamp, merge_timestamp, insert_timestamp. (7-ТМ.Валидация источника данных)
- Наименование (источника): любые комбинации латиницы, кириллицы, символов, пробелов при наличии хотя бы одной буквы или цифры. Пример: " ;;№№"02john doe, не "№;%;№. Из спецсимволов разрешено только «_». (7-ТМ.Валидация источника данных)
- Наименования всех тех.атрибутов уникальны (проверка на бэкенде); допускается совпадение наименования источника и одного из тех.атрибутов. (7-ТМ.Валидация источника данных; ТМ. Создание источника данных-18)

### Сообщения и ошибки
- Тех.атрибут, недопустимые символы (при вводе; поле красным, под полем, нельзя закрыть): «Допустимы только буквы латинского алфавита нижнего регистра (a-z), цифры (0-9), подчеркивания (_). Первый символ не может быть цифрой и символом подчеркивания» (7-ТМ.Валидация источника данных; ТМ. Создание источника данных-18)
- При сохранении, окно справа снизу, исчезает по таймауту, можно закрыть: дубль — «Ошибка. Два или более технических атрибута с одинаковыми названиями. Пожалуйста, убедитесь, что каждый технический атрибут имеет уникальное название, и попробуйте сохранить снова»; пусто — «Ошибка. Пустое значение в названии технического атрибута. Пожалуйста, убедитесь, что введено корректное значение»; запрещённое слово — «Ошибка. Наименование технического атрибута содержит запрещенное слово. Пожалуйста, придумайте другое наименование» (7-ТМ.Валидация источника данных)
- Наименование, недопустимые символы: текста ошибки нет, блокируется элемент сохранения наименования. (7-ТМ.Валидация источника данных)
- Нотификации: источник успешно создан (первое сохранение); изменения сохранены (перевод в «Подключен», смена статуса в просмотре); ошибка, если «Подключен», не заполнены обязательные поля п. 5.4.1.2 и нажато «Сохранить» — не сохраняется (текст не приведён). (ТМ. Создание источника данных-18)
- Конкурентное редактирование: «Источник редактируется пользователем <Имя пользователя>. Дождитесь завершения редактирования» (ТМ. Создание источника данных-18)

### Роли и права
- Роль: Администратор; предусловие — пользователь авторизован в SFERA. (ТМ. Создание источника данных-18)
