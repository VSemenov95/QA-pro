# Дополнительные поля в метриках из вычисляемых атрибутов

> Администратор выбирает в карточке мониторинга дополнительные поля (тех.атрибуты БС, event_stage, group_id), которые добавляются в таблицы вычисляемых атрибутов и метрик ClickHouse для настройки фильтров на дашбордах.

### Описание
- История: «Я как Администратор хочу добавить необходимые поля в таблицу БД с выч.атрибутами (с метриками), чтобы настраивать фильтры по указанным полям и иными способами оперировать данными при построении дашбордов». Сейчас дашборды не показывают результаты расчёта в разрезе фильтров: в таблицах нет нужных полей. ([US] Дополнительные поля в выч.атрибутах-31; 8-[US] Дополнительные поля в метриках)
- Поля (тех.атрибуты БС + event_stage + group_id) добавляются в ClickHouse в default.bs_%_attribute и default.bs_%_timeout_attribute. ([US] Дополнительные поля в выч.атрибутах-31)
- В default.bs_%_metric добавляются те же поля, что выбраны для выч.атрибутов. ([8-[US] Дополнительные поля в метриках)
- История: v7 (2025-03-25, Лазарев Никита) — переработка, добавлена TM_FILTERING_ATTRIBUTE_MAX_COUNT; v6 (2024-03-15) — детали состава полей в п. 1 бизнес-требований и критерии приемки 2. Метрики: v1, 2024-04-11, Полоухина Мария, PPBP-1969 [Analytics] 496, «Создание документа», «Выполнено». ([US] Дополнительные поля в выч.атрибутах-31; 8-[US] Дополнительные поля в метриках)

### Экраны и навигация
- Шаг «Вычисляемые атрибуты» карточки мониторинга (КМ): блок полей для настройки фильтров с кнопкой «+ Добавить поля для настройки фильтров»; блок «Вычисляемые атрибуты» с кнопкой «+ Создать вычисляемый атрибут» и списком. ([US] Дополнительные поля в выч.атрибутах-31)
- Кнопка открывает справа шторку «Добавление полей для настройки фильтров в выч. атрибутах»: поиск, список полей с чекбоксами, блок «Выбранные поля» (изначально пуст), счетчик (0), кнопки «Сохранить» и «Закрыть». После сохранения поля показаны чипсами, справа кнопка «Редактировать». ([US] Дополнительные поля в выч.атрибутах-31)
- Настройки применяются на шаге «Сводка» кнопкой «Поставить на мониторинг» или «Обновить карточку мониторинга» (в критериях приемки также «Обновить карточку»). ([US] Дополнительные поля в выч.атрибутах-31)
- Макеты Figma: Форма 1 — КМ без полей; 2 — шторка по умолчанию; 3 — с выбранными полями; 4 — с максимумом полей; 5 — КМ с добавленными полями. Для метрик: Форма 1 «Изменения на вкладке выч.атрибутов», https://www.figma.com/file/7wFx3vZPeDiIBMgdfnrOIV/Monitoring-card.-TRM-(Light)?type=design&node-id=319-18439&mode=design&t=hpz52U0Rlh3NRke9-4 ([US] Дополнительные поля в выч.атрибутах-31; 8-[US] Дополнительные поля в метриках)

### Поля и элементы
- Строка поиска: ввод названия поля, отображаются подходящие поля с чекбоксами. Список: наименования будущих колонок default.bs_%_event (тех.атрибуты БС + event_stage + group_id). При выборе максимума чекбоксы невыбранных становятся disable. ([US] Дополнительные поля в выч.атрибутах-31)
- Чипсы в шторке удаляются крестиком или снятием чекбокса; на странице шага чипсы только для просмотра (редактируемое: Нет), менять через «Редактировать». ([US] Дополнительные поля в выч.атрибутах-31)
- Информер блока: «Выбранные поля будут добавлены в таблицы вычисляемых атрибутов и метрик бизнес-сервиса в Clickhouse для последующей настройки фильтров на дашбордах». ([8-[US] Дополнительные поля в метриках)

### Бизнес-правила и ограничения
- Состав полей = будущие колонки default.bs_%_event: все тех.атрибуты, привязанные к бизнес-атрибутам БС (одноименные — одно поле, distinct); group_id — группа ключевых идентификаторов (тех.атрибут оригинального ключевого идентификатора не отображается); event_stage — контрольная точка. Состав уникален для каждой КМ, общее только event_stage. Изменения КМ (например, удаление КТ) меняют доступные поля. ([US] Дополнительные поля в выч.атрибутах-31)
- Максимум полей n задаёт переменная деплоя TM_FILTERING_ATTRIBUTE_MAX_COUNT, диапазон [1; +бесконечность), значение <1 приравнивается к 1; ограничение показано в UI. При n выбранных остальные недоступны, при снятии — снова доступны. Поле trmonbs_reg_id не считается (event_time, event_stage, trmonbs_reg_id = 2 поля). ([US] Дополнительные поля в выч.атрибутах-31)
- После редеплоя, если максимум стал меньше выбранного: карточки «На мониторинге» не меняются; при редактировании можно убирать поля в любом количестве, новые доступны, когда выбрано n-1. ([US] Дополнительные поля в выч.атрибутах-31)
- Функциональность опциональна, чекбоксы по умолчанию не отмечены. Доступна при создании и редактировании, только в статусе «Черновик» (новой версии тоже); в режиме просмотра кнопки «+ Добавить поля для настройки фильтров» и «Редактировать» пропадают. Работает для карточки, не стоявшей и стоящей на мониторинге (через редактирование). ([US] Дополнительные поля в выч.атрибутах-31)
- При применении колонки добавляются во всех нодах кластера ClickHouse. В attribute/timeout_attribute пишутся значения одноименных колонок default.bs_%_event массивом (значения транзакции, по которой рассчитан атрибут). ([US] Дополнительные поля в выч.атрибутах-31)
- Метрики: поля добавляются с типом Array; значения на уровне бизнес-логики не пишутся — пользователь использует groupArray в коде метрики; для фильтров на дашборде нужны функции/операторы для массивов (arrayJoin, IN). Колонки-константы из выч.атрибутов в метрики не переносятся. Пользователь может добавлять и удалять поля. Критерии приемки — только положительный сценарий. ([8-[US] Дополнительные поля в метриках)

### API и интеграции
- Компоненты: trmon-config-service (доставка конфигурации КМ), trmonbs-postgresql (хранение конфигурации КМ, КТ), trmonbs-admin-service (API с UI, конфигурация КМ, состав таблиц в ClickHouse), trmonbs-fe (выбор полей), trmonbs-clickhouse, сервисы online-metric и timeout-attribute (расчёт, запись в добавленные колонки). ([US] Дополнительные поля в выч.атрибутах-31)
- Postgres config_service.filtering_attributes (создаётся): id (int), entity_id (int, родительский атрибут), bs_id (int), name (string: event_stage, group_id или тех.атрибут КТ), is_filtering (boolean). config_service.configuration: в «value» добавляется часть переноса значений массивом. Online-metric: attribute_type (HARDCODED_ATTRIBUTE, GROUP_ID, CHECKPOINT_ATTRIBUTE); key tm.online-calc.metrics.%. ([US] Дополнительные поля в выч.атрибутах-31)
- Значение переменной деплоя приходит отдельным API (позже) при нажатии «Добавить поля»/«Редактировать» и подставляется в «Можно выбрать максимально __ полей». ([US] Дополнительные поля в выч.атрибутах-31)
- Kafka: в сообщения добавляется additionalFields (пример [event_stage, technical_attribute_1, technical_attribute_2, technical_attribute_3]) и пары «колонка — массив значений» (event_stage: [event_stage_1, event_stage_2, event_stage_3]). Топик конфигурации метрик, key tm.timeout-calc.metrics.%: в value рядом с metrics добавляется additionalFields; пример metrics: type VALUE, metricId 148, metricName «ф2», valueQuery «select 1», NORMAL (min null, max 3), CRITICAL (min 3, max null). ([US] Дополнительные поля в выч.атрибутах-31)
- bs_%_clickhouse_attributes: attribute_id 1110, attribute_name «DURATION_TIMEOUT: Длительность транзакции», attribute_status, attribute_threshold_type CRITICAL, insert_timestamp, transaction_attribute_value 0, transaction_events_count 6, transaction_time, transaction_type 1131, transaction_uuid + массивы event_stage, technical_attribute_1..3. bs_%_clickhouse_timeout_attributes: те же без threshold_type, плюс attribute_start_time, calculation_status, replacing_version (2). ([US] Дополнительные поля в выч.атрибутах-31)
- ClickHouse для метрик: default.bs_%_metric, колонки Array во всех нодах. ([8-[US] Дополнительные поля в метриках)
- OAS DEV: https://api-admin.oslb-dev01.corp.dev.vtb/swagger-ui/index.html#/ ([US] Дополнительные поля в выч.атрибутах-31)
- GET /api/checkpoints/attributes/{businessServiceId} (CheckpointController, getBusinessServiceAttributes): path businessServiceId integer обязательный; 200 массив FilteringAttributeDto; 400 ServerErrorDto «Некорректный запрос или отсутствие контрольной точки с переданным идентификатором»; 500 InternalServerError. ([US] Дополнительные поля в выч.атрибутах-31)
- POST /api/checkpoints/attributes/{bsId} (updateBusinessServiceAttributes): path bsId integer обязательный; тело — массив {key: integer, value: boolean}, пример [{key:1,value:true},{key:2,value:false}]; ответы 200 (массив FilteringAttributeDto), 400, 500 как у GET. ([US] Дополнительные поля в выч.атрибутах-31)

### Сценарии
- Основной: КМ «Черновик» → шаг «Вычисляемые атрибуты» → «+ Добавить поля для настройки фильтров» → выбор чекбоксами → «Сохранить» (чипсы, «Редактировать») → шаг «Сводка», «Поставить на мониторинг» или «Обновить карточку мониторинга». Предусловия: не менее двух КТ (источник, бизнес-атрибуты со связью с тех.атрибутами, ключевые идентификаторы в группах). ([US] Дополнительные поля в выч.атрибутах-31; 8-[US] Дополнительные поля в метриках)
- Метрики, критерий 1: ранее не добавленные поля сохранены → «Поставить на мониторинг» → в default.bs_%_metric во всех нодах добавлены колонки Array с наименованиями выбранных полей. Критерий 2: при изменении состава полей состав колонок меняется соответственно. ([8-[US] Дополнительные поля в метриках)

### Расхождения между документами
- Количество полей: выч.атрибуты — задаётся TM_FILTERING_ATTRIBUTE_MAX_COUNT (пример значения 6); метрики — критерий 1 «от 1 до 6 полей».
- Название блока: выч.атрибуты — «Поля для настройки фильтров в выч.атрибутах» (также «…в вычисляемых атрибутах и метриках» в разделе API); метрики — «Поля для настройки фильтров в вычисляемых атрибутах и метриках».
- Имена сервисов в выч.атрибутах: trmonbs-timeout-attributes-service / trmonbs-timeout-attribute-service и trmonbs-online-metric-service / trmonbs-online-metrics-service.
