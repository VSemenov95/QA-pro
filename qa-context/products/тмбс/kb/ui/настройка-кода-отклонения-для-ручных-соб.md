# Настройка кода отклонения для ручных событий мониторинга

> Настройка кода отклонения для ручных событий мониторинга: пометка ручного события как отклонения для внешних систем (текстовое поле в первой поставке, справочник кодов во второй).

### Описание
- Пользовательская история: «Я как Авторизованный Пользователь хочу промаркировать ручное событие мониторинга кодом отклонения для того, чтобы отметить отдельное ручное событие мониторинга как отклонение для внешних систем». Связанный документ: SA «ТМ. [СА] Настройка отклонений актуальная». (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- Первая поставка: PPMON-1651 «ТМБС. Отправка отклонений в сторонние системы ч1»; «Код отклонения» — текстовое поле. В БД: в monitoring_event добавить колонку «code_deviation» varchar(255); изменить контракты и DTO для GET /api/monitoring-event/{eventId}, PUT /api/monitoring-event/{eventId}, POST /api/monitoring-event (4.1.1). (23-[US] Настройка кода отклонения для ручных событий мониторинга; ТМ. [СА] Настройка отклонений актуальная-29)
- Вторая поставка: PPMON-1784 «ТМБС. Отправка отклонений в сторонние системы ч2»; «Код отклонения» — селект с предустановленными значениями (справочник) (4.2.2). (23-[US] Настройка кода отклонения для ручных событий мониторинга; ТМ. [СА] Настройка отклонений актуальная-29)
- Задачи: PPBP-2117 (интерфейс настройки отклонений в карточке события), PPBP-2344 (изменение механизма настройки отклонений + логика ручного события). ### Поля и элементы
- 1-я поставка: атрибут codeDeviation, «Код отклонения», string, макс. длина 255, M/O «-», Default «-», валидация «-»; текстовое поле. (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- 2-я поставка: атрибут codeDeviation.code, «Код отклонения», string, макс. длина 255, M/O «+» (обязательное), Default «-»; селект со справочными значениями. (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- Булев признак отклонения, Default false; тоггл отображается в карточках создания и редактирования, при нажатии становится активным и показывает селект «Код отклонения» (название тоггла и логика — см. расхождения). (23-[US] Настройка кода отклонения для ручных событий мониторинга; ТМ. [СА] Настройка отклонений актуальная-29)
- Информер у селекта, подсказка: «Ручное событие мониторинга будет являться отклонением для внешних систем». (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- Селект «Код отклонения»: по нажатию список справочных значений; поисковое поле (релевантные значения по запросу). (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- Чек-бокс «Код отклонения» в диалоге «Клонирование события мониторинга». Кнопки: «Создать событие мониторинга», «Создать», «Сохранить», «Клонировать событие мониторинга», «Клонировать». (23-[US] Настройка кода отклонения для ручных событий мониторинга)

- Валидация «Не заполненный атрибут «Код отклонения» при включенном тоггле»: если тоггл включён, а селект пуст, при «Сохранить»/«Создать» (сторона FE) — тост ошибки «Заполните все обязательные поля» И красная рамка поля + текст под полем «Поле обязательно для заполнения». (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- Ролевая модель применяется для UI и API. (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- Вторая поставка (БД): создать таблицу code_deviation по спецификации; в monitoring_event добавить колонку «code_deviation_id» (идентификатор кода отклонения). Миграция: перенести данные из колонки «code_deviation» monitoring_event в таблицу code_deviation; проставить связь в «code_deviation_id», где code_deviation.code_deviation = monitoring_event.code_deviation; удалить колонку «code_deviation» и её данные. (ТМ. [СА] Настройка отклонений актуальная-29)

### Сценарии
- 1-я поставка. 1.0: «Создать событие мониторинга» → карточка создания с текстовым полем «Код отклонения». 1.1: «Создать» с заполненными обязательными атрибутами → событие создано, карточка закрыта, вкладка «События мониторинга», событие в списке, тост «Событие мониторинга создано». 2.0: выбор ручного события → карточка редактирования с текстовым полем. 2.1: «Сохранить» (есть Разрешение 4) → событие сохранено, карточка закрыта, тост «Событие мониторинга обновлено». 3.0: «Клонировать событие мониторинга» → диалог с чек-боксом «Код отклонения». 3.1: чек-бокс активен + «Клонировать» → склонированная карточка редактирования с предзаполненным редактируемым полем. (23-[US] Настройка кода отклонения для ручных событий мониторинга)
- 2-я поставка. 4.0: карточка создания с тогглом. 4.1: нажатие тоггла → селект «Код отклонения», тоггл активен. 4.2: наведение на информер → текст подсказки. 4.3: нажатие на селект → список справочных значений. 4.5: ввод в поиск → релевантные значения. 4.6: выбор значения + «Создать» → событие создано, тост «Событие мониторинга создано». 5.0–5.3: карточка редактирования с тогглом и (при активном) селектом; подсказка, список, поиск как в 4.2/4.3/4.5. 5.4: выбор значения + «Сохранить» → тост «Событие мониторинга обновлено». 6.0: диалог клонирования с чек-боксом. 6.1: чек-бокс активен + «Клонировать» → склонированная карточка с предзаполненным редактируемым селектом. (23-[US] Настройка кода отклонения для ручных событий мониторинга)

### Расхождения между документами
- Название тоггла: US — «Является отклонением»; SA — «Отправлять отклонения».
- Логика тоггла и атрибут: US — булев признак без имени атрибута (Default false), положение тоггла зависит от codeDeviation.code (значение есть — вкл, null — выкл); SA — положение определяется атрибутом «deviation» из GET /api/monitoring-event/{eventId} ('true' — активен, 'false' — неактивен), в PUT/POST отправляется «deviation»: true.
