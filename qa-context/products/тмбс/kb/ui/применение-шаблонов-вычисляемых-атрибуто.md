# Применение шаблонов вычисляемых атрибутов в карточке мониторинга

> Функциональность создания вычисляемых атрибутов в карточке мониторинга из готовых шаблонов с управлением ими: редактирование порогов, дублирование, отвязка от шаблона и синхронизация с обновлённой версией шаблона.

### Описание
- Пользовательская история (статус «В работе»): «Я как Авторизованный Пользователь хочу создавать вычислительные атрибуты на основе готовых шаблонов, управлять ими (редактировать пороги, дублировать, отвязывать от шаблона, синхронизировать с обновлённой версией шаблона) для того, чтобы быстро настраивать типовые расчёты, избегая ручного копирования кода, и при этом иметь возможность кастомизировать критические пороги, а также обновлять атрибуты при изменении шаблона без потери ручных правок». (11-ТМ. Применение шаблонов вычисляемых атрибутов в карточке мониторинга)
- Работы в рамках спецификации: 1 Создание выч.атрибута из шаблона (1.0–1.9); 2 Редактирование (2.0–2.4); 3 Дублирование (3.0–3.1); 4 Отвязка от шаблона (4.0–4.2); 5 Синхронизация с шаблоном (5.0–5.8). (11-ТМ)
- История изменений: версия 1 от 08 апр. 2026, автор @Kalinina D.А., «Создана первая версия документа». (11-ТМ)
- Не заполнены: «Контекст», «Пользовательский путь», «Работы вне спецификации», «Допущения и ограничения», «Бизнес-правила», «Правила валидации», «Поиск и фильтрация», «Примечания для Dev/QA»; таблица атрибутов полей форм (13.1) пуста; ссылка на SA и ID разрешений не указаны. (11-ТМ)

- 2.1: вкладка «Правила вычисления» — все поля disabled. (11-ТМ)
- 2.2: вкладка «Код автоматического события» — если напротив порогов критичности включен хотя бы один параметр автогенерации события мониторинга, см. «Настройка автоматического события в карточке вычисляемого атрибута». (11-ТМ)
- 3.0: по кнопке клонирования появляется форма клонирования. 4.0: по «Отвязать от шаблона» — модальное окно. 5.2–5.4: при синхронизации — предупреждение, затем форма параметров. (11-ТМ)

### Поля и элементы
- Окно выбора: поиск по названию шаблона; выбор группы шаблонов; «Далее». (11-ТМ)
- Форма параметров: раздел «Общие переменные»; поля по типам; «Создать». (11-ТМ)
- Типы (1.5): Число → числовое поле; Строка → текстовое поле; Метка контрольной точки → селект КТметки; Массив чисел → ввод нескольких числовых значений; Массив строк (в источнике «Строка → поле ввода нескольких строковых значений») → ввод нескольких строковых значений; Метки контрольных точек → мультиселект КТметок. (11-ТМ)
- Форма редактирования: индикатор «Синхронизировано с шаблоном» (synced_with_template = true) или «Шаблон не синхронизирован» (false, шаблон изменён после создания/последней синхронизации); поле «Шаблон». (11-ТМ)
- Доступны для редактирования: «Название», «Статус», «Пороги критичности»; остальные (единицы измерения, методика расчета, класс, группы, метки, SQL‑скрипт и т.д.) disabled. (11-ТМ)
- Индикатор ручного изменения порогов (manual_threshold_override = true). (11-ТМ)
- Форма клонирования: изменение названия и выбор полей: Все, Тип атрибута, Класс, Единицы изменения, Группы, Описание, Методика расчета, Параметры критичности, Правила вычисления, Метки. (11-ТМ)
- «Отвязать от шаблона»; модальное окно: «Продолжить», «Отмена». (11-ТМ)
- «Синхронизировать» (неактивна при synced_with_template = true, активна при false); предупреждение: «Продолжить», «Отмена»; форма параметров: «Сохранить», «Отмена»; чекбокс «Синхронизировать пороги критичности» (по умолчанию false). (11-ТМ)
- Технические поля: template_id, synced_with_template, template_parameters_applied, manual_threshold_override. (11-ТМ)

### Бизнес-правила и ограничения
- 1.1: выбор группы шаблонов автоматически добавляет в выбор все шаблоны группы. (11-ТМ)
- 1.2: ввод в поиск обновляет список, показаны только подходящие шаблоны. (11-ТМ)
- 1.4: параметры с одинаковыми кодом, названием и типом в разных шаблонах выносятся в «Общие переменные» и заполняются один раз; только там; в списке по шаблонам они disabled со значением из общих; при разных дефолтных подставляется первое попавшееся. (11-ТМ)
- 1.6: заданное дефолтное значение предзаполняет поле. (11-ТМ)
- 1.7: если не все значения введены, «Создать» блокируется, поле подсвечивается ошибкой. (11-ТМ)
- 1.8: при повторяющихся названиях на форме ИЛИ совпадении с существующим выч.атрибутом — при «Создать» ошибка уникальности и возврат к форме параметров. (11-ТМ)
- 1.9: для каждого шаблона создаётся выч.атрибут в статусе «Подключено». (11-ТМ)
- 1.10: если шаблон уже применён в этой карточке — ошибка 400. (11-ТМ)
- 2.3: при изменении названия/статуса и «Сохранить» они обновляются, связь с шаблоном сохраняется. (11-ТМ)
- 2.4: при изменении порогов и «Сохранить» пороги сохраняются; manual_threshold_override = true (если отличаются от шаблонных), появляется индикатор; индикатор синхронизации остаётся «Синхронизировано» (если шаблон не менялся). (11-ТМ)
- 3.1: при подтверждении клонирования открывается форма создания нового атрибута с выбранными скопированными полями; «Название» дополняется суффиксом "КОПИЯ"; template_id не заполняется; все поля редактируемы; после сохранения — независимый атрибут без привязки. (11-ТМ)
- 4.1: «Продолжить»: template_id = NULL; synced_with_template = false; template_parameters_applied очищается; форма как у атрибута без шаблона, все поля редактируемы. 4.2: «Отмена» — возврат в исходное состояние, связь сохраняется. (11-ТМ)
- 5.0: synced_with_template = true — «Синхронизировано с шаблоном», кнопка неактивна. 5.1: false — «Шаблон не синхронизирован», кнопка активна. (11-ТМ)
- 5.3: после «Продолжить» система запрашивает у BE параметры шаблона (template_parameter) и сохранённые значения (template_parameters_applied), если есть. (11-ТМ)
- 5.4: отображаются все параметры обновлённого шаблона; существующие предзаполнены сохранёнными значениями (можно менять); новые пусты, если нет defaultValue, иначе предзаполнены им. (11-ТМ)
- 5.5: если не все значения введены, «Сохранить» блокируется, поле подсвечивается ошибкой. (11-ТМ)
- 5.6: при «Сохранить» поля обновляются по шаблону; пороги: чекбокс false — без изменений, true — перезаписываются из шаблона; SQL‑скрипт обновляется с подстановкой новых значений; новые значения сохраняются в template_parameters_applied. (11-ТМ)
- 5.7: после синхронизации «Синхронизировано с шаблоном», кнопка неактивна, поля обновлены. 5.8: «Отмена» — форма закрывается, сущность не меняется, статус «Шаблон не синхронизирован». (11-ТМ)

### API и интеграции
- 1.10: ошибка 400 при повторном применении шаблона в карточке. (11-ТМ)
- 5.3: запрос к BE за параметрами шаблона и сохранёнными значениями (метод/путь не указаны). (11-ТМ)

### Сообщения и ошибки
- 1.8: "Названия атрибутов должны быть уникальными". (11-ТМ)
- 1.9: "Атрибуты успешно добавлены". (11-ТМ)
- 1.10 (400): «Не удалось создать атрибуты: Шаблон уже применён в данной карточке мониторинга (templateId через запятую, если несколько не удалось создать)». (11-ТМ)
- 4.0: «Вы действительно хотите удалить связь с шаблоном? После отвязки все поля станут доступны для редактирования, но вы больше не сможете синхронизировать сущность с шаблоном.» Кнопки «Продолжить», «Отмена». (11-ТМ)
- 5.2: «Будут применены текущие настройки активного шаблона. Ранее изменённые вручную пороги критичности не будут перезаписаны. Если в шаблоне появились новые параметры, потребуется их заполнить». Кнопки «Продолжить», «Отмена». (11-ТМ)

### Роли и права
- Роль 1 — Администратор; ролевая модель применяется для UI и API; ID разрешений не указаны. (11-ТМ)

### Сценарии
- Создание: карточка → «Вычисляемые атрибуты» → «Создать из шаблона» → выбор шаблонов/группы, поиск → «Далее» → параметры → «Создать» → атрибуты «Подключено» и уведомление. (11-ТМ)
- Редактирование: открыть атрибут с template_id != NULL → изменить название/статус/пороги → «Сохранить». (11-ТМ)
- Дублирование: клонирование → выбор полей и названия → подтверждение → форма с суффиксом "КОПИЯ" → сохранение. (11-ТМ)
- Отвязка: «Отвязать от шаблона» → «Продолжить»/«Отмена». (11-ТМ)
- Синхронизация: «Синхронизировать» → предупреждение → «Продолжить» → форма параметров (+чекбокс порогов) → «Сохранить»/«Отмена». (11-ТМ)
