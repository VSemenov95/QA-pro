# Дебаг метрик и событий мониторинга (кнопка «Выполнить код»)

> Кнопка «Выполнить код» в формах кода метрики и события мониторинга позволяет проверить SQL-запрос и увидеть результат (до 100 строк) до сохранения, при наличии разрешения ppbp_metric_debug и включённой функции.

### Описание
- Пользовательская история: «Я как Пользователь системы. Хочу Иметь возможность выполнить и проврить код метрики и события мониторинга. Для того, чтобы Проверять корректность запроса». (11-[US] Дебаг метрик)
- Функционал аналогичен имеющемуся в «вычисляемых атрибутах»: пользователь может проверить запрос на корректность и увидеть результат его работы перед сохранением. (11-[US] Дебаг метрик)
- Код события мониторинга идентичен коду метрики в плане нового функционала (Форма 1. Код метрики). (11-[US] Дебаг метрик)
- Разделы «История изменений», «Открытые вопросы», «Связанные документы» не заполнены; таблица ознакомления содержит роли Аналитик, FE, BE, Тестирование, Дизайн (без дат и вопросов). (11-[US] Дебаг метрик)

### Экраны и навигация
- Путь: пользователь создал карточку мониторинга, дошёл до вкладки «Метрики», нажимает «Создать метрику», переходит на «Код метрики» и видит интерфейс дебага метрик. Для событий мониторинга — таб «Код событий мониторинга». (11-[US] Дебаг метрик)
- Макет Figma: https://www.figma.com/design/7wFx3vZPeDiIBMgdfnrOIV/Monitoring-card.-TRM-(Light)?node-id=1008-21693&t=G0nrKU6oNZq2KqdP-0 (11-[US] Дебаг метрик)

### Поля и элементы
- Кнопка «Выполнить код»: тип — кнопка; обязательное поле — нет; видна при наличии разрешения И включённой «ручки» в админ-сервисе. В тексте документа название встречается как «Выполнить код» и «Выполнить запрос». (11-[US] Дебаг метрик)
- «Результат запроса»: таблица, появляется после нажатия кнопки, если sql-запрос не содержит ошибок. Состоит из полей, выбранных в SELECT запроса; результаты выводятся в табличном виде. (11-[US] Дебаг метрик)
- «Оповещение»: закрывающееся окно; появляется, если результат содержит более 100 элементов. Текст: «Заголовок - Ответ по запросу включает более 100 значений. Текст - На интерфейс выведено 100 значений». (11-[US] Дебаг метрик)

### Бизнес-правила и ограничения
- При создании/редактировании метрики и события мониторинга пользователь может «выполнить код», нажав кнопку. Доступна при наличии разрешения ppbp_metric_debug. (11-[US] Дебаг метрик)
- Результат — не более 100 строк; при большем количестве выдаётся информационное окно, ниже расположены результаты запроса. (11-[US] Дебаг метрик)
- Для кнопки прорабатывается отдельное API. (11-[US] Дебаг метрик)
- Максимум 10 нажатий в минуту; затем ошибка «Превышено максимальное количество запросов. Пожалуйста, подождите», кнопка дизейблится. (11-[US] Дебаг метрик)
- Валидация SQL-запроса проходит на BE при каждом запуске. (11-[US] Дебаг метрик)
- В admin-сервисе можно выключить доработку целиком (кнопка «Выполнить» пропадает) — для соблюдения требования ИБ. (11-[US] Дебаг метрик)
- Системное отключение — через LENS, параметр tm.metric-service.debug.enabled = false. При выключенном функционале отображение такое же, как при отсутствии разрешения (кнопки «Выполнить код» нет). (11-[US] Дебаг метрик)
- Обработка ошибок — на уровне clickhouse; при некорректном запросе, по аналогии с дебагом вычисляемых атрибутов, на фронте отображается ошибка, выданная clickhouse. (11-[US] Дебаг метрик)
- Дополнительная валидация только на начало запроса: только SELECT, select и with. При некорректном запросе от бэка приходит ошибка 400. (11-[US] Дебаг метрик)
- Изменений в базах данных нет; доработки БД не требуются. (11-[US] Дебаг метрик)

### API и интеграции
- api/metric/debug — отправка запроса для валидации и отображения результата; по кнопке «Выполнить запрос». (11-[US] Дебаг метрик)
- api/metric/debug/enabled — проверка доступности функционала (включён ли в админ-сервисе); выполняется автоматически. (11-[US] Дебаг метрик)
- Логика: нажатие «Выполнить запрос» → api/metric/debug → admin-service → online-metric-service; результат возвращается на фронт табличными данными. (11-[US] Дебаг метрик)

### Сообщения и ошибки
- «Заголовок - Ответ по запросу включает более 100 значений. Текст - На интерфейс выведено 100 значений» (при >100 строк). (11-[US] Дебаг метрик)
- «Превышено максимальное количество запросов. Пожалуйста, подождите» (после 10 нажатий в минуту). (11-[US] Дебаг метрик)
- SQL-ошибка, выданная clickhouse, выводится вместо результата. (11-[US] Дебаг метрик)
- Ошибка 400 от бэка при запросе, не начинающемся с SELECT, select или with. (11-[US] Дебаг метрик)

### Роли и права
- Разрешение ppbp_metric_debug — пользователь должен состоять в группе с этим разрешением. (11-[US] Дебаг метрик)
- Без разрешения кнопки «Выполнить код» нет ни на «Код метрики», ни на «Код событий мониторинга». (11-[US] Дебаг метрик)

### Сценарии
- Критерий 1: карточка создана, вкладка «Метрики», есть разрешение, «Создать метрику», «Код метрики» → интерфейс дебага метрик. (11-[US] Дебаг метрик)
- Критерий 2 (после 1): валидный SQL, «Выполнить код» → значения в таблице «Результат запроса» (в таблицах должны лежать данные). (11-[US] Дебаг метрик)
- Критерий 3 (после 2): строк >100 → предупреждение (текст выше), ниже результаты. (11-[US] Дебаг метрик)
- Критерий 4 (после 1): невалидный SQL, «Выполнить код» → SQL-ошибка вместо результата. (11-[US] Дебаг метрик)
- Критерий 5 (после 1): таб «Код событий мониторинга», повтор критериев 2–4 → результат каждого события идентичен. (11-[US] Дебаг метрик)
- Критерии 6 и 7: нет разрешения, «Создать метрику», «Код метрики» / «Код событий мониторинга» → кнопки «Выполнить код» нет. (11-[US] Дебаг метрик)
- Основной сценарий. Пререквизиты: пользователь в группе с ppbp_metric_debug; карточка ранее стояла на мониторинге, данные по вычисляемым атрибутам есть в таблицах CH *attribute_distributed. Шаги: 1) вкладка «Метрики»; 2) «Код метрики»; 3) вставляет код метрики; 4) «Выполнить код»; 5) система делает запрос в online-metric-service; 6) выводит результат согласно введённым данным. (11-[US] Дебаг метрик)
- Альтернативный сценарий 1. Пользователь в группе с ppbp_metric_debug; создал карточку, добавил n контрольных точек, сгруппировал; вычисляемые атрибуты без данных в таблице (сервис не стоял на мониторинге). Шаги 1–5 те же, система выводит пустой результат запроса. (11-[US] Дебаг метрик)
- Альтернативный сценарий 2. Пользователь НЕ в группе с ppbp_metric_debug; карточка и атрибуты как в сценарии 1. Вкладка «Метрики», «Код метрики», вставляет код — кнопки «Выполнить код» нет. (11-[US] Дебаг метрик)
