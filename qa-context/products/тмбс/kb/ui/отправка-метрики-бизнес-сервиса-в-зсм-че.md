# Отправка метрики бизнес-сервиса в ЗСМ (чек-бокс «Выгружать в ЗСМ»)

> Чек-бокс «Выгружать в ЗСМ» у метрики БС задаёт атрибут exportToKafka, по которому рассчитанные метрики отправляются в Kafka-топик Сфера.Зонтичный мониторинг (ЗСМ).

### Описание
- Фича 1278 «ПП. ТМБС. Передача метрик цепочки сервисов из Сфера.Транзакционный мониторинг в Сфера.Зонтичный мониторинг»; задача PPBP-1721; US PPBP-1615 (критерии 1.0–1.4, 2.0). US: «Я как Авторизованный Пользователь. Хочу Иметь возможность отправлять метрику Бизнес-Сервиса. Для того, чтобы Метрика конфигурировалась в сторонней системе (ЗСМ)». (ТМ. Отправка метрики в ЗСМ-10; ТМ. [СА] Отправка метрики БС в ЗСМ-7)
- Статус СА-документа: «В работе»; ТЗ (SA) — «Готово». Тест-кейсы: PPBP-1020, 1055, 1056, 1058, 1059, 1060, 1061. (ТМ. Отправка метрики в ЗСМ-10; ТМ. [СА] Отправка метрики БС в ЗСМ-7)

### Экраны и навигация
- «Карточка мониторинга» (КМ), вкладка «Метрики»: таблица метрик БС с колонкой «Выгружать в ЗСМ» (значения: Да, Нет). Нажатие на метрику открывает карточку с вкладками «Общие настройки» (по умолчанию), «Код метрики», «Код событий мониторинга». После сохранения карточка закрывается, показывается КМ на вкладке «Метрики». (ТМ. Отправка метрики в ЗСМ-10)

### Поля и элементы
- Чек-бокс «Выгружать в ЗСМ» (заполнен/не заполнен) с иконкой «Подсказка»: «Выгрузка метрики в зонтичную систему Мониторинга»; кнопка «Сохранить». (ТМ. Отправка метрики в ЗСМ-10)
- exportToKafka: «Выгружать в ЗСМ», boolean, Default false, валидация «Не применимо». (ТМ. Отправка метрики в ЗСМ-10)

### Бизнес-правила и ограничения
- Изменение чек-бокса сохраняется только в статусе «Черновик»; в «Подключено», «Отключено в ручную», «На мониторинге» не сохраняется. Роли применяются для UI и API. (ТМ. Отправка метрики в ЗСМ-10)
- Метрика посчитана, если КМ и метрика в статусе «На мониторинге» и расчёт идёт через конфигурацию в trmonbs-metrics-calculator-service. Затем по конфигурации tm.bsmetrics.{bsId} проверяется export_to_kafka: «true» — отправлять в ЗСМ, «false» — не отправлять. (ТМ. [СА] Отправка метрики БС в ЗСМ-7)
- Данные выбираются динамически по таблице маппинга; нужны формирование сообщения в согласованном формате и отправка в топик Kafka. (ТМ. [СА] Отправка метрики БС в ЗСМ-7)
- В config_service.metric для всех записей автоматически проставить export_to_kafka = «false». (ТМ. [СА] Отправка метрики БС в ЗСМ-7)

### API и интеграции
- GET /api/metric/getMetricHeaders/{mcId} и GET /api/metric/{metricId}: в DTO добавить exportToKafka (по умолчанию «false»), статус «Изменяется». (ТМ. [СА] Отправка метрики БС в ЗСМ-7)
- Env trmonbs-metrics-calculator-service: MQ_KAFKA_EXPORT_TO_ZSM_BOOTSTRAP_SERVERS (по умолч. KAFKA_BOOTSTRAP_SERVERS), _TOPIC, _KEYSTORE_LOCATION (/opt/keystores/keystore.p12; по умолч. KEYSTORE_LOCATION), _KEYSTORE_PASSWORD (KEYSTORE_PASSWORD), _TRUSTSTORE_LOCATION (/opt/keystores/truststore.p12; TRUSTSTORE_LOCATION), _TRUSTSTORE_PASSWORD (TRUSTSTORE_PASSWORD); CONFIG_BS_METRIC_NAME=ppbp_service_chain; CONFIG_RIS_CODE=9998; CONFIG_SUB_RIS_CODE=0. (ТМ. [СА] Отправка метрики БС в ЗСМ-7)
- Маппинг: timestamp (metric_time, обяз.), ris_code int (CONFIG_RIS_CODE, обяз.), subsystem_code int (обяз.), metric_name (обяз.), metric_value int (обяз.), config_item (код ЦС, обяз.), labels: bsCode, bsName, bsCiId, bsId, chainName, chainId, chainCode, chainCiId (необяз.), metricName, metricId (обяз.); источник — tm.bsmetrics.{bsId}/результат запроса. (ТМ. [СА] Отправка метрики БС в ЗСМ-7)
- Модель: в config_service.metric колонка export_to_kafka. (ТМ. [СА] Отправка метрики БС в ЗСМ-7)
