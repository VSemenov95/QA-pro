# Фильтрация и обогащение контрольной точки: операторы сравнения, логические операторы и группы правил

> Вкладка «Фильтрация и обогащение» в конфигурации контрольной точки позволяет Администратору, Аналитику и Владельцу БС настраивать правила фильтрации из операторов сравнения, логических операторов «И»/«ИЛИ» и вложенных групп правил.

### Описание
- Пользовательская история: «Я как Администратор\Аналитик\Владелец БС хочу увидеть набор различных операторов и функций, для того чтобы настроить условия обогащения в конфигурации контрольной точки». Работы: 1) операторы сравнения (критерии 1.1-1.15); 2) дополнительное условие (2.1-2.2); 3) группа условий (3); 4) удаление условия или группы (4.1-4.2). Задача PPBP-1117 (Выполнено). Версии: 1 — 2023-10-11 создание; 2 — 2023-12-22 по итогам обсуждения с разработчиками; 3 — 2023-12-29 макеты; 4 — 2024-06-20 описание и валидация для MATCH (автор всех — Полоухина Мария). (US Новые операторы и функции в обогащении-50 — [US] Новые операторы и функции в обогащении-50)

### Поля и элементы
- «+ правило» добавляет селектор атрибута, селектор оператора и поле значения (если оператор его предполагает). Кнопки «+ правило»/«+ группа» появляются перед каждой группой; добавляют на следующем уровне вложенности. Кнопка-корзина удаляет правило или группу. Логический оператор («И», «ИЛИ») переключается нажатием. ([US] Новые операторы и функции в обогащении-50)
- Операторы сравнения (тип «Строка»):
  - `=` Равно; `!=` Неравно: поле значения, подсказка «Введите значение»; валидация: нет пробелов, непустое.
  - `<`, `>`, `<=`, `>=` (меньше, больше, меньше или равно, больше или равно): подсказка «Введите число или дату по шаблону записи (например: yyyy-MM-dd''T''HH:mm:ss.SSX)»; валидация: число либо дата формата 'yyyy-MM-dd''T''HH:mm:ss[.SSSSSSSSS][.SSSSSSSS][.SSSSSSS][.SSSSSS][.SSSSS][.SSSS][.SSS][.SS][.S][]X', 'Europe/Moscow'; непустое.
  - `LIKE` Соответствие шаблону с % и _; `NOT LIKE` Несоответствие: подсказка «Введите шаблон значения, используя символы % и _»; валидация: текстовый тип, наличие % или _ (% — любое число символов, _ — один), непустое.
  - `IN` Соответствие значению в списке; `NOT IN` Несоответствие: поле значений через запятую (chips), подсказка «Введите список значений, разделяя их запятыми»; валидация: список через запятую, элементы числовые или текстовые, список не пуст.
  - `IS NULL` Значение NULL; `IS NOT NULL` Значение NOT NULL; `IS EMPTY` Значение пустое или NULL; `IS NOT EMPTY` Значение не пустое и NOT NULL; `IS BLANK` пустое, NULL или содержит пробельные символы; `IS NOT BLANK` не пустое, NOT NULL и без пробельных символов — поле значения не требуется.
  - `MATCH` Соответствие регулярному выражению: подсказка «Введите регулярное выражение»; пояснение: «Регулярное выражение - это последовательность символов, определяющая поисковый шаблон. Его необходимо использовать для поиска значений, соответствующих определенным критериям. Регулярное выражение должно быть совместимо с Java-синтаксисом.»; примеры `^\d{4}-\d{2}-\d{2}$` (дата «ГГГГ-ММ-ДД»), `^ERROR.*$` (строки, начинающиеся с «ERROR»); валидация: непустое. ([US] Новые операторы и функции в обогащении-50)
- Логические операторы: «И» — a И b true, только когда оба true (Java `&&`); «ИЛИ» — true, когда хотя бы один true (Java `||`). ([US] Новые операторы и функции в обогащении-50)
- Примеры LIKE/NOT LIKE: `'abc%'` — начинается с «abc»; `'abc_'` — строго 4 символа, начало «abc»; `'%z'` — заканчивается на «z»; `'%Omsk%'` — содержит «Omsk»; `'% % %'` — не менее 2 пробелов, например «Hey Hey Hey»; `'%\_%'` — содержит «_» (экранирование); `'25\%'` — содержит «%» (экранирование); `'a__%'` — начинается с «a», длина не менее 3. ([US] Новые операторы и функции в обогащении-50)
- Информеры: «Обязательная контрольная точка»: «Укажите, является ли данная контрольная точка критически важной для транзакции. Если этот шаг не пройден, транзакция считается неуспешной»; «Объект мониторинга»: «Определите компонент или процесс, который подлежит мониторингу на данном этапе транзакции»; «Что мониторим»: «Опишите действие пользователя или событие системы, которое будет отслеживаться в рамках данной контрольной точки»; «Описание шага транзакции»: «Укажите, что происходит на данном этапе транзакции в рамках мониторинга бизнес-сервиса»; «Инструкция»: «Во вкладке «Фильтрация и обогащение» вы можете настроить фильтрацию потока данных из источника путем добавления правил фильтрации для данной контрольной точки. Правила и группы правил можно добавить с помощью кнопок «+ правило» и «+ группа». По умолчанию в группе правил выбрано значение оператора И, однако если на него нажать, оператор можно изменить. Доступные значения: И, ИЛИ. Добавление правила фильтра: 1. В раскрывающемся списке слева выберите технический атрибут, который вы хотите использовать для фильтрации. 2. В среднем раскрывающемся списке выберите нужный оператор. 3. Введите значение правила. В зависимости от выбранного оператора вам потребуется ввести значение в соответствующем формате, указанном в поле для ввода значения. Правило или группу правил можно удалить с помощью кнопки со знаком корзины.» ([US] Новые операторы и функции в обогащении-50)

### Бизнес-правила и ограничения
- В интерфейсе для условий используется синтаксис SQL. Правила объединяются группировкой; группа имеет наивысший приоритет вычисления; возможны несколько уровней вложенности; вложенные правила вычисляются от внутреннего к внешнему. ([US] Новые операторы и функции в обогащении-50)
- По умолчанию создается группа с одним правилом. При добавлении второго правила/вложенной группы по умолчанию «И»; можно сменить на «ИЛИ» нажатием. «+ группа» создает группу с одним условием на следующем уровне вложенности; её логический оператор присутствует, но не активен до добавления второго условия. ([US] Новые операторы и функции в обогащении-50)
- Для полей ввода значений нужна валидация; при недопустимом значении поле подсвечивается. При вводе значения предполагается, что значение атрибута ненулевое. ([US] Новые операторы и функции в обогащении-50)
- Маппинг SQL → Java: `=` — `equals()` (`message.equals(“Hello World”)`); `!=` — `!equals()`; `<`, `>`, `<=`, `>=` — операторы сравнения для чисел и дат (примеры `< 5`, `> 5`, `<= 5`, `>= 5`); валидация на бэке: число — строка преобразуется в число (пробелы убираются, запятые меняются на точки); формат даты — сравнивается дата; не удалось перевести — ошибка, валидация не пройдена; `LIKE` — перевод в регулярное выражение: `String pattern = “AB%”; pattern = pattern.replace("%", ".*"); pattern = "^" + pattern + "$"; Pattern compiledPattern = Pattern.compile(pattern); Matcher matcher = compiledPattern.matcher(message); boolean isLike = matcher.find();`; `NOT LIKE` — `boolean isNotLike = !matcher.find();`; `IN` — `List possibleValues = List.of(“Hello”, “World”); boolean isIn = possibleValues.contains(message);`; `NOT IN` — `boolean isNotIn = !possibleValues.contains(message);`; `IS NULL` — `message == null`; `IS NOT NULL` — `message != null`; `MATCH` — пользователь вводит строку с регулярным выражением; `IS EMPTY` — `isEmpty()`; `IS NOT EMPTY` — `isNotEmpty()`; `IS BLANK` — `isBlank()`; `IS NOT BLANK` — `isNotBlank()`. ([US] Новые операторы и функции в обогащении-50)
- Применение: при постановке на мониторинг, как в существующем процессе фильтрации и обогащения, в таблицу БС default.bs_%_event в Clickhouse попадают только события источника, соответствующие фильтрам контрольной точки. ([US] Новые операторы и функции в обогащении-50)
