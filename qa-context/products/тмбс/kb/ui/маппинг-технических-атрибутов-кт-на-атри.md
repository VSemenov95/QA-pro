# Маппинг технических атрибутов КТ на атрибуты поиска (колонка «Атрибут поиска»)

> Механизм сопоставления технических атрибутов источника данных в контрольной точке (КТ) с индексированными атрибутами поиска через колонку «Атрибут поиска» на вкладке «Атрибуты источника», чтобы находить транзакции через API поиска.

### Описание
- Пользовательская история: «Я как Авторизованный Пользователь хочу Сопоставить технический атрибут источника данных в рамках КТ с индексированными полями запроса поиска по атрибуту поиска, для того чтобы в последствии найти все транзакции по техническим атрибутам в рамках запроса по индексированным полям поиска». (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Задача документа: PPBP-1958 [Аналитика] ТМБС. Реализовать механизм маппинга полей запроса на атрибуты КТ. История: 13 мая 2026 (@Perekin D.С.) — первая версия; 27 мая 2026 (@Perekin D.С.) — доработка. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Связанные документы: Техническое решение (SA) — ссылка не указана; «Разрешения для КТ» (Контрольная точка); Спецификация на API 1 интеграции с енв переменными: POST /ext-api/v1/transactions-search. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Работы в рамках спецификации: 1) Просмотр маппинга тех. атрибута для запроса поиска в ИД (Критерии 1.0; PPBP-2162 [US] Реализовать интерфейс маппинга технических атрибутов КТ на атрибуты поиска и реализация интеграционного АПИ); 2) Редактирование маппинга (Критерии 2.0–2.4); 3) Автоматический сброс значения колонки «Атрибут поиска» при изменении списка атрибутов поиска в env переменной (Критерии 3.0); 4) Отображение карточки КТ без колонки «Атрибут поиска» (Критерии 4.0). Работы вне спецификации не указаны. Разделы «Контекст», «Пользовательский путь» пусты; бизнес-правила (п. 10) не указаны. (11-ТМ. Маппинг технических атрибутов на запрос поиска)

### Экраны и навигация
- Страница «Карточка мониторинга», раздел/вкладка «Объекты мониторинга». (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Страница выбранной КТ: подключённый Источник Данных (ИД) на вкладке «Атрибуты источника», таблица атрибутов ИД с учётом значений колонки «Атрибут поиска». (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Страница редактирования Карточки мониторинга (кнопка «Редактировать») на вкладке «Объекты мониторинга»; страница редактирования КТ с таблицей атрибутов ИД на вкладке «Атрибуты источника» с колонкой «Атрибут поиска». (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Прототипы: ссылки на макет; «Макет dev стенда»; «Макет с dev стенда». (11-ТМ. Маппинг технических атрибутов на запрос поиска)

### Поля и элементы
- Колонка «Атрибут поиска» в таблице «Атрибуты источника»: select с плейсхолдером «Не выбрано». (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Таблица 13.1: атрибут attributes.searchAttributeCode, название «Атрибут поиска», тип string, макс. длина —, обязательность (M/O) «+» (как указано в документе), default —; валидация: поле не обязательное, дополнительных валидаций со стороны FE не предусмотрено. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Кнопки: «Редактировать», «Сохранить». (11-ТМ. Маппинг технических атрибутов на запрос поиска)

### Бизнес-правила и ограничения
- Колонку «Атрибут поиска» отображать только для БС и КМ, указанных в енв переменной TM_INTEGRATION_REST_TRANSACTIONS_SEARCH_BS_LIST, получаемой по GET /api/config. Для остальных БС колонка отсутствует. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Справочные значения приходят в GET /api/dictionary/mappingSearchAttributes/. На FE маппинг по «attributes.searchAttributeCode» из GET /api/checkpoint/{checkpointId} и «code» из справочника для вывода человекочитаемых наименований. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- ВАЖНО: если маппинг не сработал (например, код ранее сохранённого атрибута удалён из енв переменной CONFIG_INTEGRATION_REST_SEARCH_ATTRIBUTES_LIST), на UI выводится плейсхолдер «Не выбрано». (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Валидация типа данных (13.2, «Формат типа данных технического атрибута не соответствует типу данных атрибута поиска при маппинге»): если замаплен атрибут поиска с типом «DATE», проверяется функция, на основании которой создан тех. атрибут: formatDate — валидация пройдена; иная функция (например getText) — ошибка. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- При ошибке валидации FE: выводит тост с ошибкой, удаляет выбранное значение селекта и ставит «Не выбрано». Проверка DTO — на стороне BE при создании и редактировании КТ. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Поиск и фильтрация (13.3): не предусмотрены. (11-ТМ. Маппинг технических атрибутов на запрос поиска)

### API и интеграции
- GET /api/config — список БС/КМ из TM_INTEGRATION_REST_TRANSACTIONS_SEARCH_BS_LIST. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- GET /api/dictionary/mappingSearchAttributes/ — значения колонки «Атрибут поиска». (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- GET /api/checkpoint/{checkpointId} — данные КТ, содержит attributes.searchAttributeCode. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- POST /ext-api/v1/transactions-search — API 1 интеграции. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Енв переменные: CONFIG_INTEGRATION_REST_SEARCH_ATTRIBUTES_LIST (список атрибутов поиска); CONFIG_INTEGRATION_REST_TRANSACTIONS_SEARCH_BS_LIST и TM_INTEGRATION_REST_TRANSACTIONS_SEARCH_BS_LIST — одинаковые по логике и наполнению, но с разными наименованиями: первая описана в классе бойлер темплейт, вторая в application.yaml для разделения функционала БС. (11-ТМ. Маппинг технических атрибутов на запрос поиска)

### Сообщения и ошибки
- Тост: заголовок «Ошибка», описание «Маппинг атрибута поиска на технический атрибут не соответствует типу данных » (при несоответствии типа данных). (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Плейсхолдер «Не выбрано» — при отсутствии сохранённого значения или несрабатывании маппинга. (11-ТМ. Маппинг технических атрибутов на запрос поиска)

### Открытые вопросы
- Превышение глубины поиска 31 день (это же енва и время хранения) для API 1 с учётом payDate (GTE) и payDate (LTE)? Ответ: проговорить с СУБО; отдавать данные, не превышая глубину поиска. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Что делать, если payDate не прислали? Ответ: глубина поиска. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Являются ли OffsetDateTime payDateFrom и payDateTO справочными значениями для маппинга? Ответ: являются. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Маппинг на атрибуты НЕ строкового типа? Ответ: решение для «DATE» в п. 13.2. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
- Хранение данных транзакций в Scylla? Ответ: ClickHouse. (11-ТМ. Маппинг технических атрибутов на запрос поиска)
