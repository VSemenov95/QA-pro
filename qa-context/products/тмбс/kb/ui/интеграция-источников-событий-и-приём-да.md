# Интеграция источников событий и приём данных о транзакциях

> Интеграция источников событий в ТМБС: администратор подключает источники данных бизнес-сервисов (Kafka, Ключ-Астром), настраивает предобработку и технические атрибуты, а продукт принимает и хранит события транзакций, контролируя ошибки в потоке.

### Описание
- Группа функций «Интеграция источников событий, коннекторы для приёма данных о транзакциях в шину данных»: продукт может принимать или забирать события продукта, входящих в БС, для последующей обработки. (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- Функции: 1.1 подключение к сторонним продуктам, источникам данных, для забора событий; 1.2 приём событий; 1.3 хранение принимаемых или получаемых событий; 1.4 контроль и выявление ошибок в потоке событий; 1.5 уведомление пользователя о выявленных ошибках. Цель: анализ в рамках мониторинга транзакций БС. (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- 5.3.3. Управление интеграцией источников осуществляется из раздела «Администрирование» – «Источники данных». Администратор может: 1) управлять продуктами источника; 2) добавлять примеры событий; 3) указывать типы источников и их параметры; 4) управлять предобработкой; 5) настраивать атрибуты источника. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Технические атрибуты — извлекаемые сущности, поля данных из событий продуктов в источнике; результат парсинга JSON-события; используются для управления полями источника, которые затем станут полями данных бизнес-сервиса. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Поля события мониторинга (окончание перечня): ci_name (идентификатор продукта), metric_name, metric_value, time_received (время поступления события в мониторинг). (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Управление доступами и ролями (5.3.2) — через приложение «Сфера: Доступы и роли». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Экраны и навигация
- Экран «Источники данных»: список с идентификатором источника в продукте, названием, ассоциированным продуктом, типом, бизнес-сервисом и статусом по статусной модели. Поиск по названию через элемент поиска и строку. «Создать источник данных» (роль Администратор) или выбор источника из списка; при создании — экран заполнения данных. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Вкладки источника: общая информация, параметры подключения, предварительная обработка, «Технические атрибуты», экран «Сводка» (5.3.3.5: ассоциированный продукт, описание и параметры, добавленные атрибуты). Страница конфигурации (5.3.3.6) — для редактирования. «Сохранить» — вверху справа. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Конструктор: «Источники данных» - «Создать источник данных» (задать название атрибута) - «Технические атрибуты» - «Создать атрибут»; также в режиме редактирования («Редактировать», справа вверху). Блоки: «Конструктор», «Результат выполнения кода», «Пример события». Боковое окно «Добавление функции» по «Добавить функцию». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Поля и элементы
- Общая информация: продукт из списка; описание (необязательное); пример события (просмотр и редактирование). (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Параметры подключения: тип (Kafka или Ключ-Астром), описание, адрес (bootstrap addres, input topic); «Проверить подключение» (только в режиме «Редактирования»). (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Вкладка «Технические атрибуты»: «+ Создать атрибут», «Добавить все атрибуты», «Пример события», чек-бокс «Дедупликация» (повторное сообщение с дублирующими значениями в выбранных атрибутах не учитывается; избегать полей со «временем»). (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Конструктор: «Добавить функцию», «Проверить код»/«Проверка кода» (в т.ч. с лупой в функции), «Сохранить», «Добавить»; функции отмечаются чекбоксами, при наведении — подсказка с названием и параметрами; стрелка вниз — параметры, «i» — описание. Параметры: «Json путь», «Json нода» (выбор из списка), «JsonNode аргумент»; подтверждение галочкой. Панель «Пример события»: «Вернуть в исходный JSON», «Действие назад», «Действие вперед», «Стереть полностью JSON». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Статус: «Черновик», «Подключено»; «Редактировать»; модальное окно: «Продолжить редактирование» / «Пересоздать черновик». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Бизнес-правила и ограничения
- Пример события используется для создания технических атрибутов; без него атрибуты создаются без примера. Несохранённые изменения не сохраняются автоматически — «Сохранить» (также на «Сводке»). Параметры подключения обязательны. Источник должен иметь минимум один технический атрибут. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Проверка подключения: результат не более чем через 10 секунд: успех — подтверждающее сообщение; не прошла валидация — предложение убедиться в соответствии значений правилам валидации; валидно, но соединение невозможно — сообщение с текстом ошибки. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Предварительная обработка (5.3.3.3): для массивов и подобных структур; варианты — с обогащением или без обогащения исходных событий; включение необязательно; результат используется как примеры событий в управлении атрибутами. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- «Добавить все атрибуты» (5.3.3.4.1): только для источников в статусе «Черновик»; формирует атрибуты из примера JSON; из массива — только последний элемент. Для примитива: функция getText; JSON-путь — полный путь; JSON-нода #message; название — полный путь; для массива путь содержит [-1]. Атрибуты с совпадающим JSON-путём не добавляются, прежние не изменяются, event_time не меняется. Если всё добавлено — «Все атрибуты уже добавлены». При успехе — уведомление со списком добавленных; при нарушении — ошибка у названия. Можно править вручную или удалять. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Таблица 5.3.3.4.1-1 «Правила валидации»: 1. Замена: автозамена на верхнем уровне (payload -> object), на других уровнях — список пуст. 2. snake_case: только a-z и _, символы преобразуются. 3. Нормализация: a-z, 0-9, _, прочие удаляются. 4. Первый символ — буква, иначе префикс attr_. 5. Запрещённые (префикс attr_): "registry_id", "transaction_uuid", "uuid", "source_timestamp", "insert_timestamp", "merge_timestamp", "event_source_id", "event_stage", "event_transaction_type". 6. Длина ≤ 128, иначе иконка ошибки. 7. Пустое имя — иконка ошибки. 8. Уникальность: {имя_атрибута}_n. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Конструктор (5.3.3.4.2) настраивает правила формирования технических атрибутов. Вложенные функции: после основной раскрыть параметры, заполнить «Json путь», «Json нода», «JsonNode аргумент», выбрать функцию — она становится дочерней; функции из справочника получают ID. При выборе другой функции в «JSON нода»/«JsonNode аргумент» новая становится дочерней, прежняя дочерняя выходит на верхний уровень. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- «Пример события» в конструкторе: изменённый JSON хранится локально в сессии, не попадает в «пример события» разделов «Общая информация» и «Технические атрибуты»; при некорректных данных — ошибка по строке кода. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Функции массивов (5.3.3.4.2.5): extractArray («JSON путь», «JSON нода»), summArray, avgArray, minArray, maxArray, countArray, arrayToString. В расчёт только числа; числа в строках парсятся в decimal, экспонента без потери точности; текст и null игнорируются; результат — строка. avgArray: точность до 38 знаков, математическое округление. countArray — количество не-null элементов. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### API и интеграции
- Взаимодействие через брокер сообщений (Apache Kafka); также через публичные программные интерфейсы (Rest API) других продуктов. (Сфера.ТМБС_Описание_продукта_PPBP-26.3.0-4)
- Типы источников в руководстве: Kafka, Ключ-Астром. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
