# Конструктор технических атрибутов

> Конструктор технических атрибутов позволяет собирать правила парсинга события источника данных из функций (в том числе вложенных и массивных), проверять результат на примере события и сохранять атрибут в источнике.

### Описание
- Пользовательская история: «Я как Администратор. Хочу иметь возможность настраивать правила формирования автоматической генерации технических атрибутов в конструкторе». Задачи: PPBP-1635, PPBP-1689, PPBP-2044 (функции по работе с массивами), PPBP-1629 (SA). (ТМ. Конструктор создания технических атрибутов в источнике данных-53; ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19)
- Редизайн: старый конструктор сложен для новичков. Результат пересчитывается автоматически после изменения примера события, виден результат вложенных функций, ошибки отображаются. Figma: node-id=1-43 и 1-40. (23-Конструктор технических атрибутов)
- formatDate некорректно работает с вложенными функциями, поэтому добавлена formatDateFunction (дефект PPBP-1788). (8-Функция formatDateFunction)
- Функции concat, case и const добавлены для корректной склейки транзакций. (\[US] Новые функции concat, case и const-7)
- История SA: v1 от 16.01.2026; v2 от 09.02.2026 после груминга: ренейминг «category.name» на «category.code», дополнена типизация для «returnType»: «STRING_AS_INTERNAL_FORMAT_DATE_TIME». Разделы E2E, модель данных, иные изменения, план миграции/релиза, риски не заполнены. (ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19)

### Экраны и навигация
- Сценарий: страница «Создание источника данных» → вкладка «Технические атрибуты» → «Создать атрибут» → окно «Создание технического атрибута» (предзаполнено «Новый технический атрибут»; кнопки «Отменить», «Создать») → страница создания/редактирования атрибута → «Сохранить». После сохранения открывается вкладка «Технические атрибуты» источника, атрибут виден в списке; изменённый пример события не сохраняется. (ТМ. Конструктор создания технических атрибутов в источнике данных-53; 23-Конструктор технических атрибутов; ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19)
- Вкладка «Технические атрибуты»: кнопки «Создать атрибут» и «Пример события» (шторка: «Редактировать», «Закрыть», «Сбросить до первоначального значения»). (23-Конструктор технических атрибутов)
- Клик по атрибуту в списке открывает его страницу; в примере события отображается неизменённый json (из «Общая информация», «технические атрибуты» или сплит массива). (ТМ. Конструктор создания технических атрибутов в источнике данных-53)
- «Добавить функцию» открывает шторку «Добавление функции» со списком по категориям, описанием, чек-боксом и кнопками «Добавить»/«Отменить»; единичный выбор. (ТМ. Конструктор создания технических атрибутов в источнике данных-53; 23-Конструктор технических атрибутов)
- «Отменить» в конструкторе возвращает на «Технические атрибуты» без сохранения. (23-Конструктор технических атрибутов)
- formatDateFunction: вкладка «Технические атрибуты», блок «Значение»: formatDateFunction(<список функции>(), <шаблон даты>, <временная зона>); после выбора вложенной (напр. coalesce) появляются поля JSON-путей аргументов. (8-Функция formatDateFunction)

### Поля и элементы
- Конструктор: «Развернуть функцию»; наименование функции; ID функции (сквозной, уникальный, не хранится на бэкенде); «Удалить» (при наведении; окно «Вы действительно хотите удалить функцию?», «Да»/«Отмена»); «Информация» (подсказка); «Выполнить» (без валидации); крестик сбрасывает значения; «Сохранить» значения; «Редактировать наименование» (валидация как у источника данных ТМ). (23-Конструктор технических атрибутов)
- Наименование поля берётся из api/functions/messageFunctions, parameters/description. Поле ввода обязательное: свободное (без валидации, максимум 255 символов) или выбор функции (есть поиск, сверху созданные и непривязанные). Введённое значение редактируется двойным нажатием. (23-Конструктор технических атрибутов)
- Пример события: «Редактировать», «Сбросить пример к исходному» (только в режиме редактирования), «Выход из режима редактирования». Результат: «Сбросить»; исходный текст «Для получения результата нажмите кнопку \"Выполнить\" в конструкторе функций». (23-Конструктор технических атрибутов)
- Поля функций: «JSON нода», «JsonNode аргумент», «Json путь», «Array нода»; селект функций; режим «Обработка JSON с массивом данных»; селект по событиям сплита массивов в «Пример события»; иконка очистки с подсказкой. (ТМ. Конструктор создания технических атрибутов в источнике данных-53; ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19)
- Описания разделов: «Для настройки тех. атрибута добавьте необходимые функции и настройте связи между ними. » (ТМ. Конструктор создания технических атрибутов в источнике данных-53)

### Бизнес-правила и ограничения
- Путь к объекту в JSON указывается с «$», например «$.qrcodeid». Для большинства функций выбирать #message; getCurrentTime без параметров. Рекомендуется coalesce вместо coalesceByTextValue (тот вычисляет все аргументы заранее). (6-Список функций в правилах обработки тех.атрибутов источника)
- В formatDateFunction значение #message работает некорректно, позже будет убрано из UI. Для coalesce нужно 4 аргумента (4 объекта в примере DTC). (8-Функция formatDateFunction)
- concat: при пустом атрибуте подставляется NULL, в варианте WS пустая строка; 2–10 аргументов. caseEqual: 1–10 пар, WHEN только равенство (=). const: одна string-константа. (\[US] Новые функции concat, case и const-7)
- Категории: Дата и время, Конкатенация данных, Условия сравнения, Текстовое значение, Проверка not null значений, Без категорий. Для parameters.type «stringFunction» — функции с «category.code»: «Date and time», «Data concatenation», «Comparing condition», «Text value», «Not null values check»; для «JsonNode» — «No category». Наименование категории — «category.description»; для «No category» в селекте не выводить. В селект добавляются уже созданные функции подходящего типа в формате {Наименование функции} {ID функции}, без сортировки. (ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19)
- Вынесение дочерней функции: при замене в селекте «JSON нода»/«JsonNode аргумент» новая функция становится дочерней, прежняя уходит на верхний уровень (8.2) или со всеми вложенными (8.3). (ТМ. Конструктор создания технических атрибутов в источнике данных-53; ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19)
- Массивы: extractArray при существующем пути к массиву, несуществующем пути и пути к не-массиву в блоке результата даёт ошибку 500: «Внутренняя ошибка сервиса». summArray: суммирует только числа (числа в строках парсятся в decimal, экспонента без потери точности, текст и null игнорируются), результат строкой; пустой массив — null; один элемент-число — это число строкой. avgArray: те же правила, точность до 38 знаков, математическое округление, строка; пустой — null. minArray/maxArray/countArray — те же правила включения. Предусловие 9.0: добавлена extractArray, заполнены «Json путь» и «Json нода». (ТМ. Конструктор создания технических атрибутов в источнике данных-53)
- Разрешение #1 и авторизация в SFERA обязательны. (ТМ. Конструктор создания технических атрибутов в источнике данных-53; 8-Функция formatDateFunction)

### API и интеграции
- GET /api/functions/messageFunctions: BE обогащает объект «category» для каждой функции (раздел 8.1). (ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19; 23-Конструктор технических атрибутов)
- POST /api/functions/splitMessage вызывается при переходе в «Технические атрибуты», если включён сплит массива. (ТМ. [СА] Конструктор создания технических атрибутов в источнике данных-19)
