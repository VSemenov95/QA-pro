# Принадлежность ручного события мониторинга к Сервису

> Возможность создавать, редактировать, отвязывать и клонировать принадлежность ручного события мониторинга к Сервису через необязательный селект «Сервис» в карточке мониторинга.

### Описание
- Пользовательская история: «Я как Авторизованный Пользователь. Хочу Иметь возможность создавать, редактировать и просматривать принадлежность ручного события мониторинга к Сервису. Для того, чтобы Вычислять ручные события мониторинга на основании принадлежности к конкретному Сервису». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Работы в рамках спецификации (задача PPBP-2530 [US] Доработка 4-го варианта реализации): создание принадлежности при создании (КП 1.0–1.4); при редактировании (КП 2.0–2.4); удаление принадлежности (КП 3.0–3.2); подсказка для селекта «Сервис» (КП 4.0); клонирование с привязкой к сервису (КП 5.0–5.2); поиск в селекте «Сервис» (КП 6.0–6.1). (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- История изменений: версия 1, 24 авг. 2026, автор @Perekin D.С., задача PPBP-2528 [Аналитика] ТМБС. Подготовка артефактов для 4 варианта реализации, «Создана первая версия документа». Связанные документы: Техническое решение (SA) — Готово. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Разделы «Контекст», «Пользовательский путь», «Работы вне спецификации», допущения и ограничения, бизнес-правила, примечания для Dev/QA не заполнены. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)

### Экраны и навигация
- Страница «Карточка мониторинга», вкладка «События мониторинга»: кнопка «Создать событие мониторинга» открывает форму «Создания события мониторинга». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- На странице «Карточки мониторинга» в разделе «События мониторинга» при нажатии на ручное событие в списке открывается форма «Редактирования ручного события мониторинга». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- После успешного сохранения (создание, редактирование, отвязка) форма закрывается и отображается страница «Карточки мониторинга» в разделе «События мониторинга». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Диалог «Клонирование события мониторинга» открывается кнопкой клонирования на форме «Карточка ручного события мониторинга»; после клонирования отображается форма «Карточка создания ручного события мониторинга». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)

### Поля и элементы
- Селект «Сервис» в формах создания и редактирования ручного события; плейсхолдер «Выбрать из списка». Обязательность — Нет. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Дропдаун показывает Сервисы в рамках цепочки сервисов; для каждого — «Наименование Сервиса» и «Код Сервиса». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Значение после выбора: при создании (КП 1.2) — «Наименование Сервиса»; при редактировании (КП 2.2) — «Наименование Сервиса» и «ID Сервиса (внутренний ТМБС)». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Крестик в селекте сбрасывает значение; отображается пустой селект с плейсхолдером «Выберать из списка» (так в документе). (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Подсказка у элемента рядом с полем «Сервис» (при наведении): «Принадлежность события мониторинга к Сервису». Макета нет. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Диалог «Клонирование события мониторинга»: текстовое поле «Название»; чек-боксы «Все», «Описание», «Метки», «Рассчитывать по», «Группа оповещений», «Шаблон ссылки надашборд» (так в документе), «Частота запроса», «Выгружать в ЗСМ», «Код события мониторинга», «Код отклонения», «Сервис». По умолчанию все true. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Таблица атрибутов (13.1): селект — name, «Наименование сервиса», string, select, макс. длина «В рамках ширины селекта», обязательность Нет, default «-», валидация «-». Список селекта — name, «Наименование сервиса», string, select, «В рамках ширины списка селекта», Нет, «-», «-»; code, «Код сервиса», string, select, «В рамках ширины списка селекта», Нет, «-», «-». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Поиск и фильтрация (13.3): не заполнено. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)

### Бизнес-правила и ограничения
- Ролевая модель применяется для UI и API; пользователь авторизован по списку ролей системы. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Сохранение при создании: система валидирует данные, проверяет права доступа на объект «Сервис», сохраняет новое ручное событие с принадлежностью. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Сохранение при редактировании и отвязке: валидация данных DTO, на бэке проверка прав на объект «Сервис», сохранение события (с принадлежностью или без). (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Отвязка: после сброса крестиком и «Сохранить» событие сохраняется без принадлежности к Сервису. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Клонирование (КП 5.1): если «Сервис» был заполнен, событие клонируется со всеми атрибутами, включая «Сервис», в форме «Карточка создания ручного события мониторинга» поле заполнено. (КП 5.2): если не заполнено — клонируется без привязки, поле пустое с плейсхолдером «Выбрать из списка». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Поиск в селекте выполняется на FE по «Код сервиса» и «Наименование сервиса»; релевантные значения отображаются; нет совпадений — пустой список. Макетов нет. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Валидация «Пустой список селекта «Сервис»»: права проверяются на BE; при запросе GET /api/service/header без Разрешения 1 — статус 403; на FE пустой список; ошибка-тост при раскрытии не предусмотрена. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)

### API и интеграции
- GET /api/service/header — запрос списка Сервисов для селекта; без Разрешения 1 — 403. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- При сохранении (создание, редактирование, отвязка) без Разрешения 1 — 403, событие не создаётся/не обновляется. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)

### Сообщения и ошибки
- Успех создания: тост «Событие мониторинга создано». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Успех редактирования и отвязки: тост «Событие мониторинга обновлено». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Неудача создания (403, нет Разрешения 1): тост, заголовок «Ошибка», описание «Не удалось создать событие. {$"errorMessage"}». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Неудача редактирования и отвязки (403, нет Разрешения 1): заголовок «Ошибка», описание «Не удалось обновить событие. {$"errorMessage"}». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- При раскрытии пустого списка из-за отсутствия прав ошибка-тост не показывается. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)

### Роли и права
- Роль 1: Администратор. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- Разрешение 1: PPBP_SERVICE_CHANGE_LINK (ID: «-») — нужно для отображения списка Сервисов в дропдауне (КП 1.1) и для сохранения привязки/отвязки. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)

### Сценарии
- 1.0 Если пользователь авторизован в SFERA, есть Роль 1, на вкладке «События мониторинга» страницы «Карточка мониторинга»; когда нажимает «Создать событие мониторинга» — отображается форма «Создания события мониторинга» с селектом «Сервис» и плейсхолдером «Выбрать из списка». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 1.1 При наличии Разрешения 1 нажатие на селект показывает список Сервисов в рамках цепочки с «Наименование Сервиса» и «Код Сервиса». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 1.2 Выбор Сервиса закрывает дропдаун и показывает «Наименование Сервиса». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 1.3 После заполнения обязательных полей и «Сохранить»: валидация, проверка прав на «Сервис», сохранение с принадлежностью, закрытие формы «Создание ручного события мониторинга», страница «Карточки мониторинга» в разделе «События мониторинга», тост «Событие мониторинга создано», событие в таблице. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 1.4 Нехватка прав (403, нет Разрешения 1): событие не создаётся, тост «Не удалось создать событие. {$"errorMessage"}». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 2.0 Нажатие на ручное событие в списке открывает форму «Редактирования ручного события мониторинга» с селектом «Сервис» и плейсхолдером. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 2.1 Дропдаун: список Сервисов с «Наименование Сервиса» и «Код сервиса». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 2.2 Выбор: дропдаун закрывается, селект показывает «Наименование Сервиса» и «ID Сервиса (внутренний ТМБС)». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 2.3 «Сохранить»: валидация DTO, проверка прав на бэке, сохранение с принадлежностью, закрытие формы «Редактирование ручного события мониторинга», страница «Карточки мониторинга» в «События мониторинга», тост «Событие мониторинга обновлено». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 2.4 Нехватка прав (403): не обновляется, тост «Не удалось обновить событие. {$"errorMessage"}». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 3.0 После КП 1.3 или 2.3 в открытой форме редактирования крестик в селекте сбрасывает значение, отображается пустой селект с плейсхолдером. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 3.1 «Сохранить»: валидация DTO, проверка прав, сохранение без принадлежности, закрытие формы, страница «Карточки мониторинга» в «События мониторинга», тост «Событие мониторинга обновлено». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 3.2 Нехватка прав (403): не обновляется, тост «Не удалось обновить событие. {$"errorMessage"}». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 4.0 На форме карточки ручного события при наведении на элемент рядом с полем «Сервис» — подсказка «Принадлежность события мониторинга к Сервису». (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 5.0 Кнопка клонирования на форме «Карточка ручного события мониторинга» открывает диалог «Клонирование события мониторинга» (все чек-боксы true). 5.1 и 5.2 — см. бизнес-правила. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
- 6.0 При КП 1.1 или 2.1 ввод в поле поиска: FE ищет по «Код сервиса» и «Наименование сервиса», отображает релевантные значения. 6.1 Нет совпадений — пустой список. (_ТМ. Принадлежность ручного события мониторинга к Сервису-3)
