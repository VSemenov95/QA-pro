# Проверка соединения для источника данных (кнопка «Проверить соединение»)

> Кнопка «Проверить соединение» на вкладке «Параметры подключения» источника данных типа Kafka позволяет администратору проверить корректность параметров подключения при создании или редактировании источника, не дожидаясь постановки карточки на мониторинг.

### Описание
- Пользовательская история PPMON-495 «ПП. Транзакционный мониторинг БС. Проверка соединения для источника данных в пользовательском интерфейсе», статус «В работе». Я как Администратор хочу иметь возможность проверить соединение с источником данных при его создании или редактировании, чтобы убедиться в корректности введенных параметров подключения еще на этапе настройки конфигурации. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Контекст: сейчас соединение с источником устанавливается в момент постановки на мониторинг карточки, к которой привязан источник, поэтому некорректность параметров выявляется только на этом этапе. Нужна предварительная проверка при создании или редактировании источника. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- История изменений: версия 1 (2024-03-21, Полоухина Мария) — создание документа; версия 2 (2024-07-19, Полоухина Мария) — добавлены разрешения, обновлено описание ошибок, добавлен п. 7 в раздел 5.1. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)

### Экраны и навигация
- Вкладка «Параметры подключения» страницы конфигурации источника, режим редактирования, тип источника «Kafka». ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Формы: Форма 1 «Вкладка «Параметры подключения» для типа источника Kafka»; Форма 2 «Проверка подключения»; Форма 3 «Уведомление пользователя о результатах проверки». Макеты Figma: https://www.figma.com/design/7wFx3vZPeDiIBMgdfnrOIV/Monitoring-card.-TRM-(Light)?node-id=1202-72580&t=3VQ5sOfxGDs0Pk4p-0 ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Во время проверки перейти на другую вкладку невозможно; после получения результата возможность перехода возвращается. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)

### Поля и элементы
- Кнопка «Проверить соединение»: тип — кнопка; обязательное поле — «-»; редактируемое поле — «-»; отображается только при выборе типа источника Kafka; сообщения об ошибке — см. п. 5.3.2. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- В режиме просмотра кнопки для проверки соединения нет. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- На время проверки на кнопке «Проверить подключение» отображается лоадер, все поля недоступны для ввода и изменения значений. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Поле inputtopic: редактируемость соответствует паттерну создания ([US] Создание источника данных) или редактирования ([US] Редактирование источника данных). При создании (не было версии источника в статусе «Подключен») поле доступно для редактирования; при редактировании (прежняя версия доведена до статуса «Подключен») недоступно. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)

### Бизнес-правила и ограничения
- БТ 1: система должна предоставлять функциональность проверки корректности параметров подключения к источнику данных; проверка доступна на этапе создания или редактирования источника. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- БТ 2: в интерфейсе создания и редактирования источника должна быть кнопка проверки корректности соединения. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- БТ 3: при нажатии на кнопку появляется сообщение с результатом: при успехе — подтверждающее, при проблеме с параметрами — информативное сообщение об ошибке, помогающее понять проблему. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- БТ 4: проверка выполняется тем же способом, что и при реальной работе системы; успешная проверка гарантирует, что настройки будут работать и в реальных условиях. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Допущение 1: проверить соединение можно, если источник или его новая версия находится в статусе «Черновик». ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Допущение 2: проверка возможна только в режиме редактирования. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Допущение 3: при нажатии происходит валидация полей параметров подключения; правила описаны в [US] Создание источника данных. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Допущение 4: в первой итерации кнопка доступна только для типа Kafka; в последующих итерациях будет реализована проверка для типа источника Ключ-АСТРОМ. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Допущение 5: для тестового соединения с Kafka для микросервиса trmon-event-collector-kafka установить таймаут 10 секунд. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Допущение 6: при ошибке соединения текст ошибки отображается пользователю в UI (п. 5.3.2). Допущение 7: см. описание поля inputtopic. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Требования к системе (6.1): не заполнены («-»). ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)

### Сообщения и ошибки
- Успешное соединение — «Проверка соединения прошла успешно. Соединение установлено.» ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Несоответствие правилам валидации — «Невозможно проверить соединение. Введённые значения не соответствуют правилам. Пожалуйста, проверьте правильность введённых параметров подключения и попробуйте снова.» ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Соответствие правилам валидации, но соединение не установлено — «Ошибка. Не удалось установить соединение с источником. <Текст ошибки>». Для Kafka: «Ошибка. Не удалось установить соединение с источником. Брокер не найден.»; «Ошибка. Не удалось установить соединение с источником. Не удалось подключиться к брокеру.»; «Ошибка. Не удалось установить соединение с источником. Топик отсутствует.» ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Истечение времени ожидания при установлении HTTP соединения между FE и BE — «Ошибка. Не удалось проверить соединение. Превышено время ожидания ответа. Пожалуйста, попробуйте снова» ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)

### Сценарии
- Критерий приемки 1: ЕСЛИ пользователь авторизован в SFERA И находится на странице конфигурации источника во вкладке «Параметры подключения» в режиме редактирования И тип источника «Kafka», КОГДА вводит параметры подключения, ТОГДА видит введенные параметры И кнопку «Проверить соединение». ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
- Критерий приемки 2: ЕСЛИ критерий 1 выполнен, КОГДА пользователь нажимает «Проверить соединение», ТОГДА: на кнопке «Проверить подключение» лоадер; все поля недоступны для ввода/изменения; переход на другую вкладку невозможен; по истечении не более 10 секунд отображается сообщение с результатом: а) успех — подтверждающее сообщение; б) несоответствие правилам валидации — сообщение с предложением убедиться в соответствии значений правилам; в) соответствие правилам, но соединение не установлено — сообщение с текстом ошибки. После этого поля снова доступны, переход на другую вкладку возможен. ([US] Проверка соединения для источника данных в пользовательском интерфейсе-16)
