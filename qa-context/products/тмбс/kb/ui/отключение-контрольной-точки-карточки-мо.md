# Отключение контрольной точки карточки мониторинга (статус «Отключено вручную»)

> Возможность вручную отключить контрольную точку (КТ) в карточке мониторинга новым статусом «Отключено вручную» (DISCONNECTED_MANUAL), чтобы данные её источника не попадали в события БС, и затем включить её обратно.

### Описание
- Пользовательская история: «Я как Пользователь системы Хочу Отключить контрольную точку Для того, чтобы Данные источника не попадали в события БС так как на текущий момент не актуальны». Пользователю периодически нужно отключать КТ в карточке мониторинга, а позже включить её, чтобы она была поставлена на мониторинг. Включение и выключение КТ нужно для остановки потока данных в систему. (17-Отключение контрольной точки карточки мониторинга)
- Ситуации отключения: 1) отключение источника, генерирующего ошибочные данные; 2) неготовность КТ к постановке на мониторинг из-за проблем с интеграцией данных, административных проблем или других факторов. (17-Отключение контрольной точки карточки мониторинга)
- Бизнес-требования: 1) отключить КТ, ранее поставленную на мониторинг; 2) включить ранее отключённую КТ; 3) отредактировать ранее отключённую КТ и провести по статусной модели КТ; 4) отключить КТ, созданную, но не поставленную на мониторинг. (17-Отключение контрольной точки карточки мониторинга)
- История изменений: «Создание документа»; версия от 2024-12-20 (Климов Александр): статус DISCONNECTEDMANUAL -> DISCONNECTED_MANUAL; исправлена ошибка в имени разрешения PPBP_CHECKPOINT_STATUS_CHANGE_FROM_CONNECTED_ _TO DISCONNECTEDMANUAL. (17-Отключение контрольной точки карточки мониторинга)

### Экраны и навигация
- Формы UI не изменяются. Новый статус «Отключено вручную» появляется на UI после добавления со стороны BE. (17-Отключение контрольной точки карточки мониторинга)
- Путь: пользователь открывает карточку мониторинга и нужную КТ; если карточка ранее была поставлена на мониторинг — создаёт новую версию карточки, если нет — открывает черновик. Кнопки/функции: «Поставить на мониторинг», «Снять с мониторинга». (17-Отключение контрольной точки карточки мониторинга)

### Поля и элементы
- Статус КТ: новое значение «Отключено вручную» (DISCONNECTED_MANUAL). (17-Отключение контрольной точки карточки мониторинга)
- Статусы КТ и переходы:
  - Черновик: начальный статус при создании; редактирование атрибутов КТ. Переход: Подключено, Отключено вручную.
  - Подключено: готовность к постановке на мониторинг; изменение атрибутов невозможно. Переход: На мониторинге (автоматически при постановке карточки на мониторинг), Отключено вручную.
  - Отключено: проставляется автоматически при снятии карточки с мониторинга («Снять с мониторинга»); пользователь установить его иначе не может. Переход: На мониторинге (автоматически при постановке карточки).
  - Отключено вручную: сбор событий из источников данных, привязанных к КТ, не происходит; данные не собираются и не записываются в таблицы бизнес-сервиса. Переход: Черновик, Подключено.
  - На мониторинге: КТ на мониторинге, данные собираются и записываются; ставится автоматически при постановке карточки. Переход: Подключено (при создании новой версии карточки), Отключено (при отключении карточки). (17-Отключение контрольной точки карточки мониторинга)

### Бизнес-правила и ограничения
- Два статуса выключения: «Отключено» — вместе с карточкой мониторинга, автоматически; «Отключено вручную» — отключение КТ пользователем. (17-Отключение контрольной точки карточки мониторинга)
- «Отключено вручную» можно установить только из «Черновик», «Подключено». (17-Отключение контрольной точки карточки мониторинга)
- При отключении, включении или постановке на мониторинг карточки КТ в «Отключено вручную» статус не меняется (не становится «Отключено» или «На мониторинге»). (17-Отключение контрольной точки карточки мониторинга)
- Для отключённой КТ данные могут поступать, если находятся в темах Kafka: приём и обработка в БД идут до полной вычитки, затем новые данные не поступают. (17-Отключение контрольной точки карточки мониторинга)
- Система не собирает данные по такой КТ и не пишет их в таблицы бизнес-сервиса (Scylla, Clickhouse); ранее сохранённые данные по КТ не должны быть потеряны. В config_service.configuration нет записей конфигурации по КТ (привязанному источнику). Остальные КТ «На мониторинге» работают штатно. (17-Отключение контрольной точки карточки мониторинга)
- Включение: по статусной модели Отключено вручную -> Подключено -> На мониторинге КТ ставится на мониторинг, события источника поступают в таблицы БС, в config_service.configuration появляются записи конфигурации по КТ. Если источник КТ используется в других КТ этого или других БС, его конфигурация (trmonbs-collector-service) не затрагивается, события собираются по настройкам КТ других БС. Изменения конфигурации затрагивают только отключаемую КТ БС: trmonbs-enrichment-service и trmonbs-merging-service. (17-Отключение контрольной точки карточки мониторинга)

### API и интеграции
- trmonbs-admin-service: новая статусная модель КТ; изменена логика валидации статусов КТ и генерации конфигурации. Остальные компоненты — только ссылки. (17-Отключение контрольной точки карточки мониторинга)
- ClickHouse (данные не пишутся): bs_ _event{%}, bs_ _event_distributed{%}, bs_ _event_mv{%}, bs_ _event_queue{%}; {%} — идентификатор БС, имя КТ равно значению поля event_stage. Scylla: bs_{%}_event_id_to_message. (17-Отключение контрольной точки карточки мониторинга)
- PostgreSQL: в config_service.checkpoint статус DISCONNECTED_MANUAL; в config_service.configuration для application = trmonbs-enrichment-service и key = tm.enrichment.config.{%} в поле value нет записей по отключённой КТ ({%} — идентификатор БС). (17-Отключение контрольной точки карточки мониторинга)
- Необходимые доработки: 1) добавить «Отключено вручную» (DISCONNECTED_MANUAL) в словарь статусов: GET https://trmonbs-admin-service.ppmon.dev.sfera-t1.ru/swagger-ui/index.html#/DictionaryController; проверка: SELECT UNNEST(enum_range(null::cp_status)) AS cp_status; 2) доработать алгоритм изменения и проверки статуса: в «Отключено вручную» только из Черновик, Подключена; из него только в Черновик, Подключена; 3) доработать регенерацию конфигурации микросервисов, исключить поступление данных по отключённой КТ в бизнес-сервис на мониторинге (согласно п.6 н.д.); 4) добавить разрешения и назначить пользователю «Администратор системы». (17-Отключение контрольной точки карточки мониторинга)

### Роли и права
- Администратору системы (список «Контрольная точка»): PPBP_CHECKPOINT_STATUS_CHANGE_FROM_DRAFT_TO_DISCONNECTEDMANUAL (Черновик → Отключено вручную); PPBP_CHECKPOINT_STATUS_CHANGE_FROM_CONNECTED_TO_DISCONNECTEDMANUAL (Подключена → Отключено вручную); PPBP_CHECKPOINT_STATUS_CHANGE_FROM_DISCONNECTEDMANUAL_TO_DRAFT (→ Черновик); PPBP_CHECKPOINT_STATUS_CHANGE_FROM_DISCONNECTEDMANUAL_TO_CONNECTED (→ Подключена). (17-Отключение контрольной точки карточки мониторинга)

### Сценарии
- 1.1 Перевод в «Отключено вручную»: пользователь создал новую версию карточки ИЛИ открыл черновик, открыл КТ со статусом Черновик ИЛИ Подключено, изменил статус на «Отключено вручную», сохранил — видит «Отключено вручную». (17-Отключение контрольной точки карточки мониторинга)
- 2.1 Перевод из «Отключено вручную»: открыл черновик карточки, видит «Отключено вручную», изменил на «Черновик» ИЛИ «Подключено», сохранил — видит выбранный статус. (17-Отключение контрольной точки карточки мониторинга)
- 3.1 Постановка на мониторинг («Поставить на мониторинг») — КТ остаётся «Отключено вручную». 4.1 Снятие с мониторинга («Снять с мониторинга») — КТ остаётся «Отключено вручную». (17-Отключение контрольной точки карточки мониторинга)
- Отключение: открыть карточку и КТ; новая версия (если была на мониторинге) или черновик; статус «Отключено вручную»; «Поставить на мониторинг» — статус не меняется, данные не собираются и не пишутся в Scylla, Clickhouse, записей в config_service.configuration нет, остальные КТ работают штатно. (17-Отключение контрольной точки карточки мониторинга)
- Включение: открыть карточку и КТ; создать новую версию; без изменений — «Отключено вручную» → «Подключено», при необходимости изменений — → «Черновик», правки, → «Подключено»; поставить на мониторинг — «Подключено» автоматически становится «На мониторинге», данные поступают в таблицы БС, появляются записи в config_service.configuration. (17-Отключение контрольной точки карточки мониторинга)
- Описан только положительный сценарий. (17-Отключение контрольной точки карточки мониторинга)
