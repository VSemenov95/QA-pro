# Администрирование источников данных: версии, клонирование, статусы, конкурентное редактирование

> Администрирование источников данных в ТМБС: версии источника, клонирование с выбором копируемых полей, смена статуса и конкурентное редактирование несколькими пользователями.

### Описание
- Пользовательская история: «Я как Пользователь системы. Хочу Клонировать источник. Для того, чтобы Облегчить и ускорить процесс создания источника». (3-Клонирование источника данных)
- Клонирование ускоряет создание источника, предзаполняя его нужной информацией заранее. (3-Клонирование источника данных)
- Конкурентное редактирование позволяет нескольким пользователям вносить изменения в источник без риска потери данных или случайной перезаписи изменений друг друга. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- История изменений клонирования: версия 1, 07.07.25, автор Лазарев Никита, «Создание». Раздел «Открытые вопросы» в документе пуст. (3-Клонирование источника данных)

### Экраны и навигация
- Версии: рисунок 5.3.3.6-3 – Пересоздание черновика; рисунок 5.3.3.6-4 – Статус «Подключен». В режиме просмотра видна новая версия источника в статусе «Подключен». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Кнопка клонирования находится рядом с кнопкой «редактирования» источника; открывается окно клонирования (рисунок 5.3.3.7-1), где выбирается, какие элементы клонировать. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Клонирование запускается кнопкой в окне просмотра. По «Клонировать» появляется диалоговое окно с выбором полей. После выбора полей и нажатия «Клонировать» открывается окно создания источника в статусе «Черновик» со скопированными выбранными полями; доступны «Сохранить» и «Отмена». (3-Клонирование источника данных; Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Диалоговое окно на момент написания документа не отрисовано; наполнение смотри в пункте 4.3.3 (так указано в документе). (3-Клонирование источника данных)
- Просмотр ранних версий: в режиме просмотра источника нажать на раскрывающийся список версий. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Изменение статуса: в режиме просмотра нажать на текущий статус и выбрать желаемый, затем «Сохранить». После сохранения появляется уведомление об успешном сохранении изменений; администратор возвращается на страницу конфигурации источника в режиме просмотра, новый статус отображается, кнопка «Редактировать» снова доступна. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Поля и элементы
- Список версий источника: содержит версии, доведённые до статуса «Подключен»; для каждой отображаются номер версии, дата и время сохранения в статусе «Подключен», имя пользователя, совершившего сохранение. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Кнопка «Редактировать» при выборе версии, отличной от действующей, неактивна. После выбора нового статуса в режиме просмотра «Редактировать» меняется на «Сохранить». (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Кнопка «Клонироваь» (написание как в документе): тип — Кнопка; обязательность — Нет; редактируемое — «-»; сообщения об ошибке — «-». (3-Клонирование источника данных)
- Диалоговое окно, поле «Название»: Поле для ввода; обязательное — Да; редактируемое — Да; валидации нет («валидируется только в момент сохранения выч.атрибута»); сообщений об ошибке нет. (3-Клонирование источника данных)
- Диалоговое окно, «Поля для клонирования»: Множественный выбор; обязательное — Да; редактируемое — Да; валидаций и сообщений об ошибке нет. (3-Клонирование источника данных)
- Диалоговое окно, кнопки «Клонировать» и «Отмена»: Кнопка; обязательность — Да; остальные атрибуты «-». Доступны для нажатия: чекбокс напротив каждого элемента, «Клонировать», «Отмена». (3-Клонирование источника данных)
- Общие поля для клонирования: «Все» (выделяет все доступные варианты); «Тип источника» (всегда выбран, отменить нельзя); «Описание источника»; «Описание подключения»; «Правила вычисления»; «Пример события»; «Информационная система»; «Предварительная обработка»; «Технические атрибуты». (3-Клонирование источника данных)
- Для типа kafka: bootstrapAdress; inputTopics. (3-Клонирование источника данных)
- Для типа Ключ-Астром: «Идентификатор переменного окружения кластера»; «Имя хоста кластера»; «ID Сервиса, по которому забираем данные»; «Наименование сервиса»; «Описание сервиса». (3-Клонирование источника данных)

### Бизнес-правила и ограничения
- Чтобы применить новую версию, администратор в режиме редактирования выбирает статус «Подключен» и нажимает «Сохранить». Прежняя версия становится недоступна для редактирования и подключения к контрольной точке. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Редактировать можно только последнюю действующую версию; при выборе иной версии настройки видны в режиме просмотра. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Статус действующей версии можно изменить, в том числе в режиме просмотра. Изменение статуса может повлиять на работу источника и доступность данных. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- «Тип источника» при клонировании остаётся тем же, изменить нельзя. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4; 3-Клонирование источника данных)
- Клонируется только сохранённая информация: если пользователь ввёл данные и, не нажав «Сохранить», нажал «Клонировать», несохранённое не склонируется. (3-Клонирование источника данных)
- Клонировать можно как в режиме просмотра, так и в режиме редактирования. (3-Клонирование источника данных)
- Можно выбрать, какие поля клонировать; набор полей зависит от типа источника. (3-Клонирование источника данных)
- Склонированный источник создаётся в статусе «Черновик»; наименование клонируется с припиской «КОПИЯ». (3-Клонирование источника данных)
- Клонировать можно только 1 источник за раз. (3-Клонирование источника данных)
- Конкурентное редактирование: если один пользователь открыл сессию («Редактировать»), второй при нажатии «Редактировать» видит нотификацию об ошибке и не может изменить статус. После закрытия сессии первым («Сохранить») второй может перейти в редактирование и изменить статус. Если пользователь открыл сессию и покинул страницу без «Сохранить», вернуться к редактированию через «Редактировать» может только он же. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Сообщения и ошибки
- «В данный момент <Имя пользователя> редактирует источник» (нотификация об ошибке). (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Уведомление об успешном сохранении изменений после сохранения статуса. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)

### Роли и права
- Описанные действия с версиями, статусом и конкурентным редактированием выполняет пользователь в роли администратора. (Сфера.ТМБС_Руководство_пользователя_PPBP-26.3.0-4)
- Для клонирования нужно разрешение на создание источников; новых разрешений не вводится. (3-Клонирование источника данных)

### Сценарии
- Критерий 1: ЕСЛИ пользователь в режиме просмотра ИЛИ редактирования источника И имеет разрешение на создание источников, КОГДА нажимает «Клонировать», ТОГДА видит всплывающее окно с множественным выбором полей (чекбокс напротив каждого элемента, кнопки «Клонировать» и «Отмена»). (3-Клонирование источника данных)
- Критерий 2: ЕСЛИ выполнен критерий 1, КОГДА выбирает одно, несколько или «все» поля и нажимает «Клонировать», ТОГДА открывается окно создания источника в статусе «Черновик», выбранные поля скопированы, доступны «Сохранить» и «Отмена». (3-Клонирование источника данных)
- Критерий 3: ЕСЛИ выполнен критерий 2, КОГДА нажимает «Сохранить», ТОГДА источник сохранён в статусе «Черновик». (3-Клонирование источника данных)
- Критерий 4: ЕСЛИ выполнен критерий 2, КОГДА нажимает «Отменить», ТОГДА окно создания закрыто, клон не создан. (3-Клонирование источника данных)

### Расхождения между документами
- Статусы, в которых доступно клонирование: Руководство пользователя — в любом статусе источника; 3-Клонирование источника данных — в любом статусе, кроме «Постановка».
