# Оконные функции и подзапросы в SQL вычисляемых атрибутов

> Возможность писать в SQL вычисляемых атрибутов (всех типов) подзапросы первого уровня вложенности с группировками и оконными функциями в нотации H2 над таблицей data.

### Описание
- Пользовательская история: «Я как Пользователь системы (Аналитик, администратор) хочу иметь возможность написать вложенный SQL запрос для выч. атрибута с оконной функцией, для того, чтобы реализовать логику интересующего меня выч.атрибута». (US Оконные функции в вычисляемых атрибутах-8)
- Контекст: не вся логика расчёта реализуема из-за ограничений в исполнении вложенных запросов и невозможности использования оконных функций. (US Оконные функции в вычисляемых атрибутах-8)
- Бизнес-требования: (1) можно использовать подзапросы SQL; (2) в подзапросе можно использовать оконные функции; (3) в подзапросе можно использовать группировки. Реализуется независимо от типа выч. атрибута, для каждого типа с SQL-запросом. (US Оконные функции в вычисляемых атрибутах-8)
- Задача: PPBP-1999. История: v1, 2024-04-11, Климов Александр, «Создание документа»; v2, 2024-05-20, Климов Александр, «Корректировки SQL запросов согласно замечениям тестирования». (US Оконные функции в вычисляемых атрибутах-8)

(US Оконные функции в вычисляемых атрибутах-8)

### Бизнес-правила и ограничения
- Запросы выполняются в h2 in-memory хранилище, нотация h2. (US Оконные функции в вычисляемых атрибутах-8)
- Только до первого уровня вложенности. Выполняется: `select max(nb) from (select column1, count(*) as nb from data group by nb)`. Не выполняется (пользователю ошибка): `select max(nb) from (select column1, count(*) as nb from (select * from data) group by nb)`. (US Оконные функции в вычисляемых атрибутах-8)
- Запрос возвращает одну строчку или 0 строк с одной колонкой — результат функции агрегации (max, min, count ...). (US Оконные функции в вычисляемых атрибутах-8)
- Нельзя join \ union: доступ только к таблице data с поступившими на момент расчёта событиями транзакции. (US Оконные функции в вычисляемых атрибутах-8)
- Запрос (или подзапрос) должен обращаться к data; запросы `select 1`, `select current_timestamp()` дают ошибку. (US Оконные функции в вычисляемых атрибутах-8)
- Расчёт инициируется при поступлении новых событий; выч. атрибут рассчитывается многократно и перезаписывается более новыми расчётами согласно внутренней логике БД Clickhouse. (US Оконные функции в вычисляемых атрибутах-8)
- В подзапросе можно where \ group by \ order by \ having и оконные функции согласно спецификации H2. (US Оконные функции в вычисляемых атрибутах-8)
- Внедрение не должно увеличивать нагрузку на бизнес-сервис расчёта выч. атрибутов. (US Оконные функции в вычисляемых атрибутах-8)
- Логика: (1) пользователь готовит запрос; (2) донасыщение фильтром транзакции: where _system_execution_id = _system_execution_id (системное поле с идентификатором расчёта); (3) донасыщение группировкой: group by _system_execution_id. (US Оконные функции в вычисляемых атрибутах-8)
- Доработка: снять ограничение на пользовательские подзапросы, реализовать их выполнение. (US Оконные функции в вычисляемых атрибутах-8)

### Сообщения и ошибки
- При подзапросе второго уровня и запросах без обращения к data пользователю отдаётся ошибка (текст не приведён). (US Оконные функции в вычисляемых атрибутах-8)

### Сценарии
- Критерий приёмки 1 (одинаков для всех типов): ЕСЛИ пользователь авторизован в SFERA, создана карточка мониторинга БС, открыт раздел создания выч. атрибутов, нажато «Создать вычисляемых атрибут», заполнены «Общие настройки», выбран тип «Общий» ИЛИ «С ожиданием по времени» ИЛИ «Полнота»; КОГДА перешёл в «Правила вычисления», написал SQL, нажал «Вывести пример», выбрал транзакцию/транзакции и нажал «Выполнить код»; ТОГДА видит результат в «Результат запроса». (US Оконные функции в вычисляемых атрибутах-8)
- Тест: 6 событий, транзакция d595a177-c00e-4341-b511-38e72cf54dfd. (US Оконные функции в вычисляемых атрибутах-8)
  - `SELECT count(event_stage) FROM data d` — 6
  - `SELECT count(event_stage) FROM (SELECT event_stage FROM data d)` — 6
  - `SELECT count(event_stage) FROM (SELECT event_stage FROM "data" d WHERE event_stage = 'check_events')` — 4
  - `SELECT max(nb) FROM (SELECT event_stage, event_status, count(*) AS nb FROM "data" d WHERE event_stage = 'check_events' GROUP BY event_stage, event_status)` — 2
  - `SELECT max(rn_status) FROM (SELECT event_stage, ROW_NUMBER() OVER (ORDER BY event_stage) AS rn_status FROM "data" d) WHERE event_stage = 'check_events'` — 5
  - тот же запрос плюс `having count(distinct event_stage) = 1` — 5
