# Просмотр примеров событий источника данных в JSON формате (окно «События источника данных»)

> Окно «События источника данных» в ТМБС позволяет пользователю с нужным разрешением просматривать сохранённые исходные события источника в JSON-формате с фильтрацией, выбором столбцов и поиском внутри JSON.

### Описание
- Пользовательская история PPMON-657 «ПП. Транзакционный мониторинг БС. Просмотр примеров событий в JSON формате источника данных в пользовательском интерфейсе» (статус «В работе»). Я как: Пользователь системы. Хочу: Посмотреть исходные события источника в интерфейсе. Для того, чтобы: Знать формат событий поступающих в источник. (US Просмотр примеров событий в JSON формате источника данных в пользовательском интерфейсе-11)
- История изменений: версия 1, 26.09.2024, автор Лазарев Никита, «Создание документа». Макет: Figma, «Monitoring-card. TRM (Light)», node-id=1618-47480. Разделы 4.1, 6.1-6.4 и 7 содержат только шаблонные заглушки. (US-11)

### Экраны и навигация
- В окно можно попасть двумя способами: через пункт «Администрирование - Просмотр событий источника данных» или прямым переходом по кнопке из источника данных. При прямом переходе в поле «Источник данных» предзаполнен источник, из которого перешли. Переход из источника возможен только если события сохраняются. (US-11)
- Окно состоит из блоков: «Условия поиска», «События», «Json» (блок «Атрибуты» с полем «Поиск»). Блок можно свернуть/развернуть элементом слева от названия, скрыть элементом рядом с названием, расширять и сужать, потянув за края. (US-11)
- Кнопка рядом с «источником данных» переводит к выбранному источнику. (US-11)

### Поля и элементы
**«Условия поиска»**
- Источник данных: раскрывающийся список, обязательное, редактируемое; выбор только 1 источника; доступны все источники системы, ввод фильтрует список; у источников с включённым сохранением надпись «События сохраняются». (US-11)
- Кнопка перехода в источник: отображается всегда; открывает выбранный источник в текущем состоянии в новой вкладке. (US-11)
- Версия: раскрывающийся список, необязательно; версии, для которых включено «Сохранять исходные события», либо «Все» (по умолчанию, события по всем версиям); ввод фильтрует варианты. (US-11)
- Период: поле «Календарь», редактируемое; формат dd:mm:yyyy hh:mm - dd:mm:yyyy hh:mm или выбор календарём. Начальная дата не позднее -30 дней от текущей; даты позже текущего времени выбрать нельзя. (US-11)
- Максимальное количество: раскрывающийся список, обязательное; значения 10, 50, 100. (US-11)
- Текст для поиска: необязательное, редактируемое; поиск внутри JSON по атрибутам и значениям. Разрешены: латиница (Aa-Zz), кириллица (Аа-Яя), цифры 0-9, - : @ / | . , ! ? " & *. Запрещён ' (одинарные кавычки). (US-11)
- Кнопка «Применить»: выводит json-сообщения по фильтрации; блок «События» отображается по её нажатию; не более 10 раз в минуту одним пользователем. (US-11)
- Кнопка «Очистить»: очищает все введённые параметры; не сбрасывает уже найденные сообщения и JSON после «Применить». (US-11)

**«События»**
- Показаны события по фильтрам. Столбцы по умолчанию: source_time, insert_time, версия (версия источника, по которой записано/выводится событие), json (сообщение в одну строку). Если введённый «Текст для поиска» найден, столбец JSON отображается с начала этого текста. (US-11)
- Если json не удаётся отобразить, в поле «json» выводится «Невозможно отобразить json». (US-11)
- «Шестеренка»: добавление доп. столбцов (атрибутов) чекбоксами, множественный выбор. Перечень атрибутов в документе не приведён. (US-11)
- Выделить и показать можно только одно сообщение за раз. (US-11)

**«Json»**
- Нередактируемое поле; при выделении события показывает форматированное json-сообщение; рядом с названием блока отображается event_time сообщения. (US-11)
- «Атрибуты», поле «Поиск»: редактируемое, поиск по вхождению без ограничений ввода; найденный текст подсвечивается; «стрелочки» к следующему совпадению, «крестик» очищает поле. (US-11)

### Бизнес-правила и ограничения
- Сообщение доступно после включения настройки «Сохранять исходные события» (история «[US] Сохранение исходных событий источника данных в БД ClickHouse в JSON формате», там же настройка времени хранения). (US-11)
- «Применить» не более 10 раз в минуту на пользователя; затем кнопка дизейблится, при наведении предупреждение «Превышен Лимит. Пожалуйста, подождите (отсчет в реальном времени)». (US-11)
- Если выбран источник без включённого сохранения, в блоке сообщений выводится «События не найдены». (US-11)

### Сообщения и ошибки
- «Имеются недопустимые символы» — при запрещённых символах в «Текст для поиска»; «Применить» недоступна. (US-11)
- «Превышен Лимит. Пожалуйста, подождите (отсчет в реальном времени)» — при превышении 10 нажатий в минуту. (US-11)
- «События не найдены» — при ошибке 400 и при выборе источника без сохранения событий. (US-11)
- «Невозможно отобразить json» — в поле «json». (US-11)

### Сценарии
- Крит. 1: ЕСЛИ создан источник, включено сохранение событий и есть разрешение, КОГДА нажимает кнопку перехода к источнику, ТОГДА попадает на экран просмотра событий JSON с предзаполненным источником. 1.1: при тех же условиях переход на вкладку «Администрирование - Просмотр событий источника» открывает экран. 1.2: после 1.1 выбор источника с надписью «События сохраняются». (US-11)
- Крит. 2-5: при 1 ИЛИ 1.2 пользователь выбирает версию (конкретную или «ВСЕ»), период календарём, максимальное количество, вводит текст для поиска. (US-11)
- Крит. 6: при (1 ИЛИ 1.2) И критерии 3 нажатие «Применить» показывает события по фильтрации; при найденном тексте столбец JSON с начала введённого текста. (US-11)
- Крит. 7: при наличии событий нажатие на событие показывает в блоке JSON форматированное сообщение. (US-11)
- Крит. 8: ввод текста в поиск по JSON выделяет все совпадения; перемещение стрелочками. (US-11)
