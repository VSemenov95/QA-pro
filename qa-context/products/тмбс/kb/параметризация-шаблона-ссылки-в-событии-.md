# Параметризация шаблона ссылки в событии мониторинга значениями из SQL-запроса

> Администратор задаёт в коде события мониторинга метрики шаблон ссылки на дашборд с динамическими параметрами (${alias}), значения которых подставляются из результата SQL-запроса события при срабатывании трешхолда и отправляются в уведомлении.

### Описание
- Пользовательская история: «Я как Администратор. Хочу Создать шаблон ссылки с динамическими параметрами. Для того, чтобы Пользователи могли переходить на дашборд с деталями интересующей транзакции прямо из уведомления о событии мониторинга». ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Контекст: в текущей реализации можно задать шаблон ссылки, которую система генерирует при возникновении события мониторинга, но генерируемые ссылки не содержат всей необходимой информации, что требует от пользователей дополнительных усилий для нахождения деталей события. Необходимо гибко параметризировать шаблон ссылки под бизнес-потребности конкретного бизнес-сервиса. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)

### Бизнес-правила и ограничения
- БТ 1: пользователь должен иметь возможность указать шаблон ссылки с требуемыми параметрами (0 - N). ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- БТ 2: в тексте уведомления, отправляемого пользователям при возникновении события мониторинга, должна присутствовать сформированная по шаблону ссылка со всеми необходимыми параметрами; пользователи переходят по ней для просмотра деталей без дополнительных действий для поиска данных. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 1: указанные в шаблоне параметры/поля должны использоваться в SQL-запросе события мониторинга (в примере `var-payment_id=${id}` имя `id` — alias в SQL-запросе). ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 2: значения параметров не сохраняются в таблицу default.bs_${bs_table}_monitoring_event_distributed, за исключением случаев, когда в качестве параметра используется поле данной таблицы. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 3: результат выполнения запроса при срабатывании трешхолда (возникновении события мониторинга) должен логироваться. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 4: если SQL-запрос возвращает пустое значение или NULL для одного из параметров, система подставит пустое значение. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 5: если SQL-запрос возвращает строку с массивом значений для одного из параметров, система генерирует N ссылок с каждым таким значением, значения остальных параметров идентичны в каждой ссылке; все N ссылок приходят в одном сообщении о событии мониторинга. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 6: если массив значений возвращается для двух и более параметров, система последовательно соотносит значения по порядковому номеру элемента (0-й элемент одного массива соответствует 0-му другого и т.д.) и генерирует N ссылок, где N — наибольшее число значений в массиве; для недостающих значений подставляется пустота. Корректность соотнесения значений с точки зрения бизнес-задачи должна обеспечиваться написанием корректного SQL-запроса, учитывающего это ограничение. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 7: если результат выполнения SQL-запроса содержит несколько строк, система сгенерирует несколько событий мониторинга. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Допущение 8: в данной истории не рассматривается обработка и отображение пользователю ошибок, возникающих при написании некорректного шаблона ссылки. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
- Требования к системе: (1) при срабатывании трешхолда метрики извлечь из результата выполнения SQL-запроса кода события мониторинга значения параметров, указанных в шаблоне как переменные; (2) подставлять каждое значение в соответствующие места шаблона; (3) логировать результат выполнения SQL-запроса при срабатывании трешхолда; (4) при пустом значении или NULL подставлять пустое значение; (5) при массиве для одного параметра генерировать N ссылок, остальные параметры идентичны, все N в одном сообщении; (6) при массивах для двух и более параметров соотносить по порядковому номеру элемента, N — наибольшее число значений, недостающие — пустота. ([US] Параметризация шаблона ссылки в событии мониторинга значениями из SQL запроса-21)
