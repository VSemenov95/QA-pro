# Обязательная контрольная точка: условный запуск расчёта вычисляемых атрибутов для несклеенных событий

> Механизм, по которому события, не склеившиеся в бизнес-сервисе, передаются на расчёт вычисляемых атрибутов только если их контрольная точка помечена флагом «Обязательная контрольная точка», что снижает нагрузку на микросервис расчёта.

### Описание
- Пользовательская история: «Я как Администратор системы. Хочу Сократить количество вычислений атрибутов транзакций. Для того, чтобы Снизить нагрузку на микросервис расчета вычисляемых атрибутов». (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Контекст: расчёт вычисляемых атрибутов ведётся по каждому приходящему событию. По первым событиям транзакций атрибуты вычисляются, но бизнес-смысла не несут: для расчёта разницы по времени, проверки статусной модели, ошибок и т.д. нужно как минимум два события. Нужен механизм, исключающий ненужные и неэффективные вычисления. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Пользователь может для контрольной точки выставить флаг «Обязательная контрольная точка». (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)

### Экраны и навигация
- Форма 1. Включение обязательности КТ (ссылка на Figma и описание в документе не заполнены; ссылка на форму приведена в п. 5.3). (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)

### Поля и элементы
- Поле «Обязательная контрольная точка»: Чекбокс (boolean); обязательное — Нет; редактируемое — Нет (дословно как в таблице); правила отображения, валидации — «False по умолчанию»; сообщения об ошибке — Нет; параметр в ответе с ВЕ — не указан («-»). (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- В БД конфигурации признак: таблица config_service."checkpoint", поле mandatory bool DEFAULT false NOT NULL. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)

### Бизнес-правила и ограничения
- БТ 1: возможность настроить правило запуска расчёта вычисляемых атрибутов, т.е. при каких условиях он запускается. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- БТ 2: система должна уметь не запускать вычисляемые атрибуты для одинарного (не склеенного) события. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- «Обязательная контрольная точка» = true: событие по КТ пришло и не склеено — расчёт производится. = false: событие пришло и не склеено — расчёт не производится. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Допущение 1: первые события — всегда те, что невозможно склеить с событиями какого-либо бизнес-сервиса; функциональность влияет только на такие события. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Допущение 2: для разных КТ в разных бизнес-сервисах флаг может иметь разные значения; логика запуска должна соответствовать настройкам параметров КТ. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Требование к системе: функционал не должен влиять на производительность, она не должна ухудшаться. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)

- Компоненты: trmonbs-merging-service — склейка транзакций; Kafka — шина обмена данными микросервисов; trmonbs-online-metrics-service — расчёт вычисляемых атрибутов; trmonbs-enrichment-service — обогащение, отнесение событий к бизнес-сервису. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Порядок: 1) trmonbs-enrichment-service по конфигурации обогащает события источников, они попадают в bs_XX_enrichment; 2) trmonbs-merging-service склеивает события и определяет, что склеилось и что нет в рамках бизнес-сервиса; 3) trmonbs-online-metrics-service рассчитывает вычисляемые атрибуты. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)

### Сценарии
- 1) При приходе каждого события анализируется возможность его склейки с другими событиями бизнес-сервиса и присвоения идентификатора транзакции. 2) Если не склеилось — записывается как новое, получает идентификатор транзакции. 3) Для каждого нового события проверяется, принадлежит ли оно обязательной КТ. 4) Если да — производится расчёт вычисляемых атрибутов данного бизнес-сервиса. 5) Если нет — расчёт не производится. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Признак обязательности КТ устанавливает пользователь через интерфейс (п. 5.3). (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
- Доработка расчёта: анализировать, является ли событие первым (не склеилось с другими событиями БС), И проверять признак обязательности для решения о расчёте. (US События не передаются на расчет вычисляемых атрибутов если событие не склеилось во всех бизнес-сервисах, которому может относится-9)
