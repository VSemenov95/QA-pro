### Бизнес-правила и ограничения
- 3.1.1 Общий тип: используется, когда значение атрибута не зависит от времени и вычисляется по мере поступления событий. Пример: `select sum(amount) where event_stage in ('payment_1', 'payment_2')`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- 3.1.2 Тип «С ожиданием по времени»: используется, когда необходимо вычислить временной интервал. Задаются правило расчёта начала интервала, окончания интервала и пороги, являющиеся таймаутами. Если время начала вычислено, а время окончания нет, и с начала интервала истекло время таймаута, атрибуту проставляется соответствующий порог (warning или critical). В финальную таблицу атрибутов значение пишется в миллисекундах. Код запроса должен возвращать единственное значение типа Дата_время. Примеры: `select min(event_time) from data where event_stage = 'A' and status = 'SUCCESS'`; `select max(event_time) from data where event_stage = 'B' and status = 'SUCCESS'`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- 3.1.3 Тип «Полнота»: используется, когда состояние Normal наступает не при первом событии, а лишь с последующими. Пример: ожидается 9 событий в транзакции; тогда состояние Normal, а транзакция с количеством событий меньше 9 — Critical. Выставляется timeout; если за timeout атрибут не достиг Normal, он записывается с порогом Critical. Интервалы: Critical: (-бесконечность, 9), Normal: [9, +бесконечность). (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- 3.1.3, поле «Начало ожидания»: код должен возвращать единственное значение типа Дата_время, пример `select min(event_time) from data`. Поле «Код вычисляемого атрибута»: код должен возвращать единственное целочисленное значение, пример `select count(1) from data`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- 3.2 Запрос метрик: код `select count(1) from data`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- 3.3 Запрос события мониторинга. Комментарий в коде: «Перед выполнением кода измените переменные: {$Идентификатор_БС$}, {$Идентификатор_выч.атрибута$}, {$идентификатор_мертрики$}». Состоит из блока расчёта метрики и CTE `metrics`, `monitoring_events`, `eventid` с итоговой выборкой. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- Расчёт метрики (из `default`.bs_{$Идентификатор_БС$}_attribute_distributed ba): `sipHash64(metric_id, metric_time) as metric_uuid`; `'{$идентификатор_мертрики$}' as metric_id`; `toStartOfMinute(transaction_time) as metric_time`; `'Количество транзакций в системе' as metric_name`; `count(distinct transaction_uuid) as metric_value`; `'1m' as metric_period`; `last_value(transaction_uuid) as metric_object`; `count(distinct transaction_uuid) as metric_object_count`; `toDateTime(now(),'Europe/Moscow') as insert_timestamp`; условия `attribute_id in ({$Идентификатор_выч.атрибута$})` и `transaction_time >= now() - toIntervalMinute(600)`; `group by metric_time`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- CTE `metrics` (из `default.bs_5_metric_distributed md`): severity `case when metric_value > 0 then 'CRITICAL' else 'NORMAL' end`; metric_name as metricName; metric_value as metricValue; insert_timestamp as timeAlertCreated; `cast(metric_uuid, 'String') as object`; object as originalData; metric_object_count as additionalAttributes; `toDateTime(now(), 'Europe/Moscow') as insert_timestamp`; metric_object; условия `metric_id=52` и `md.insert_timestamp > toDateTime(now(), 'Europe/Moscow') - toIntervalHour(1)`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- CTE `monitoring_events`: `select externalId from default.bs_5_monitoring_event_distributed me where externalId != ''`. CTE `eventid`: `select distinct event_id_3, transaction_uuid from default.bs_5_event_distributed d where d.insert_timestamp > toDateTime(now(), 'Europe/Moscow') - toIntervalHour(24)`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
- Итоговая выборка: `'TRmonBS' as application`; `'Бизнес-сервис' as category`; severity; `'5' as ciName`; `'ЦСПереводы c2c' as serviceName`; `'2099 Транзакционный мониторинг. \n' as title`; `'Количество транзакций ERROR по 2.2 \n' || title || 'Идентификатор транзакции ' || eventid.event_id_3 as alertText`; metricName, metricValue, timeAlertCreated; `metric_object as object`, `metric_object as originalData`; insert_timestamp; `metrics.object as externalId`; `from metrics left join monitoring_events on metrics.object = monitoring_events.externalId left join eventid e on e.transaction_uuid = toUUIDOrZero(metrics.metric_object)`; `where metrics.object != monitoring_events.externalId and severity != 'NORMAL' limit 1`. (Шаблоны SQL запросов выч. атрибутов, метрик, событий мониторинга-5)
