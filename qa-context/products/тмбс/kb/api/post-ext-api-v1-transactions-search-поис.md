# POST /ext-api/v1/transactions-search — поиск транзакций по индексированным атрибутам

> POST /ext-api/v1/transactions-search — внешний метод ТМБС, который ищет транзакции бизнес-сервиса по индексированным атрибутам (в ClickHouse) и возвращает список идентификаторов транзакций и их количество.

### Описание
- URL: /ext-api/v1/transactions-search; метод HTTP: POST; наименование: Поиск транзакций по индексированным атрибутам с возвратом идентификаторов транзакций; авторизация: JWT (token) пользователя; ссылка на swagger: -; обработка ошибок: 400, 403, 409, 423, 500; http-статус в ответе: 200; задача: PPBP-1955 [Аналитика] ТМБС. АПИ для поиска БС и id транзакции по заданным полям (26-POST _ext-api_v1_transactions-search)
- OpenAPI: title «2099.ppbp-transactionsSearch-s-rest-v1», description «API для поиска транзакций по индексированным атрибутам», version 1.0.0, openapi 3.0.1; operationId getTransactions; tag ExternalApiController. Метод ищет транзакции по переданным атрибутам и возвращает список идентификаторов; для атрибута можно указать одно значение (value) или массив (valueArray) в зависимости от типа операции (26-POST _ext-api_v1_transactions-search)
- История (автор @Perekin D.С.; в 1.8 указано «D.S.»): 1.0, 15 мая 2026 — создание страницы; 1.1, 25 мая 2026 — описание логики; 1.2, 27 мая 2026 — переменные CONFIG_INTEGRATION_REST_TRANSACTIONS_RESPONSE_LIMIT и CONFIG_INTEGRATION_REST_TRANSACTIONS_STRING_ARRAY_MAX_SIZE, тип STRING_ARRAY и операция IN; 1.3, 29 мая 2026 — valueArray в теле запроса; 1.4, 10 июн. 2026 — изменения OPEN API по замечаниям Внедрения; 1.5, 18 июн. 2026 — изменения по apiBsCode; 1.6, 02 июл. 2026 — тип «Date» обязателен; 1.7, 08 июл. 2026 — FEATURE_INTEGRATION_REST_ENABLED для всех АПИ эндпоинтов; 1.8, 22 июл. 2026 — изменение примера OpenApi (26-POST _ext-api_v1_transactions-search)

### Поля и элементы
- Вход (body): attributes — array<object>, «Атрибуты поискового запроса», обязательный; apiBsCode — string, «Код Бизнес-сервиса», обязательный, пример 8. Значения по умолчанию не заданы (26-POST _ext-api_v1_transactions-search)
- Элемент attributes: code — string, необязательный; value — string, необязательный; valueArray — array<string>, необязательный, пример ["111","222","333","444"]; operation — string, enum EQ, LTE, GTE, пример EQ (26-POST _ext-api_v1_transactions-search)
- Выход: transactionIds — array<UUID>, необязательный, «id транзакций», пример [e80d1eda-bd4a-4e36-ae80-20250f2ce482]; transactionCount — int, обязательный, «Общее кол-во транзакций выдаваемых в ответе», пример 24000 (26-POST _ext-api_v1_transactions-search)
- Пример запроса: apiBsCode "8"; attributes: clientExtId "1111" EQ; transactionId и instructionId "af9bd94b-c9e7-4b12-a2af-7e3123836f70" EQ; accountLast4 "2590" EQ; amount "3000" EQ; documentNumber "1789" EQ; mdm value null, valueArray ["111","222","333","444"], IN; idRs af9bd94b-c9e7-4b12-a2af-7e3123836f70 EQ; payDate "2026-01-03" GTE и LTE. Для атрибутов с value valueArray = null (26-POST _ext-api_v1_transactions-search)
- Пример ответа: {"transactionIds":["c64ae0e8-570d-4408-8317-45ed91ae2bec","6ce289e2-2a7d-44d9-9434-f8d7c4127d5b","e80d1eda-bd4a-4e36-ae80-20250f2ce482"],"transactionCount":2400} (26-POST _ext-api_v1_transactions-search)
- Схема OpenAPI: TransactionsSearchRequestDto — обязательные apiBsCode (string, 1–255, «Идентификатор Бизнес-сервиса», example "8"), attributes (maxItems 100). TransactionsSearchRequestAttribute — обязательные code (1–255, «Код атрибута») и operation; value 1–2000, «Значение атрибута (используется для операций EQ, LTE, GTE, LT, GT)»; valueArray maxItems 500, элементы 1–2000, «Массив значений атрибута (используется для операции IN)». AttributeOperationType «Тип операции сравнения»: EQ, LTE, GTE, LT, GT, IN. TransactionsSearchResponseDto — обязательное transactionCount (integer 0–25000, «Общее количество транзакций, соответствующих критериям поиска», example 24000); transactionIds maxItems 25000, «Список идентификаторов транзакций (UUID)», string format uuid. ServerErrorDto: errorCode integer 1–99999, «Внутренний код ошибки»; errorMessage string 1–10000, «Сообщение об ошибке сервиса»; additionalProperties false (26-POST _ext-api_v1_transactions-search)

### Бизнес-правила и ограничения
- Предусловие: администратор наполняет env-переменные в конфигурационном файле и/или оставляет по умолчанию (заполняются для внутреннего АПИ в ppbp-admin-service) (26-POST _ext-api_v1_transactions-search)
- CONFIG_INTEGRATION_REST_TRANSACTIONS_SEARCH_ATTRIBUTES_LIST — справочные значения атрибутов поиска для БС из ..._SEARCH_BS_LIST, маппинг данных. «order» выставляется для селективности скрипта поиска; атрибут типа «Date» должен иметь order «0». Дефолт (в документе назван CONFIG_INTEGRATION_REST_SEARCH_ATTRIBUTES_LIST): clientExtId «Идентификатор организации в ДБО» STRING 1; transactionId «Идентификатор транзакции/инструкции» STRING 2; instructionId «Идентификатор инструкции» STRING 3; accountLast4 «Последние 4 цифры счета» STRING 4; amount «Сумма платежа» STRING 5; documentNumber «Номер платежного документа» STRING 6; mdm «MDM-код» STRING_ARRAY 7; idRs «Идентификатор РС счета» STRING 8; payDate «Дата Платежа» DATE 0 (26-POST _ext-api_v1_transactions-search)
- CONFIG_INTEGRATION_REST_TRANSACTIONS_SEARCH_DEPTH_IN_DAY — глубина поиска в днях, пример 31; CONFIG_INTEGRATION_REST_TRANSACTIONS_SEARCH_BS_LIST — коды БС, пример "8", "10"; CONFIG_INTEGRATION_REST_RESPONSE_MAX_SIZE_IN_KB — макс. размер ответа, пример 900; CONFIG_INTEGRATION_REST_TRANSACTIONS_RESPONSE_LIMIT — лимит транзакций (transactionUUID), пример 24000; CONFIG_INTEGRATION_REST_TRANSACTIONS_STRING_ARRAY_MAX_SIZE — макс. число значений в STRING_ARRAY, пример 20; FEATURE_INTEGRATION_REST_ENABLED — вкл/выкл механизма, глобальная для POST /ext-api/v1/transactions-search, /transactions-attributes, /transactions-events, пример true (26-POST _ext-api_v1_transactions-search)
- ВНИМАНИЕ: наименование и формат env-переменных может измениться при реализации; значения информационные (26-POST _ext-api_v1_transactions-search)
- Операции (ENUM, захардкожены): EQ, GTE, LTE, GT, LT, IN. STRING — только EQ; DATE — EQ, GTE, LTE, GT, LT; STRING_ARRAY — IN. Атрибут типа «Date» обязателен в attributes (26-POST _ext-api_v1_transactions-search)
- Операторы: EQ — равно (=); LT — строго меньше (<); LTE — ≤; GT — строго больше (>); GTE — ≥ (26-POST _ext-api_v1_transactions-search)
- DATE: EQ — точная дата; GTE И LTE — диапазон; GT И LT — строгий диапазон; GT ИЛИ GTE — больше даты; LT ИЛИ LTE — меньше даты (26-POST _ext-api_v1_transactions-search)
- Поиск — строго по полному совпадению атрибутов на колонки таблицы bs_<bs_id>_event_distributed по маппингу (кроме типа DATE) (26-POST _ext-api_v1_transactions-search)

### API и интеграции
- Логика: 1) сервис вызывает эндпоинт. 2) Валидация: нет apiBsCode — ошибка 1; apiBsCode не из ..._SEARCH_BS_LIST — ошибка 2; неуникальность apiBsCode в config_service.business_service (два и более) — ошибка 5; нет ни одного объекта attributes — ошибка 1; нет атрибута «Date» — ошибка 6; код атрибута отсутствует в ..._ATTRIBUTES_LIST — ошибка 3; недопустимая операция — ошибка 4 (26-POST _ext-api_v1_transactions-search)
- 3) Обработка: a) в config_service.monitoring_card найти карточку по bs_id (businessServiceId), взять последнюю версию в статусах «Monitoring» и «Disconnected», получить row_id; b) в config_service.checkpoint отфильтровать КТ по monitoring_card_row_id, получить checkpoint_id; c) в config_service.checkpoint_attribute отфильтровать по checkpoint_id, получить маппинг бизнес-атрибута («name») на поля поиска («search_attributes»); d) перейти в CLICKHOUSE в bs_<bs_id>_event_distributed (26-POST _ext-api_v1_transactions-search)
- 4) Поиск. 5) Ответ: если найдены — посчитать transaction_uuid в transactionCount, положить в transactionIds, посчитать размер в КБ и сравнить с CONFIG_INTEGRATION_REST_RESPONCE_MAX_SIZE_IN_KB; при превышении обрезать по transaction_uuid, иначе полный ответ. Не найдены — пустой transactionIds, transactionCount = "0" (26-POST _ext-api_v1_transactions-search)
- Серверы: IFT — https://api.iftppbp.test.vtb.ru; PREPROD — https://api.app-ppbp.oslb-app01.test.vtb.ru; PROD — https://api.trmonbs.region.vtb.ru (26-POST _ext-api_v1_transactions-search)

- 2 — 400 — Неизвестный apiBsCode: "...default message [apiBsCode]]; default message [not found]]" (26-POST _ext-api_v1_transactions-search)
- 3 — 400 — Неизвестный код атрибута: "[externalApiTransactionSearchRequestDto.attributes,code]; arguments []; default message [attributes.code]]; default message [not found]]" (26-POST _ext-api_v1_transactions-search)
