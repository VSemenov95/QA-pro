# POST /api/authorities — получение списка разрешений пользователя для бизнес-сервиса

> POST /api/authorities с типом объекта BUSINESS_SERVICE проверяется на ответ 200 OK и формирование сообщений аудита начала и успешного завершения операции.

## Сфера.Аудит — история прохождений и тест-план.md

### Описание
- Тест-кейс PPBP-3593 «[BE] Проверка события BUSINESS_SERVICE_GET_AUTHORITIES» в тест-плане «[US] Реализовать механизмы для перехода на Сфера.Аудит».
### API и интеграции
- Запрос: `POST {{baseURL}}/api/authorities`.
- Тело запроса: `{"objectType":"BUSINESS_SERVICE","objectId":1234}`. `objectId` — `bsId` бизнес-сервиса из предусловия.
- Ожидаемый результат: «Статус Код 200 OK».
- Предусловия: `SFERA_AUDIT_ENABLED = true`, `SFERA_AUDIT_TRANSPORT_MODE=KAFKA`, `SFERA_AUDIT_KAFKA_TOPIC=audit-event`; существует бизнес-сервис и известен его id, например, `1234`.
- kafka-dev: https://kafka-ui.ppcps-stable.dev.sfera-t1.ru/ui/clusters/shared/all-topics/audit-events/messages ; kafka-test: https://kafka-ui.ppcps-stable.test.sfera-t1.ru/ui/clusters/shared/all-topics/audit-events/messages.
### Сценарии
- Отправить запрос с указанным телом и проверить `200 OK`.
- Проверить наличие сообщения в kafka для события `PPBP_BUSINESS_SERVICE_GET_AUTHORITIES` с атрибутами: `status = START`, `infoSystemCode = PPBP`, `infoSystemId = 2099`, `userIdentity.requestMetadata.method = POST`, `userIdentity.requestMetadata.url=/api/authorities`, `additionalAttributes.authInfoDto.objectType=BUSINESS_SERVICE`, `additionalAttributes.authInfoDto.objectId=1234`, `businessOperation=Получение списка разрешений пользователя`, `messageTemplate=Начало операции`. Ожидается: «Сообщение для события PPBP_BUSINESS_SERVICE_GET_AUTHORITIES присутствует в топике audit-event».
