# POST /api/sendCheckpointInformation/ — запуск отправки списка КТ по всем БС в стороннюю систему

> Метод POST /api/sendCheckpointInformation/ запускает механизм отправки списка КТ по всем БС в стороннюю систему через Kafka; доступен роли Администратор по JWT.

### Описание
- Наименование метода: «Запуск механизма отправки списка КТ по всем БС в стороннюю систему». URL: /api/sendCheckpointInformation/. Метод HTTP: POST. Способ авторизации: JWT (token) пользователя. (2-POST _api_sendCheckpointInformation_)
- Ссылка на swagger: не указана. (2-POST _api_sendCheckpointInformation_)
- История изменений: версия 1.0, автор @Perekin D.С., дата 03 июн. 2026, описание «Создание страницы», задача PPBP-2190 [Аналитика] Отправка данных карточки мониторинга с соответствием КТ и ИС в Kafka. (2-POST _api_sendCheckpointInformation_)
- Оглавление страницы: Описание метода, История изменений, Входные параметры, Пример запроса, Выходные параметры, Логика работы. (2-POST _api_sendCheckpointInformation_)

### Поля и элементы
- Входной параметр один: authorization, тип string, описание «JWT (token) пользователя», расположение header, обязательный (+), значение по умолчанию и пример не указаны. (2-POST _api_sendCheckpointInformation_)
- Раздел «Пример запроса» пуст. (2-POST _api_sendCheckpointInformation_)

### Бизнес-правила и ограничения
- При успешном запросе запускается механизм отправки КТ в Кафку по согласованному формату сообщения, описанному на отдельной странице (полная ссылка в документе не приведена). (2-POST _api_sendCheckpointInformation_)
- При ошибке запроса механизм не запускается. (2-POST _api_sendCheckpointInformation_)

### API и интеграции
- Метод запускает отправку списка КТ по всем БС в стороннюю систему через Kafka. (2-POST _api_sendCheckpointInformation_)
- Адрес сервиса: https://trmonbs-admin-service.ppmon.dev.sfera-t1.ru/api/sendCheckpointInformation/ (2-POST _api_sendCheckpointInformation_)

### Сообщения и ошибки
- В разделе «Обработка ошибок» заявлены коды 400, 401, 403, 500; http-статус кода в ответе: 200. (2-POST _api_sendCheckpointInformation_)
- Таблица «Статус-код» (HTTP-статус / Код сообщения / Сообщение / Сценарий возникновения): (2-POST _api_sendCheckpointInformation_)
  - 200 — ОК — «Операция выполнена успешно» — «Запустился механизм формирования отправки КТ».
  - 400 — BadRequest — «Ошибка формата запроса».
  - 403 — Forbidden — «Нет прав для доступа к данным метода»; сценарий «Доступ запрещен (согласно ролевой модели)».
  - 409 — Conflict (сообщение и сценарий не указаны).
  - 423 — Locked (сообщение и сценарий не указаны).
  - 500 — «Сервис временно недоступен», «Внутренняя ошибка сервера»; рядом с кодом 500 в извлечённом тексте встречается строка «Доступ запрещен (согласно ролевой модели)» (соответствие строк неоднозначно).

### Роли и права
- Роль: Администратор. Доступ запрещён согласно ролевой модели — ответ 403. (2-POST _api_sendCheckpointInformation_)

### Сценарии
- 1. Получить запрос. 2. В случае успеха — запустить механизм отправки КТ в Кафку по согласованному формату сообщения. 3. В случае ошибки запроса — механизм не запускается. (2-POST _api_sendCheckpointInformation_)
