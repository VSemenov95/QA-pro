# Поле user_transaction_time (UTT): настройка времени начала транзакции

> Поле user_transaction_time (UTT) позволяет администратору настроить правила определения времени начала транзакции в карточке мониторинга, чтобы от него считались вычисляемые атрибуты, метрики и графики в Графане.

### Описание
- UTT = user_transaction_time. Пользовательская история: «Я как Администратор. Хочу Заполнять поле user_transaction_time по настроенной логике. Для того, чтобы Корректно задавать время начала отсчета для расчета вычисляемых атрибутов и построения графиков в Графане». (28-[US] Добавление поля user_transaction_time)
- Контекст: сейчас система берёт время поступления первого шага как transaction_time для начала построения графиков. Начало отсчёта не всегда должно вестись с первого шага, поэтому графики получаются нерелевантными. Решение: поле user_transaction_time, в которое записывается время по нужной пользователю логике; оно используется в выч. атрибутах и графиках. (28-[US] Добавление поля user_transaction_time)
- История изменений: версия 1, 2024-03-28, автор Лазарев Никита, «Создание документа». (28-[US] Добавление поля user_transaction_time)
- Бизнес-требования: (1) пользователь может задавать время, которое учитывается как начало транзакции; (2) может настроить правило, которое задаётся как начало транзакции; (3) начало транзакции может быть не только временем начала этапа, но и временем определённого статуса внутри транзакции; (4) заданное время можно использовать как время расчёта метрик бизнес-сервиса. (28-[US] Добавление поля user_transaction_time)
- Реализация: в bs_*_attribute_distributed CH добавлен атрибут user_transaction_time. В postgres добавляются 2 таблицы: user_transaction_time_checkpoint и user_transaction_time. (28-[US] Добавление поля user_transaction_time)

### Экраны и навигация
- Настройка UTT на вкладке (шаге) «Вычисляемые атрибуты» карточки мониторинга (4-й шаг создания карточки): селектор (свитчер) «user_transaction_time» и кнопка «Редактировать», открывающая окно редактирования UTT. ### Поля и элементы
- Свитчер «user_transaction_time»: включает настройку поля; по умолчанию выключен. При включении автоматически включается опция «Минимальное время брать из поля "event_time"» (выключается в редактировании). Если свитчер выключен, расчётов и записей со стороны бэка нет. (28-[US] Добавление поля user_transaction_time)
- Кнопка «Редактировать»: правка правил; при выключенном свитчере не видна. (28-[US] Добавление поля user_transaction_time)
- Окно редактирования UTT:
  - Селектор «Минимальное время брать из поля event_time» (в БТ — «Брать минимальное время поступления в систему из всех контрольных точек», сокращённо «минимальное время»): по умолчанию включен. Если включен, блок настройки не отображается, вместо него надпись «Минимальное время будет взято из поля event_time. Для пользовательской настройки поля user_transaction_time вылкючите опцию "Минимальное время брать из поля "event_time""»; значения берутся из event_time.
  - Информационное окно с оповещением (по макету).
  - Блок «Приоритет»: приоритеты КТ выбираются из выпадающего списка; по умолчанию не выставлены; на одну КТ один приоритет; каждый приоритет только одной КТ.
  - «Название контрольной точки»: по умолчанию все КТ данной КМ.
  - «Атрибут»: выпадающий список; значок (i) с текстом «Можно выбрать только атрибуты типа "время", относящиеся к данной контрольной точке».
  - «Сохранить» — сохраняет данные; «Отмена» — возврат на экран «Вычисляемых атрибутов» без сохранения; «Ошибка» — выводится при сохранении без выставленных приоритетов. (28-[US] Добавление поля user_transaction_time)
- В поле UTT два атрибута настройки: «Приоритет контрольной точки» и «технический атрибут», а также настройка «Брать минимальное время поступления в систему из всех контрольных точек». (28-[US] Добавление поля user_transaction_time)

### Бизнес-правила и ограничения
- Приоритеты задают порядок, в котором система проверяет КТ и берёт время. Пример: Приоритет 1 - ct_name_3; Приоритет 2 - ct_name_1; Приоритет 3 - ct_name_4. Если после записи времени КТ с приоритетом (n+x) приходит КТ с приоритетом (n), UTT перезаписывается, вычисляемые атрибуты и метрики пересчитываются. (28-[US] Добавление поля user_transaction_time)
- Технический атрибут должен быть типа «время» (timestamp); набор зависит от выбранной КТ (только добавленные в неё). Доступны все тех. атрибуты КТ; event_time доступен всегда, независимо от наличия в КТ. (28-[US] Добавление поля user_transaction_time)
- Если ни одно правило не сработало, пишется transaction_time первого пришедшего шага; при последующем приходе времени по правилам поле перезаписывается, выч. атрибуты и метрики пересчитываются. (28-[US] Добавление поля user_transaction_time)
- Нумерация и сортировка (4.3.2): строки сортируются автоматически по приоритету, высший всегда выше низшего, при смене приоритетов пересортировка. Приоритеты могут быть прерывными (1,3,4,6 работают). Для выбора доступны приоритеты до максимального+1: при 1,2 — 1,2,3 (независимо от числа КТ); при 1,4 — 1,2,3,4,5; выбор 3 даёт 1,3,4. (28-[US] Добавление поля user_transaction_time)
- При проставлении уже занятого приоритета занимавший его сдвигается +1, следующий +1 и т.д. Пример: 1,2,3,4, для новой КТ ставим 3 → 1,2,3 (новая КТ),4 (был 3),5 (был 4). Удаление КТ — её приоритет остаётся пустым (удалили 2 — остаются 1,3,4...); редактирование КТ — её приоритет пустой (изменили 1 — остаются 2,3,4...); новая КТ — приоритет пустой. (28-[US] Добавление поля user_transaction_time)
- Частные случаи (4.3.1), при правке источника в КТ после настройки UTT (через «Редактировать» в карточке «На мониторинге» и в черновике):
  - «Обновление источника в КТ до новой версии» / «Смена источника в КТ»: UTT не ссылается на тех. атрибут этой КТ — действий нет; ссылается на event_time — действий нет; на другой атрибут — UTT выключается (если был включён), показывается предупреждение (не показывается, если поле не было активно), тех. атрибуты этой КТ в настройках сбрасываются на event_time, приоритет КТ сбрасывается.
  - Источник не менялся (КТ отредактирована): не ссылается или event_time — действий нет; другой атрибут — если маппинг тех. атрибута на бизнес-атрибут ИЛИ бизнес-атрибута на тех. атрибут не изменился — действий нет; изменился — UTT выключается (если был включён), предупреждение (не показывается, если поле не было активно), атрибуты КТ сбрасываются на event_time, приоритет сбрасывается.
  - Удаление КТ: не ссылался (нет правил) — действий нет; ссылался — UTT выключается (если был включён), предупреждение (не показывается, если поле не было активно), настройки КТ пропадают из UTT. (28-[US] Добавление поля user_transaction_time)

### API и интеграции
- Поле используется для вычисляемых атрибутов, расчёта метрик бизнес-сервиса и графиков в Графане. Раздел 6.4.2 «Изменения EP API» в документе пуст. (28-[US] Добавление поля user_transaction_time)
- БД: таблица (тип колонок в документе не заполнен): id (pk) — Id записи; id_table_2 (fk) — Id записи таблицы 2; user_transaction_time_id (fk) — ссылка на айди таблицы user_transaction_time; technical_attribute_id (fk) — ссылка на айди технического атрибута; priority — Приоритет. Таблица: id (pk) — Айди записи; setting_status — Включено или нет; used_min_time — Включена ли настройка «Брать минимальное время event time». (28-[US] Добавление поля user_transaction_time)

### Сообщения и ошибки
- «У контрольной точки "имя кт" изменились настройки источника. Пожалуйста, переконфигурируйте user_transaction_time» — при обновлении/смене источника КТ с правилом UTT по атрибуту не event_time и при изменении маппинга задействованного атрибута. (28-[US] Добавление поля user_transaction_time)
- «Контрольная точка "имя кт" была изменена. Пожалуйста, переконфигурируйте user_transaction_time» — при удалении КТ с правилом в UTT. (28-[US] Добавление поля user_transaction_time)
- «Задайте приоритет минимум для одной контрольной точки либо включите опцию "Минимальное время брать из event_time"» — при сохранении, когда выбран тех. атрибут КТ, а приоритет не выбран. (28-[US] Добавление поля user_transaction_time)

### Сценарии
- Настройка при создании карточки: 1) «Создать карточку мониторинга»; 2) на втором шаге создать КТ, добавить источники, настроить тех. атрибуты и бизнес-маппинг, перевести КТ в «Подключено»; 3) на третьем шаге группировка идентификаторов; 4) на четвёртом шаге (вычисляемые атрибуты) включить свитчер «user transaction time» и нажать «редактировать»; 5) выключить свитчер «минимальное время брать из поля event_time»: а. выставить приоритеты и выбрать тех. атрибуты у всех КТ с приоритетами, «Сохранить» — п.6; б. выбрать тех. атрибут у КТ без приоритета, «Сохранить» — ошибка (п. 5.3); в. выставить приоритеты нескольким КТ без выбора тех. атрибутов, «Сохранить» — п.6; 5.1. если свитчер не выключать и нажать «Сохранить»; 6) пользователь попадает на вкладку «Вычисляемые атрибуты». (28-[US] Добавление поля user_transaction_time)
- Критерии приёмки, создание UTT: свитчер в «вкл» → появляются «Редактировать» и надпись «Минимальное время брать из поля event_time»; «Редактировать» → окно с включённым свитчером; выключение свитчера → доступна настройка UTT; выбор приоритета и тех. атрибута, «Сохранить» → настройка сохранена, переход на таб «Вычисля… (выдержка обрывается). (28-[US] Добавление поля user_transaction_time)
