# Журналирование: настройка логирования и получение логов

> Раздел описывает настройку логирования сервисов ТМБС (варианты выгрузки логов, уровни логирования, форматирование и маскирование http-логов) и способы получения логов по X-Span-Id вручную через Kubernetes или через OpenSearch.

### Описание
- Раздел описывает настройку логирования и получение логов сервисов. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)

### Поля и элементы
- Таблица 5.3.1-1 «Варианты выгрузки логов» (имя / описание / активация): (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
  - STDOUT — Default-вариант. Журналирование работы компонентов сервисов осуществляется по умолчанию в консоль (использование стандартных форматов логирования Spring Boot). Активен по умолчанию.
  - TCP — пишет localhost:5170, там его слушает sidecar и отправляет в ELK. Описание работы представлено в разделе «Интеграция с СС.Журналирование». Активация: указать значение true для переменной окружения TCP_LOGGING_ENABLE.
  - JSON_STDOUT — пишет логи в json в stdout. Активация: «-».
- Параметры logbook.custom (YAML-пример): (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
  - default-settings — настройки по умолчанию для всех контекстов; level: FULL — уровень логирования.
  - obfuscate — маскирование: allowedHeaders — список заголовков, которые будут залогированы (если список пустой — логируются все заголовки), пример: Authorization; headers — список заголовков, которые будут замаскированы, если они будут залогированы, пример: Authorization; parameters — маскирование параметров, пример: secret; paths — маскирование путей, пример: /api/v1/logbook/{userId}/login; fields — маскирование полей http body json, пример: password.
  - max-body-size: -1 — ограничение размера http body.
  - exclude — исключения из логирования контекстов, которые доступны в include, пример: /api/v1/logbook/exclude.
  - include — список контекстов, к которым применяется весь текущий блок; если список пустой — блок применяется ко всем контекстам, пример: /api/v1/logbook/**.
  - overridden-settings — переопределение настроек по умолчанию; settingsName — название переопределённого конфига, все непереопределённые поля берутся из конфига по умолчанию; в примере level: BASIC, obfuscate.paths: /api/v1/logbook/customSettings/{userId}/login, include: /api/v1/logbook/customSettings/**.

### Бизнес-правила и ограничения
- ВАЖНО: переопределённое маскирование добавляется к маскированию по умолчанию, а не заменяет его. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- При уровне логирования BASIC переопределять имеет смысл только маскирование paths. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- Доступные уровни логирования http запросов-ответов: (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
  - NONE – отключено логирование.
  - BASIC – включено логирование методов запроса, URL, кода статуса ответа и времени выполнения.
  - HEADERS – включено логирование основной информации вместе с заголовками запросов и ответов.
  - FULL_WITHOUT_HEADERS – включено логирование тела и метаданных запросов и ответов.
  - FULL – включено логирование заголовков, тела, метаданных запросов и ответов.

### Сценарии
- Шаги настройки логирования: 1. Настроить логирование, опираясь на варианты выгрузки логов (таблица 5.3.1-1). 2. Настроить уровни логирования через переменные окружения LOGGING_LEVEL_ROOT и LOG_LEVEL. 3. Настроить форматирование htttp, например, через переменную окружения LOGBOOK_CUSTOM_DEFAULTSETTINGS_EXCLUDE. Пример настройки в формате YAML приведён в документе; эти настройки можно конвертировать в переменные окружения. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- Получение логов. Предусловия: на стенде Зонтичной cистемы мониторинга открыть devtools; во вкладке Network открыть запрос с ошибкой. В Request URL указывается сервис, к которому относится запрос, а по X-Span-Id можно найти логи сервиса. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- Шаги получения логов вручную: 1. Открыть Kubernetes (например, с помощью IDE Lens). 2. Открыть pod-ы. 3. Найти нужный сервис. 4. Найти в логах по X-Span-Id необходимую информацию. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- Примечание: если один сервис вызывает другой сервис, то необходимо проверить логи вызванного сервиса (выполнить шаги 1 – 4). (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
- Шаги получения логов через OpenSearch: 1. В OpenSearch ввести в строке поиска X-Span-Id. 2. Просмотреть цепочку логов. (Сфера.ТМБС_Руководство_администратора_PPBP-26.3.0-4)
