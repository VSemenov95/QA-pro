# База знаний QA pro: как устроена (v33)

## Слои
1. **Разделы.** Документ режется на фрагменты, модель раскладывает каждый по функциональным разделам. Она видит оглавление всех разделов (до 200 штук) и кладёт сведения в уже существующий раздел, если он про ту же функцию. Выдержки хранятся в `products/<pid>/kb/<id>.parts`.
2. **Сводка раздела** (`synth`). После разбора каждый затронутый раздел пересобирается по выдержкам из всех документов и прежней сводке.
   - Единый текст по подзаголовкам базы знаний, у каждого пункта источник в скобках.
   - `conflicts`: противоречия между документами, в тексте сводки — подзаголовок «Расхождения между документами».
   - `links`: связанные разделы.
   - `summary`: заново по всем документам.
   - Сведения документа, которого больше нет в продукте, из сводки убираются.
   - Документ разобран заново (изменился): в разделе `redo` — его сведения из прежней сводки считаются устаревшими и берутся только из новых выдержек.
3. **«Что агент знает о продукте»** (паспорт продукта). Общий конспект по всем документам. Пополняется после генерации, по кнопке «Изучить документы» и автоматически после разбора новых документов. Если в это время идёт генерация, обновление ждёт её окончания.

## Большие разделы (v33)
- Выдержки в запрос сводки больше не обрезаются.
- Материал до 13 тыс. знаков — один запрос. Больше — сводка по подзаголовкам:
  - подзаголовок, материал которого больше 24 тыс. знаков, сначала сжимается моделью без потери фактов (повторы и лишние слова уходят, значения и тексты остаются, у пунктов — источники, разные значения — отдельными пунктами);
  - затем подзаголовки сводятся группами (вход до 24 тыс., выход до 6 тыс. знаков на запрос) и собираются в одну сводку; расхождения и связи объединяются.
  - Общий объём большой сводки — до 22 тыс. знаков (хранится до 24 тыс.). Ответы готовых шагов помнятся до перезагрузки — повтор после лимита их не повторяет.
- Размер раздела в базе ≤ 240 КБ:
  - при переполнении сначала убираются выдержки, уже сведённые в полную сводку (`synthV = 2`): остаётся отметка «документ, фрагмент» (`cut`), сведения хранит сводка и переносит в следующую;
  - если во время разбора несведённых выдержек набирается больше 60% лимита, раздел сводится сразу («разросся — свожу сейчас»), не дожидаясь конца разбора;
  - самые старые несведённые выдержки уходят только в крайнем случае (`lost`).
- Сохранение выдержек при разборе больше не стирает сводку раздела.
- `read_knowledge_section` отдаёт длинную сводку частями по 6000 знаков (`part`/`parts`).

## Когда пересобираются сводки
- Новый или изменённый документ: сводки разделов, куда он попал или откуда ушли его прежние выдержки.
- Удалён документ: сводки разделов, где он был (при включённом «Разбирать новые документы автоматически»).
- Вручную: баннер «Собрать сводки» (разделы без сводки или с устаревшей сводкой) и «Обновить сводку» на странице раздела.
- Признак свежести: в индексе `meta/kb` у раздела `ph` (хэш выдержек) и `sh` (хэш, по которому собрана сводка). Устарела, если `sh` пустой или `ph ≠ sh`.

## Прогресс
- Разбор: «Разбираю документы по разделам: N из M · фрагментов разобрано: X из Y · разделов: K, новых L · не получилось · сейчас «документ», часть i из n · осталось ≈». Полоса — по фрагментам.
- Сводки: «Собираю сводки разделов: N из M · документов сведено полностью: X из Y · не получилось · большой раздел «…» — шаг k из n · осталось ≈».
- Та же строка — под списком документов в любом режиме. Документы с расхождениями — «расхождений N · Показать» (окно со строками по разделам).

## Ответы на вопросы
- Сначала быстрая модель по вопросу и оглавлению выбирает до 3 разделов «по смыслу» и подбирает синонимы, формулировки из документации и английские варианты.
- Потом локальный отбор по словам вопроса и подобранных терминов: разделы (их сводки), пункты знаний о продукте, до 6 фрагментов документов, доп. контекст, кейсы.
- Ответ — строго по найденному, с источниками.

## Генерация
- В каждый запрос анализа, чек-листа, плана, кейсов, доработки, актуализации и ревью идёт блок «База знаний продукта — разделы по теме».
  - Это сводки разделов по теме запроса из всех документов продукта, включая расшифровки видео, даже если этих документов нет среди отмеченных в запуске.
  - Отбор: слова запроса с весом по редкости (idf), совпадение с названием раздела — втрое больше. До 6 разделов.
  - Лимиты: анализ 3000 знаков, чек-лист и план 7000, кейсы 4500, ревью 3000. В экономном режиме ×0,6. Из длинной сводки берутся строки по теме запроса.
- Правила для модели:
  - требования выделяются только из документов запуска;
  - по расхождениям анализ задаёт вопросы;
  - при конфликте приоритет у требований запуска;
  - спорное из «Расхождений» не выдаётся за факт.
- В агентном режиме (большие документы) у модели есть инструменты `search_knowledge_base` и `read_knowledge_section`.
- Перед запуском база знаний загружается целиком. В журнале шага «Документы» видно, сколько разделов учтено.
- Кэш анализа учитывает блок базы знаний: изменилась сводка по теме фрагмента — анализ повторяется.

## Стоимость
- Разбор: один запрос на фрагмент документа (до 24 тыс. знаков).
- Сводки: один запрос на обычный раздел; большой — по запросу на каждые ~24 тыс. знаков сжимаемого подзаголовка плюс 1–4 запроса на группы подзаголовков (раздел в 140 тыс. знаков ≈ 16 запросов).
- Знания о продукте: один запрос на фрагмент документов.
- Вопрос: плюс один быстрый запрос на поиск по смыслу.
