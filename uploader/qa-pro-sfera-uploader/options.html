Настройки загрузчика

QA pro → Сфера ФТ

Загрузчик работает от вашего имени: берёт вход из этой Сферы, открытой в браузере. Для адреса, отличного от sfera-t1.ru, браузер попросит разрешение.

По одному адресу в строке. QA pro на claude.ai, с локального компьютера (file://) и с localhost загрузчик видит и так. Для файлов с диска включите в настройках расширения «Разрешить доступ к URL файлов».

Задания из приложения Claude для компьютера

В приложении Claude нет расширений браузера. Связь идёт через локальный мост qa-pro-bridge — расширение приложения Claude: QA pro передаёт ему кейсы, а загрузчик забирает их и открывает своё окно здесь. Мост скачивается в QA pro: шестерёнка → ТМС.

Запасной путь без моста

Задание из приложения может принять QA pro, открытый во вкладке этого браузера. Включите, чтобы загрузчик сам держал такую вкладку: откроет её закреплённой при запуске браузера и не даст выгрузить из памяти.

API Сферы для QA pro

QA pro заводит дефекты в Сфера.Задачи и читает репозитории автотестов через загрузчик — от вашего имени. Адреса этих операций зависят от инсталляции Сферы, поэтому их задают здесь. Как заполнить: в Сфере откройте DevTools → Network, выполните действие вручную (создайте дефект, откройте файл в репозитории) и перенесите адрес, метод и тело запроса в описание операции.

Если QA pro пишет «загрузчик не найден»

  1. Обновите страницу QA pro (Ctrl+F5) или нажмите «Подключить к открытым вкладкам».
  2. QA pro должен быть открыт в этом браузере, а не в приложении Claude для компьютера: там расширений нет.
  3. На странице расширения в chrome://extensions → «Сведения» → «Доступ к сайтам» не должно стоять «По нажатию».
  4. Если не помогло — включите режим ниже: тогда загрузчик увидит QA pro на любом адресе.
