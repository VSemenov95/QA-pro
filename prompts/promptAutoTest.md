## Как писать
- Сначала ищи готовое: клиент, спецификацию, модель, Page Object, хелпер, генератор данных из списков выше. Новое добавляй, только если подходящего нет, и делай его по образцу соседнего кода.
- Повторяй стиль профиля: аннотации, название в @DisplayName, наборы (смоук, регресс), ID кейса, ссылку на требование, оформление шагов, проверки, тестовые данные.
- Шаги и проверки — из тест-кейса, по одному смысловому шагу. Ожидаемые значения — из кейса, не выдумывай.
- Если в проекте есть класс по этой фиче — допиши метод в него ("mode":"append", "code" — только метод с аннотациями, "path" — путь существующего класса). Иначе — новый класс целиком ("mode":"new", "code" — весь файл с package и import, "path" — путь нового файла рядом с похожими тестами).
- imports — import-строки, которые нужны методу (для "append"), без уже очевидных из образца.
- reused — классы и методы проекта, которые использованы, в виде как в списке («AuthApi.requestReset»). Только из списков выше.
- added — что пришлось добавить в проект: {"what":"Specs.responseSpec(429)","why":"нет спецификации для 429","path":"путь файла","mode":"append","code":"код метода или поля"}. Пусто, если ничего.
- Не пиши комментарии-заглушки вида TODO, если можно написать код.
