# QA pro

Генерация тест-кейсов и чек-листов из документации (ТЗ, требования, спецификации). Агент разбирает документы, выделяет требования, строит план, пишет кейсы по шаблонам команды, проверяет их ревьюером и передаёт в проект или в Сферу ФТ.

Работает в браузере и в приложении Claude для компьютера. Файлы документов в браузере не загружаются на сервер: разбор идёт на вашем устройстве.

## Возможности

- **Генерация.** Анализ требований, чек-лист («Смоук» и «Регресс»), план, тест-кейсы API, UI и E2E по шаблонам команды.
- **Черновик.** Кейсы сначала попадают в черновик и проходят ревью. В проект они добавляются отдельной кнопкой.
- **Перегенерация по правилам.** Заменяет кейсы черновика новыми, сгенерированными с текущими правилами. База знаний и паспорт продукта при этом не используются.
- **Сокращение тестов.** Вы задаёте, сколько кейсов оставить. Система выбирает самые важные по документации и сохраняет покрытие требований. Если покрытие при таком числе не сохранить, система предупреждает и ждёт подтверждения.
- **База знаний продукта.** Разделы и паспорт продукта копятся между запусками и подставляются в запросы.
- **Актуализация.** Сверка и обновление уже существующих кейсов из файла.
- **Ревью.** Ревьюер проверяет кейсы и чек-лист по документации, шаблонам и правилам команды. Показываются критичные и существенные замечания; мелкие — одной строкой на пакет. Замечания можно исправить, отклонить или вернуть.
- **Строгий режим.** Нарушения правил команды при ревью исправляет модель (это тратит запросы).
- **Спецификации OpenAPI / Swagger.** Загрузите `.json` или `.yaml`, укажите API в поле «API, для которого нужны тесты» — в документ попадут только нужные эндпоинты.
- **Экспорт.** Формат задаётся словами в настройках (CSV, XLSX, JSON, XML, Markdown, TXT); без формата выгружается стандартный JSON.
- **Продукт.** Переименование, экспорт и импорт продукта целиком, удаление продукта.
- **Загрузка в Сферу ФТ.** Через расширение Chrome или мост в приложении Claude.

## Версия для браузера

### Что нужно

- Google Chrome (или Chromium) последней версии.
- Python 3 для сборки (только стандартная библиотека).

### 1. Собрать приложение

```bash
git clone https://github.com/VSemenov95/QA-pro.git
cd QA-pro
python3 build.py
```

После сборки появятся `qa-pro.html` (готовое приложение в одном файле) и `tc-agent.html` (то же приложение для тестов). Файлы `app.js`, `tc-agent.html` и `qa-pro.html` в git не попадают, их всегда собирают заново.

### 2. Открыть в Chrome

Самый простой способ: дважды щёлкнуть по `qa-pro.html`. Если какая-то функция не работает при открытии файла, поднимите локальный сервер:

```bash
python3 -m http.server 8000
```

и откройте `http://localhost:8000/qa-pro.html`.

### 3. Настроить модель

Откройте шестерёнку в правом верхнем углу → вкладка **Модель**. Выберите провайдера и модель. Если выбран Claude, запросы расходуют лимит вашего аккаунта.

**Модель по этапам.** Там же, в блоке «Модель по этапам», для каждого этапа можно выбрать свою модель: «как основная», быстрая (класс Haiku), стандартная (Sonnet) или максимальная (Opus). Этапов четыре:

| Этап | Что входит | Рекомендуем |
|---|---|---|
| Анализ, план и сверка | требования, чек-лист, план проверок, сверка кейсов при актуализации | стандартная |
| Тест-кейсы | написание, доработка и актуализация кейсов | стандартная |
| Ревью | проверка кейсов и пунктов чек-листа | быстрая |
| Служебные шаги | покрытие, знания о продукте, справка по базе знаний, сокращение набора, формат экспорта | быстрая |

Рядом с каждым этапом приложение объясняет, почему рекомендует именно этот уровень. Кнопка **Применить рекомендации** ставит такую раскладку одним нажатием, **Все этапы — как основная** возвращает прежнее поведение. Выбор по этапам сильнее экономного режима.

Рекомендации основаны на замере одного тестового ТЗ (141 кейс, 73 вызова): генерация даёт около 45% входных токенов и 53% выходных, ревью — ещё 47% входных. Быстрая модель на входе примерно в 20 раз дешевле стандартной (Haiku 5.5 — $0,10, Sonnet 5.5 — $2 за 1 млн токенов, цены на октябрь 2026). Качество ревью на быстрой модели мы не сравнивали, поэтому проверьте раскладку на своих документах.

Уровень переключается для аккаунта Claude и для подключения по ключу Claude. Для ChatGPT и Иннокода модель одна, и выбор по этапам недоступен.

### 4. Первый запуск

1. Нажмите **Новый продукт** или выберите существующий. Для пробы есть кнопка **Добавить пример ТЗ**.
2. Добавьте документы (`.docx`, `.pdf`, `.xlsx`, `.csv`, `.txt`, `.md`; `.json` и `.yaml` — только спецификации OpenAPI или Swagger) в блоке «Документы». Видео не принимаются.
3. Выберите виды тестов и что генерировать (тест-кейсы, чек-лист или оба).
4. Нажмите **Сгенерировать тест-кейсы**.
5. Когда генерация закончится, проверьте черновик на вкладке **Черновик** и добавьте его в проект.

## Версия в приложении Claude для компьютера

В приложении Claude QA pro открывается как артефакт (страница на claude.ai). Для загрузки в Сферу ФТ нужен мост `qa-pro-bridge`.

### 1. Открыть QA pro

Откройте в приложении Claude ссылку на артефакт QA pro. Её выдаёт команда или владелец проекта. Страница работает так же, как версия для браузера, но не требует сборки.

### 2. Установить мост

Мост — это расширение `.mcpb` (архив с `manifest.json` в корне). Его можно скачать прямо из QA pro: в блоке загрузки в Сферу нажмите **Скачать мост (.mcpb)**. Либо соберите самостоятельно из папки `bridge/qa-pro-bridge`:

```bash
cd bridge/qa-pro-bridge && zip -r ../qa-pro-bridge.mcpb . && cd ../..
```

Дальше:

1. Откройте файл `qa-pro-bridge.mcpb` двойным щелчком или в приложении Claude через **Настройки → Расширения** (перетащите файл в окно).
2. Подтвердите установку.
4. Держите приложение Claude открытым: мост работает только пока оно запущено.

Не меняйте отображаемое имя моста в `manifest.json`: по нему QA pro находит мост.

### 3. Проверить

В QA pro нажмите **Проверить мост**. Страница покажет, найден ли мост и подключён ли загрузчик в Сферу ФТ из Chrome.

### Ограничения

- Новые инструменты моста страница в приложении Claude может использовать только после публикации из локальной сессии Claude. Если вы видите сообщение «ещё не разрешено», опубликуйте страницу заново из локальной сессии.
- Микрофон в приложении Claude может быть недоступен внутри страницы. В этом случае используйте версию для браузера.

## Загрузка в Сферу ФТ

Тест-кейсы передаются в Сферу двумя путями.

### Расширение Chrome (версия для браузера)

1. Откройте `chrome://extensions`, включите **Режим разработчика** и нажмите **Загрузить распакованное расширение**.
2. Выберите папку `uploader/qa-pro-sfera-uploader`.
3. Войдите в Сферу ФТ в этом же браузере. Расширение берёт вход из cookie `ACCESS_TOKEN`.
4. В QA pro нажмите **Загрузить в Сферу ФТ**, выберите раздел и подтвердите загрузку. Загрузчик для Chrome можно скачать кнопкой **Скачать загрузчик (.zip)**.

Смоук-кейсы получают метку `SMOKE`, регресс — поле «Регрессионный». Метку `AI_gen` не ставим.

### Мост (приложение Claude)

Мост передаёт кейсы загрузчику в Chrome, если он установлен и подключён. Используйте актуальные версии загрузчика и моста: они поставляются вместе с QA pro. Подробности в [`docs/sfera-uploader.md`](docs/sfera-uploader.md).

## Частые вопросы

**Почему кнопок «Перегенерировать по правилам» и «Сократить количество тестов» нет?**
Они появляются, когда генерация завершилась и результат лежит в черновике с кейсами. «Сократить» требует минимум два кейса.

**Почему после правки `prompts/*.md` ничего не изменилось?**
Файлы подставляются при сборке. Запустите `python3 build.py` и обновите страницу.

**Почему мост «не найден»?**
Проверьте, что приложение Claude открыто и мост установлен и включён в **Настройках → Расширениях**. Если установлена старая версия, обновите её.

**Как оформить тело запроса, сообщение Kafka или SQL в предусловиях и шагах?**
Модель пишет такие данные блоком кода: строка с тремя обратными кавычками (после них можно указать язык), сам текст и закрывающая строка с тремя кавычками. В кейсе это обычный текст. При выгрузке в Сферу ФТ (загрузка и файл `qa-pro-sfera.json`) блок превращается в `<p>пояснение</p>`, пустой `<p>`, `<pre data-id style>` и пустой `<p>`. В XLSX кавычки убираются, остаётся только текст. `<pre>` из выгрузок ТМС при загрузке файла превращается в такой же блок. Правило для агента можно формулировать словами («тело запроса оформляй блоком кода»); описывать HTML в нём не нужно.

**Почему при актуализации часть кейсов раньше пропускалась?**
Модель нумеровала кейсы в пакете с единицы, а приложение искало их по номерам из заголовков («### #11»). Из-за несовпадения пакет считался неполным и отбрасывался. Теперь приложение сопоставляет ответы по номеру из заголовка, затем по порядковому номеру в пакете и по позиции, если вернулось столько же кейсов, а в промптах номер из заголовка указан явно.

**Как описывается сообщение в Kafka?**
Без метода: только топик, ключ (если важен) и тело сообщения, без POST, PUT и «методом…» — ни в названии, ни в шагах, ни в блоке кода. Правило лежит в `rules/kafka.md` и подставляется в промпты генерации, актуализации, доработки и исправления.

**Какие значения у приоритета?**
Только четыре: `P1_LOW`, `P2_MEDIUM`, `P3_HIGH`, `P4_CRITICAL`. Старые записи (`High`, `Medium`, `Low`, `high`, `medium`, `low`) приводятся к ним при сохранении. Правило лежит в `rules/priority.md`. В Test IT приоритет `Critical` для P4 и в Qase приоритет 1 для P3 и P4 — предположения, проверьте по документации систем.

В предусловиях кейсов не пишется, что сервис работает: это подразумевается (`rules/preconditions.md`).

**Как описывается вызов API в шаге?**
Так: «Вызвать POST /эндпоинт с телом:», пустая строка и блок кода с телом запроса. Для запроса без тела — «Вызвать GET /эндпоинт». Правило лежит в `rules/api-call.md`.

**Где посмотреть все тест-кейсы продукта, например после загрузки продукта?**
Вкладка **Тест-кейсы**. Когда запуск не открыт, на ней показаны все кейсы продукта, добавленные в проект, а сразу после кнопки **Импорт** вкладка открывается сама. Кейсы сгруппированы в разделы по документам, из которых они написаны (документ определяется по требованиям кейса); кейсы без требований попадают в раздел «Без документа». Название раздела можно изменить: карандаш справа от названия, **Enter** — сохранить, **Esc** — отмена, **Как документ** — вернуть название документа. Названия хранятся в продукте и выгружаются вместе с ним. Нажмите на кейс, чтобы открыть запуск с этим кейсом. Когда открыт запуск, переключатель **Этот запуск / Весь продукт** выбирает, какие кейсы показывать; в списке запуска кейсы тоже идут по разделам.

**Какие метки стоят в названиях тест-кейсов?**
Название начинается с метки вида теста: `[BE]` — API, `[Kafka]` — проверка сообщений Kafka (вместо `[BE]`), `[FE]` — UI, `[E2E]` — сквозные сценарии. Метку ставит модель по правилу `rules/title-tags.md`, а при генерации, доработке, актуализации и исправлении по ответам приложение само проверяет её и при необходимости дописывает или исправляет (например, `[UI]` → `[FE]`). Вручную правленые названия не меняются, но ревью предупредит, если метки нет. Метки заданы в `TITLE_TAG` и `KAFKA_TAG` (`app1.js`).

**Где хранятся данные?**
В версии для браузера — в хранилище самого браузера и в базе, если она подключена. Документы и кейсы на сервер QA pro не отправляются. Запросы к модели уходят в выбранного провайдера.
