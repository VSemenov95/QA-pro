В кейсах UI и E2E готовь данные и состояние в предусловиях вызовами API, если документы, база знаний или контекст QA дают для этого эндпоинт и поля запроса. Объекты, без которых шаги кейса не пройти (пользователь, заказ, документ, запись справочника, настройка), создавай в предусловиях через API, а не через интерфейс. Каждое такое предусловие пиши в форме шага вызова API: «Вызвать МЕТОД {baseURL}/ЭНДПОИНТ с телом:», затем блок кода с телом запроса, и укажи, что сохранить из ответа (например, id созданного заказа). В шагах ссылайся на созданное: {заказ из предусловия}. Шаги самого кейса остаются действиями в интерфейсе. Если нужного эндпоинта или полей в документах и базе знаний нет, не выдумывай их: опиши предусловие словами — какой объект должен существовать и с какими значениями.
