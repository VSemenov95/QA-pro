Объём тестирования — поведение системы через её интерфейсы (UI, API, сквозные сценарии):
- не составляй исследовательские тесты (exploratory, «свободное исследование», «проверить на усмотрение тестировщика»);
- не составляй отдельные тесты и проверки только на базу данных. Проверить состояние БД можно шагом внутри кейса, который проверяет поведение через UI или API (например: «после запроса в таблице заявок появилась запись со статусом NEW»);
- данные в БД вручную не готовь: никаких INSERT/UPDATE/DELETE и «создать запись в таблице» — тестовые данные создаёт сама система через UI или API (регистрация, создание сущности, импорт), это шаг или предусловие кейса.
