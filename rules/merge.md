Объединяй похожие по смыслу проверки в одну: если несколько значений относятся к одному классу эквивалентности и дают один и тот же ожидаемый результат, это одна проверка (один кейс) с перечнем тестовых данных. Пример: «Email неверного формата (без @, без домена, с пробелом) — ошибка «Введите корректный email»» вместо трёх отдельных. Отдельные проверки — только когда ожидаемый результат различается (другой текст ошибки, код ответа, поведение) или это граница диапазона (минимум, максимум, на единицу за ними). Не дублируй одну проверку на разных уровнях: валидацию и коды ошибок проверяй в API, а в UI — только то, что видно пользователю.
