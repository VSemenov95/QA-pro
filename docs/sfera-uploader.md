# Загрузка в Сферу ФТ: загрузчик и мост

Загрузка тест-кейсов из QA pro в Сферу ФТ идёт через расширение Chrome «QA pro — загрузчик в Сферу ФТ». Оно сделано из QA Toolkit, от которого оставлен только загрузчик. Вход в Сферу берётся из открытой Сферы (cookie ACCESS_TOKEN), токен вводить не нужно.

## Метки
- Смоук → метка `SMOKE`.
- Регресс → родное поле Сферы «Регрессионный» (`ti_regressive: true`).
- Метку `AI_gen` не ставим.

## Как QA pro передаёт кейсы (по приоритету)
1. **QA pro в Chrome** (claude.ai или автономный файл).
   - Расширение встраивает в окно QA pro свой скрипт-посредник.
   - Сообщения идут по двум каналам:
     - `window.postMessage`;
     - события документа `qa-pro:to-uploader` / `qa-pro:from-uploader`.
   - Расширение открывает своё окно: там выбирается раздел и подтверждается загрузка.
2. **QA pro в приложении Claude: локальный мост `qa-pro-bridge`.**
   - Мост — расширение приложения Claude (`.mcpb`), MCP-сервер на Node.js без зависимостей.
   - **Имя для `host:`.** Приложение Claude называет мост из `.mcpb` по отображаемому имени: всё, кроме `[A-Za-z0-9_-]`, заменяется на `_`.
     - «QA pro — мост к загрузчику Сферы ФТ» → `host:QA_pro_____________________________` (35 символов после `host:`).
     - При ручной настройке в `claude_desktop_config.json` имя — ключ конфига `qa-pro-bridge`.
     - В манифесте артефакта объявлены оба имени. Страница пробует их по очереди и запоминает рабочее (`localStorage` `qapro.hostname`).
     - Отображаемое имя в `manifest.json` моста не менять: изменится имя сервера, и QA pro перестанет его находить.
   - Инструменты:
     - `ping` и `sfera_job` — только чтение;
     - `sfera_upload` и `sfera_cancel` — приложение может просить подтверждение.
   - Мост (с версии 1.1) состоит из двух частей:
     - `server/index.js` — MCP-обёртка, её запускает приложение Claude;
     - `server/core.js` — ядро, отдельный фоновый процесс: переживает выход из приложения, задания хранит в `~/.qa-pro-bridge/jobs.json`, секрет для обёртки — в `~/.qa-pro-bridge/token`.
   - Обёртка находит ядро (`/health`), заменяет ядро старой версии (`/shutdown`), а если отдельный процесс запустить нельзя, держит ядро у себя.
   - Ядро завершается само, если приложение Claude не появлялось трое суток.
   - Ядро слушает `127.0.0.1:47321`:
     - WebSocket `/ext` — только для расширения браузера;
     - `/rpc` — только с секретом и без заголовка Origin.
   - Загрузчик (с версии 1.3) держит с мостом постоянное соединение:
     - сначала тихо проверяет `/health`;
     - раз в 30 секунд переподключается;
     - сердцебиение моста не даёт фоновой части расширения уснуть.
   - Если загрузчик в момент отправки не подключён, задание ждёт в мосту и уходит, как только загрузчик подключится.
   - `sfera_job` умеет ждать изменения до 25 секунд (долгий опрос).
   - После перезагрузки страницы QA pro продолжает следить за заданием (`localStorage` `qapro.hostjob`).
3. **Без моста: через базу артефакта.**
   - Задание кладётся в личную часть базы (`data/users/<id>/sfjob-*`).
   - QA pro во вкладке Chrome с загрузчиком подхватывает его (захват через `acquire`).
   - Результат применяет только устройство-отправитель (`fromDevice`).
   - Вкладка Chrome отмечает, что она на связи, документом `sfera-relay`.
4. **Вручную:** «Скачать JSON для загрузчика» (`qa-pro/sfera-v1`), потом выбрать этот файл в окне загрузчика.

## Фоновый исполнитель (QA pro)
- QA pro во вкладке браузера (лучше Chrome с загрузчиком) включается как фоновый исполнитель: шестерёнка → «Фон». Флаг хранится в `localStorage` `qapro.worker`; в приложении Claude этот режим недоступен.
- Что подхватывает исполнитель:
  - **Генерация.** Запуск со статусом `running`, у которого нет живого пульса: окно при закрытии пишет `hb: 0`, иначе срабатывает `HB_STALE` = 90 с. Исполнитель захватывает запуск через `acquire`, открывает его и продолжает (`resumeRun`). Если модель окна-источника здесь недоступна, берёт свою.
  - **База знаний.** Неразобранные документы продукта из сессии. Разбор продукта идёт под арендой `products/<pid>/meta/kbjob` на 120 с, её продлевает каждый фрагмент.
  - **Задания Сферы** через базу (`sfjob-*`).
- Присутствие исполнителя — документ `data/users/<id>/worker`, обновляется раз в 50 с. Пока исполнитель ничего не делает, он не пишет личную сессию.
- Загрузчик раз в 20–30 с шлёт вкладкам QA pro `QA_TICK`: фоновую вкладку это будит, и её пульс не отстаёт.

## Настройки загрузчика (v1.4)
- Сообщения для моста (окно открыто, результат, отмена) копятся в `chrome.storage.local`, пока мост не подтвердит их (`ack`).
- Адрес Сферы и свои адреса QA pro.
- Связь с приложением Claude через мост: включение, порт, состояние.
- «Держать QA pro открытым» — закреплённая вкладка для запасного пути 3.
- «Работать на любых сайтах» — на случай, если загрузчик не видит окно QA pro.
- Журнал обращений QA pro.

## Расшифровка видео в базу знаний (мост 1.2, загрузчик 1.5, QA pro v27)
- «База знаний → Материалы» принимает `.mp4` (до 3 часов). Видео не сохраняется: хранилище файлов артефакта (`assets`) убрано из QA pro.
- Конвейер на странице: звук → речь → кадры → экран → итоги → документ продукта.
  - **Звук.** Свой разбор MP4 (moov/stbl) и WebCodecs `AudioDecoder` (AAC, MP3, Opus); файл читается окнами до 24 МБ, целиком в память не грузится. Фрагментированный MP4 или неизвестный кодек — запасной путь `decodeAudioData` (файлы до 600 МБ). Дальше 16 кГц моно → μ-law.
  - **Нарезка по паузам:** фрагменты 18–28 с, тишина длиннее 2 с пропускается, фрагменты без речи не отправляются.
  - **Речь** распознаёт Whisper в мосте на компьютере пользователя (`asr_prepare` / `asr_status` / `asr_transcribe`). Модель: small (≈250 МБ, по умолчанию) или base (≈80 МБ). Язык: русский, английский или «русский и английский вперемешку» — язык определяется для каждого фрагмента, выбор только из ru/en.
  - **Кадры:** смена сцены (изменилось ≥1,5% точек), до 24 JPEG. Описывает модель QA pro: Claude — через `sample` с `images`, ChatGPT — `image_url`, Claude по ключу — `image`.
  - **Итоги:** «Главное», требования и правила, решения, открытые вопросы.
- Результат — документ продукта «Видео — <имя>.md» (`source: 'video'`, метаданные в `video`): разделы «Главное из видео», «Что показано на экране», «Расшифровка речи» с метками [мм:сс]. Документ всегда ставится в разбор базы знаний и по умолчанию отмечен для генерации.
- Как страница добирается до моста:
  - **QA pro в Chrome** (claude.ai или автономный): страница → `bridge.js` (`SFERA_RPC`) → фон загрузчика (`BRIDGE_RPC`) → WebSocket `{t:'rpc'}` → ядро моста. Звук в очередь не кладётся. Ядро пускает из браузера только `ping` и `asr_*`.
  - **QA pro в приложении Claude:** `host:…` → `asr_*`. В манифесте артефакта v27 этих инструментов **нет**: облачная сессия не может добавить локальные инструменты, это делается публикацией из локальной сессии Claude. Без них страница в приложении объясняет, что видео пока надо разбирать в Chrome.
- Мост 1.2:
  - Распознаватель — transformers.js 4.3.0 и onnxruntime-web (WebAssembly) из npm с проверкой sha512, ≈36 МБ при первом запуске.
  - Модель — с Hugging Face или зеркала (`hf_mirror` в настройках моста); можно положить в `~/.qa-pro-bridge/models/Xenova/whisper-small/`.
  - Whisper работает в отдельном потоке (`asr-worker.js`): ядро во время распознавания отвечает за ~0,1 с, а не замирает.
  - Защита от «зацикливания» Whisper (проверка по степени сжатия текста), лимит 320 токенов на фрагмент.

## Проверено на имитации (видео, run24 + bridge_asr.js)
- Настоящий мост 1.2 с Whisper base, путь приложения Claude (`host`) и путь Chrome через настоящий загрузчик 1.5. Видео 38 с (AV1 + Opus): 3 фрагмента речи, 2–3 экрана, расшифровка за 22–31 с.
- Расшифровка сохраняется в продукт, попадает в базу знаний и в запросы генерации (план и тест-кейсы).
- Отмена посреди распознавания; удаление расшифровки (метаданные и части документа).
- Смешанная русско-английская речь в режиме «вперемешку» распознана верно.
- Фрагментированный MP4 обработан запасным путём.
- В тестовом Chromium нет H.264/AAC: страница даёт понятную ошибку. В Chrome и в приложении Claude эти кодеки есть, но живьём на компьютере пользователя не проверено.
- Нет моста или нет разрешения `asr_*` — страница объясняет, что делать, и даёт кнопки «Скачать мост» / «Скачать загрузчик».

## Проверено на имитации (фон)
- Окно приложения закрыли посреди генерации, исполнитель её доделал. После повторного открытия результат на месте.
- Документ добавили и закрыли окно — исполнитель разобрал его в базу знаний.
- Приложение закрыли (обёртку остановили), ядро осталось, загрузчик загрузил кейсы. После повторного открытия отметки применились.

## Проверено на компьютере пользователя
- Windows, приложение Claude 2.19675 (Electron 44, Node 24).
- Мост из `.mcpb` запущен в приложении Claude, `ping` прошёл через связь сессии с компьютером.
- На 6 октября установлен мост 1.0.0 и загрузчик 1.3.0. Для расшифровки видео нужны мост 1.2 и загрузчик 1.5.

## Не проверено на живом окружении
- Вызов моста из самой страницы QA pro в приложении Claude (после исправления имени).
- Видит ли расширение окно артефакта на живом claude.ai.
- Скачивание Whisper small с Hugging Face (в песочнице закрыт), скорость small на компьютере пользователя.
- Описание кадров через `sample` с `images` на живом claude.ai.
