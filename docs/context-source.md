# Источник контекста: репозиторий или папка вместо базы QA pro

QA pro может брать правила, шаблоны, память агента, знания о продукте и базу знаний не из своего хранилища, а из **git-репозитория** или **папки на компьютере**. Интерфейс остаётся прежним: вы открываете QA pro на claude.ai под своей учёткой Claude, а в настройках указываете, откуда тянуть контекст. Изменения, сделанные в QA pro (правила, шаблоны, замечания агенту, паспорт продукта, доп. контекст), записываются обратно в файлы. В удалённый репозиторий они уходят отдельной веткой, чтобы правки правил проходили ревью.

> Бета-функция ветки `feature/context-source`. В `main` не влита.

## 1. Что выбрать

Источник выбирается для каждого продукта: шестерёнка → вкладка **«Контекст»**. Настройка личная, коллеги выбирают источник сами (у каждого своя папка на компьютере).

| Источник | Где лежат файлы | Чтение и запись | Что нужно установить |
|---|---|---|---|
| **База QA pro** | хранилище страницы на claude.ai | напрямую | ничего (как сейчас) |
| **Папка на компьютере** | любая папка или ваш git-клон | мост `qa-pro-bridge` | браузер: загрузчик 1.8 и ядро моста; приложение Claude: мост 1.5 |
| **Git-репозиторий** | удалённый репозиторий (GitHub, GitLab, Сфера — любой git по https или ssh) | мост клонирует его на компьютер и работает с клоном | то же, что для папки, и git на компьютере |
| **GitHub без моста** | репозиторий на GitHub | загрузчик ходит в API GitHub по токену | только загрузчик 1.8 и токен GitHub |
| **Папка только для чтения** | папка на компьютере | файлы читаются в браузере при выборе папки | ничего; изменения не записываются |

Что рекомендуем:

- **Для команды**: git-репозиторий с контекстом (в GitHub, GitLab или Сфере), источник **«Git-репозиторий»**. Правки идут веткой и запросом на слияние.
- **Для черновиков и данных, которые нельзя выносить**: **«Папка на компьютере»**.
- **Чтобы попробовать без установки моста**: **«GitHub без моста»** или **«Папка только для чтения»**.

## 2. Раскладка файлов

Всё — обычные Markdown-файлы: их читают и люди, и модель. Можно держать контекст в подпапке репозитория (поле «Подпапка контекста»).

```
CLAUDE.md                          порядок работы — для Claude Code и людей (QA pro создаёт при выгрузке)
rules/
  generation.md                    правила для агента
  review.md                        правила ревью
templates/
  api.md  ui.md  e2e.md            шаблоны кейсов
  export.md                        формат экспорта
knowledge/
  *.md                             общая база знаний для всех продуктов
products/
  <папка продукта>/
    passport.md                    знания о продукте (паспорт)
    context.md                     доп. контекст QA
    lessons.md                     память агента
    kb/*.md                        база знаний продукта
```

«Папка продукта» по умолчанию — название продукта латиницей или кириллицей через дефис (например `мой-продукт`), её можно задать вручную, например `lk`.

**Правила** (`rules/*.md`, `templates/export.md`) — свободный текст. Строка-заголовок `# Правила для агента` (`# Правила ревью`, `# Формат экспорта`) необязательна и в запрос не попадает.

**Шаблон** (`templates/api.md` и др.) — в том же формате, что и `templates/*.md` в репозитории QA pro:

````markdown
# Шаблон API

idPrefix: API-

## Правила

- Один тест-кейс проверяет один эндпоинт и одну ситуацию.

## Образец

```json
{ "id": "API-001", "title": "[BE] POST /api/v1/… — …", "priority": "P3_HIGH", "steps": [] }
```
````

Если в файле шаблона нет блока ```` ```json ````, QA pro использует шаблон команды и пишет предупреждение во вкладке «Контекст».

**Память агента** (`lessons.md`) — правило на строку, метка необязательна (без метки — для генерации):

```markdown
- [генерация] Email в шагах — только test@example.ru
- [ревью] Негативный кейс без кода ошибки — замечание
- [оба] Название экрана — дословно из макета
```

**Доп. контекст** (`context.md`) — разделы `## Для всех`, `## API`, `## UI`, `## E2E`, как вкладки поля «Доп. контекст» в QA pro.

**База знаний** — каждый файл в `knowledge/` и `products/<папка>/kb/` становится разделом с названием из первого заголовка `#`. Файл длиннее 8 000 знаков делится на разделы по заголовкам `##` («Платежи › Возвраты»). В каждый запрос попадают только разделы по теме — по тому же отбору, что и база знаний QA pro.

Чего в источнике нет, QA pro берёт из своей базы: например, если в репозитории только `rules/generation.md`, шаблоны и память остаются командными.

## 3. Установка: QA pro в браузере

QA pro открыт на claude.ai в Chrome, Edge или Яндекс Браузере. Запросы к модели идут от вашей учётки Claude.

### 3.1. Загрузчик 1.8

1. QA pro → шестерёнка → **ТМС** → **«Скачать загрузчик»**, распакуйте архив.
2. `chrome://extensions` → включите «Режим разработчика» → **«Загрузить распакованное»** → папка `qa-pro-sfera-uploader` (если загрузчик уже стоит — **«Обновить»**).
3. Обновите страницу QA pro (Ctrl+F5).

Для **«GitHub без моста»** этого достаточно. Дальше — правый клик по значку загрузчика → **«Параметры»** → раздел **«Контекст QA pro»**:

- **Токен GitHub** — fine-grained токен с доступом только к репозиторию контекста: *Repository permissions → Contents: Read and write*. Токен хранится в загрузчике, страница QA pro его не получает.
- **Адрес API GitHub** — `https://api.github.com`; для GitHub Enterprise — `https://github.company.ru/api/v3` (браузер попросит разрешение на адрес).

### 3.2. Ядро моста (для папки и git)

Папки на компьютере и git браузеру недоступны, поэтому с ними работает ядро моста `qa-pro-bridge` — небольшая программа на Node.js. Если на компьютере стоит приложение Claude с мостом 1.5 и оно запущено, ядро уже работает, этот шаг можно пропустить.

1. Установите **Node.js 18** или новее (`node --version`) и **git** (`git --version`) — git нужен только для источника «Git-репозиторий» и кнопок pull/push.
2. QA pro → шестерёнка → **ТМС** → **«Скачать мост»**. Файл `qa-pro-bridge.mcpb` — это zip-архив: переименуйте в `.zip` и распакуйте, например, в `C:\tools\qa-pro-bridge` или `~/tools/qa-pro-bridge`.
3. Запустите ядро:
   - Windows: двойной щелчок по `start-core.cmd` (окно можно свернуть);
   - macOS и Linux: `sh ~/tools/qa-pro-bridge/start-core.sh`;
   - или напрямую: `node server/core.js --keep`.
4. Проверьте: откройте `http://127.0.0.1:47321/health` — там `"version":"1.5.0"` и `"keep":true`. В параметрах загрузчика в разделе «Контекст QA pro» должно быть **«Мост подключён»** (загрузчик подключается сам раз в 30 секунд).

`--keep` — ядро не завершается само. Без него оно закрывается, если трое суток к нему никто не обращался.

**Автозапуск**, чтобы не запускать вручную:

- **Windows**: `Win+R` → `shell:startup` → положите туда ярлык на `start-core.cmd`.
- **macOS**: файл `~/Library/LaunchAgents/ru.qa-pro.bridge.plist`, затем `launchctl load ~/Library/LaunchAgents/ru.qa-pro.bridge.plist`:

  ```xml
  <?xml version="1.0" encoding="UTF-8"?>
  <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
  <plist version="1.0"><dict>
    <key>Label</key><string>ru.qa-pro.bridge</string>
    <key>ProgramArguments</key><array>
      <string>/usr/local/bin/node</string><string>/Users/ВЫ/tools/qa-pro-bridge/server/core.js</string><string>--keep</string>
    </array>
    <key>RunAtLoad</key><true/><key>KeepAlive</key><true/>
  </dict></plist>
  ```

  Путь к node — из `which node`.
- **Linux**: `~/.config/systemd/user/qa-pro-bridge.service`, затем `systemctl --user enable --now qa-pro-bridge`:

  ```ini
  [Unit]
  Description=QA pro bridge
  [Service]
  ExecStart=/usr/bin/node %h/tools/qa-pro-bridge/server/core.js --keep
  Restart=on-failure
  [Install]
  WantedBy=default.target
  ```

Порт по умолчанию — `47321`. Если он занят: `QA_PRO_BRIDGE_PORT=47400 node server/core.js --keep` и тот же порт в параметрах загрузчика («Порт моста»).

Папку можно разрешить заранее, без окна в браузере: `node server/core.js --allow "C:\work\qa-context"`. Список разрешённых: `node server/core.js --roots`.

## 4. Установка: QA pro в приложении Claude

В приложении Claude для компьютера расширений браузера нет — страница работает с мостом напрямую.

1. Установите мост **1.5**: QA pro → шестерёнка → ТМС → **«Скачать мост»** → откройте `qa-pro-bridge.mcpb`, приложение предложит установить (или: настройки приложения → «Расширения» → установить из файла). Фоновое ядро старой версии мост перезапустит сам.
2. В настройках расширения **«QA pro — мост…»** укажите **«Папка контекста QA pro»** — папку или git-клон с контекстом. Клоны, которые мост делает сам (источник «Git-репозиторий»), разрешены без настройки.
3. **Странице QA pro нужно разрешить новые инструменты моста** `context_read`, `context_write`, `context_git`. Новые инструменты в разрешениях страницы можно добавить только публикацией из локальной сессии (Claude Code на вашем компьютере), из облака публикация с ними отклоняется. Пока это не сделано, QA pro в приложении пишет: «Этой странице QA pro не разрешены инструменты моста context_*…» — работайте с источником через браузер (раздел 3), там это ограничение не действует.

При первом обращении приложение Claude спросит разрешение на вызов моста — как при загрузке в Сферу.

## 5. Подключение в QA pro

1. Выберите продукт.
2. Шестерёнка → **«Контекст»** → **«Подключить репозиторий или папку»**.
3. Выберите источник и заполните поля:

   | Источник | Поля |
   |---|---|
   | Папка на компьютере | полный путь: `C:\work\qa-context` или `/Users/me/qa-context` |
   | Git-репозиторий | адрес `https://git.company.ru/qa/context.git` или `git@git.company.ru:qa/context.git`; ветка — необязательно |
   | GitHub без моста | `владелец/репозиторий`, например `team/qa-context`; ветка — необязательно |
   | Папка только для чтения | кнопка **«Выбрать папку»** |

   Для всех, кроме базы QA pro: **«Подпапка контекста»** (если контекст лежит не в корне репозитория) и **«Папка продукта»** (`products/<папка>`).
4. **«Подключить»**. В браузере загрузчик откроет окно **«Доступ к контексту»** — проверьте папку (репозиторий) и адрес страницы и нажмите **«Разрешить»**. Окно появляется один раз для каждой пары «страница — папка».
5. Вкладка покажет, что найдено: правила, шаблоны (сколько из трёх), память агента, паспорт, доп. контекст, разделы базы знаний.

**Репозиторий пустой?** Нажмите **«Выгрузить контекст QA pro в источник»**: QA pro запишет туда текущие правила и шаблоны команды, память агента, паспорт и доп. контекст продукта, разделы его базы знаний и `CLAUDE.md`. Если файлы уже есть, QA pro покажет, какие будут перезаписаны, и попросит подтвердить.

## 6. Как работать дальше

**Генерация** не меняется. В каждый запрос к модели идут правила, шаблон, память агента и доп. контекст из источника, а также пункты паспорта и разделы базы знаний по теме запроса. Инструменты агента `search_knowledge_base` и `read_knowledge_section` ищут и по разделам из репозитория.

**Правки в QA pro** записываются в файлы источника:

| Что меняете в QA pro | Куда пишется |
|---|---|
| Правила для агента (левая колонка), шестерёнка → Шаблоны, Формат экспорта, Правила ревью — кнопка **«Сохранить в источник»** | `rules/…`, `templates/…` |
| Замечания агенту (память), удаление правила памяти | `products/<папка>/lessons.md` |
| Поле «Доп. контекст» | `products/<папка>/context.md` |
| Обновление знаний о продукте (этап «Знания о продукте», правка паспорта) | `products/<папка>/passport.md` и, как раньше, хранилище QA pro |

Для папки и git-репозитория запись идёт сразу. Для «GitHub без моста» правки копятся (точка на вкладке «Контекст») до кнопки **«Отправить в GitHub»** и переживают перезагрузку страницы.

**Если файл изменили в источнике** после того, как QA pro его прочитал (коллега, вы в редакторе), QA pro его не перезаписывает. Во вкладке «Контекст» появится список: **«оставить мою»** или **«взять из источника»**.

**Обновить.** Для git — **«Обновить (git pull)»**: только fast-forward, затем QA pro перечитывает файлы. Для папки без git — **«Обновить из источника»**.

**Отправить на удалённый.**

- Git (папка-клон или «Git-репозиторий») — **«Зафиксировать и отправить»**: если вы на `main`, `master` или основной ветке, QA pro создаёт ветку `qa-pro/<дата-время>`, делает коммит и `push`. Ссылка **«открыть запрос на слияние»** — для GitHub и GitLab. Следующие правки идут в ту же ветку. Прямо в `main` и `master` QA pro не отправляет.
- GitHub без моста — **«Отправить в GitHub»**: коммит в новую ветку `qa-pro/<дата-время>`. Дальше QA pro работает в этой ветке, пока запрос на слияние не принят. После слияния — **«вернуться на основную ветку»**.

**Без связи с источником** (мост выключен, ноутбук без загрузчика) QA pro работает с копией файлов, прочитанных в последний раз, и пишет об этом во вкладке «Контекст».

**Отключить** — источник снова «База QA pro». Правила, шаблоны, память и паспорт возвращаются к командным, файлы в источнике не трогаются.

## 7. Переключение между удалённым и локальным

Один и тот же репозиторий можно подключать двумя способами, переключаясь кнопкой **«Изменить»**:

- **«Git-репозиторий»** (удалённый) — мост сам держит клон в `~/.qa-pro-bridge/repos/<имя>`: вы указываете только адрес, обновление и отправка — кнопками в QA pro.
- **«Папка на компьютере»** (локальный) — ваш собственный клон, в котором вы работаете и в редакторе, и в Claude Code. Кнопки pull и «Зафиксировать и отправить» работают и здесь, если в папке есть git с `origin`. Папка без git — просто файлы, история не ведётся.

Перед переключением отправьте или зафиксируйте изменения: несохранённые правки GitHub без моста при отключении пропадают (QA pro предупредит). Переключение ничего не копирует автоматически. Чтобы перенести контекст в новый источник, после подключения нажмите **«Выгрузить контекст QA pro в источник»**.

## 8. Безопасность

- Мост читает и пишет только **текстовые файлы** (`.md`, `.txt`, `.json`, `.yaml`) и только **внутри разрешённых папок**: папка из настроек моста в приложении Claude, папки, разрешённые в окне загрузчика или командой `--allow`, и клоны, которые мост сделал сам. Пути с `..`, абсолютные пути, `.git` и ссылки за пределы папки отклоняются.
- В браузере каждая страница получает доступ к папке или репозиторию **только после «Разрешить»** в окне загрузчика. Разрешения видны и отзываются в параметрах загрузчика (раздел «Контекст QA pro» → «Отозвать»).
- Ядро моста слушает только `127.0.0.1` и принимает WebSocket только от расширения браузера.
- git запускается без оболочки и без запроса пароля в терминале. Адреса — только `https://` и ssh. Вход — ваш обычный для git: ключ SSH или сохранённый пароль, QA pro их не видит.
- Токен GitHub хранится в загрузчике, страница QA pro его не получает. Достаточно fine-grained токена на один репозиторий.
- QA pro не отправляет изменения прямо в `main` и `master` — только веткой.
- Правила компании: ТЗ и база знаний уходят в модель от вашей учётки Claude. Уточните, можно ли так с вашими данными.

## 9. Если не работает

| Сообщение в QA pro | Что сделать |
|---|---|
| «Загрузчик QA pro версии 1.8 не видит эту страницу» | Установите или обновите загрузчик (3.1), обновите страницу Ctrl+F5. В `chrome://extensions` → загрузчик → «Доступ к сайтам» не должно быть «По нажатию». |
| «Мост qa-pro-bridge не запущен на этом компьютере» | Запустите ядро (3.2) или приложение Claude с мостом. Проверьте `http://127.0.0.1:47321/health` и порт в параметрах загрузчика. |
| «Папка не разрешена для QA pro» | В браузере — разрешите в окне загрузчика (если окно закрыли, нажмите «Подключить» ещё раз). В приложении Claude — укажите папку в настройках моста или `node server/core.js --allow "<папка>"`. |
| «Доступ к папке не разрешён в окне загрузчика» | Вы нажали «Отклонить» или закрыли окно — подключите снова. |
| «Этой странице QA pro не разрешены инструменты моста context_*» | Приложение Claude: страницу нужно опубликовать заново из локальной сессии (раздел 4, шаг 3). Пока — работайте в браузере. |
| «git не установлен или не найден в PATH» | Установите git и перезапустите ядро моста. |
| «git clone: … Authentication failed» / «Permission denied (publickey)» | Проверьте, что `git clone <адрес>` работает в терминале этого компьютера без ввода пароля (ключ SSH или менеджер учётных данных). |
| «git не уложился в 25 с» | Большой репозиторий: склонируйте его сами и подключите как «Папка на компьютере». |
| «git pull: … Not possible to fast-forward» | В клоне есть свои коммиты, которых нет на удалённом: отправьте их («Зафиксировать и отправить») или разберитесь в терминале. |
| «GitHub не принял токен» / «Репозиторий или ветка не найдены» | Проверьте токен и его доступ к репозиторию (Contents: Read and write). |
| «Файлы изменились в источнике после чтения» | Выберите «оставить мою» или «взять из источника» для каждого файла. |
| «Источник недоступен — работаю с копией от …» | Связи нет, QA pro использует последнюю прочитанную копию. Восстановите связь и нажмите «Обновить». |

## 10. Ограничения

- Разделы базы знаний из репозитория используются в генерации, ревью и поиске агента и перечислены во вкладке «Контекст», но **не показываются на вкладке «База знаний»**. Разделы, которые агент собирает из загруженных документов, по-прежнему хранятся в QA pro: в репозиторий они попадают при «Выгрузить контекст QA pro в источник».
- Готовые кейсы продукта (для поиска дублей) остаются в QA pro, в репозиторий не выгружаются.
- «Git-репозиторий» клонируется с историей на 50 коммитов (`--depth 50`). Каждая операция git ограничена 25 секундами.
- Настройка источника личная. Чтобы вся команда работала с одним репозиторием, каждый подключает его у себя.
- В приложении Claude нужна повторная публикация страницы из локальной сессии (раздел 4).
